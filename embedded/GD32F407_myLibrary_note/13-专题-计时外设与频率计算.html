13 · 专题：所有「靠计数取时间」的外设与频率计算 ​

这是一篇跨模块专题，不绑定某几次提交 —— 它把本工程里所有跟「计数 / 定时 / 分频」有关的代码摊在一张表上，统一成同一套算法。 涉及模块：SysTick（01）、PWM 与蜂鸣器（07）、RTC（11）、看门狗（12）、串口波特率（04）、DMA 等待（08）、EXTI 消抖（06）、数码管扫描与状态机调度（05/09）。 上游专题：14 时钟树与总线 —— 本篇的第三章「时钟底账」在 14 篇里会展开成完整的时钟树讲解。建议先 14 后 13：14 讲「时钟是多少」，本篇讲「拿这个时钟怎么数出时间」。 整理日期：2026-09-26　｜　所有数字均代入公式验算过，并在文中给出推导过程。

学习目标 ​

  • 能把任意一个「计时类」外设，拆成源时钟 / 分频 / 计数值三个量
  • 会用一套公式算遍：定时器、PWM、蜂鸣器、RTC、两个看门狗、串口波特率
  • 说清本工程里「哪条总线、多快、为什么倍频后统一成 168 MHz」
  • 会从需求反推参数（要 1 ms 周期 → PSC 和 ARR 各取多少）
  • 知道哪些「时间」是硬件算的、哪些是软件凑的（以及软件凑的会有什么代价）
  • 建立精度意识：RC 振荡器、晶振、取整误差、总线差异分别带来多大偏差

记住三句话，剩下的都是套公式：

  1. 每个计时外设都有「一个源时钟」 —— 先查它挂在哪条总线上。
  2. 分频永远是「除以 (值+1)」 —— 写进去的寄存器值要 减 1（这是最容易错的点）。
  3. 数满多少个计数就是多长时间 —— 时间 = 计数个数 ÷ 计数频率。

二、通用公式卡（背这 6 条） ​

设：

  • f_src = 源时钟频率（Hz）
  • PSC = 预分频寄存器值（实际分频 = PSC + 1）
  • ARR = 周期/重装载寄存器值（实际计数个数 = ARR + 1）
  • CCR = 比较值（占空比用）
#公式用途
①f_cnt = f_src / (PSC + 1)计数频率（每个计数走多快）
②t_cnt = 1 / f_cnt = (PSC + 1) / f_src一个计数代表多长时间
③T_out = (ARR + 1) × t_cnt = (PSC + 1)(ARR + 1) / f_src溢出周期（定时中断 / PWM 周期）
④f_out = 1 / T_out = f_src / ((PSC + 1)(ARR + 1))输出频率
⑤占空比 = CCR / (ARR + 1) → CCR = (ARR + 1) × 占空比PWM 占空比
⑥引脚翻转（toggle）时：f_out = f_cnt / 2方波发生（蜂鸣器）

两个「隐形」的加法（本篇反复强调）：

位置规律
分频寄存器写 N-1 才等于除以 N。写 PSC = 168-1 表示分频 168 倍
计数寄存器数 N 个计数要写 ARR = N-1。写 ARR = 100-1 表示数 100 个

3.3 定时器为什么要「倍频」——以及它到底是怎么统一的 ​

c
// 时钟倍频(全局配置 所有定时器都是168Mhz)
rcu_timer_clock_prescaler_config(RCU_TIMER_PSC_MUL4);
1
2

这一行的目的一句话：让「定时器时钟」和「系统主频」相等，这样算参数时只需要记住一个数 168 MHz。

但它的实现规则比想象中讲究（直接看库里的注释，gd32f4xx_rcu.h 第 962~969 行）：

RCU_TIMER_PSC_MUL4：如果 APB1PSC/APB2PSC ∈ {0b0xx(÷1), 0b100(÷2), 0b101(÷4)}，则 CK_TIMERx = CK_AHB； 否则 CK_TIMERx = 4 × CK_APBx。

套到本工程：

APB1PSC = ÷4 (0b101) ✔ 在允许集合里
APB2PSC = ÷2 (0b100) ✔ 在允许集合里
        ↓
CK_TIMERx = CK_AHB = 168 MHz   ← 所有定时器（APB1 上的和 APB2 上的）都是 168 MHz
1
2
3
4

这就是「所有定时器都是 168 MHz」的准确依据，也解释了教材那张表里的「倍频」列为什么 APB1 写 ×4、APB2 写 ×2 —— 两条总线的分频比不同，但最终结果都是 168 MHz。

⚠️ 边界提醒（值得记住的反例）：如果哪天把 APB1 分成 ÷8，那么它就不在允许集合里，CK_TIMERx = 4 × 42/2 = ... 会变成另一个值，所有定时器参数都得重算。改时钟树 = 所有基于时间的参数全部重算，这是条铁律。

5.4 软 PWM 与软方波：中断周期 ≠ 输出周期 ​

这是最容易算错的一类，因为输出是「在中断里手动翻转/拉高拉低」出来的。

① 软 PWM（a2eeece）：高电平占 1/5

#define PERIOD 20 - 1          // → 中断周期 = 20 × 10 μs = 200 μs

cnt = (cnt + 1) % 5;           // 5 个中断一轮
if (cnt == 0) 高电平; else 低电平;

PWM 周期 = 5 × 200 μs = 1000 μs ？ —— ❌ 错！
实际：中断每 200 μs 来一次，每次根据 cnt 决定高低
     5 次中断 = 5 × 200 μs = 1 ms 一轮
     其中 1 次高、4 次低
     ⇒ 「PWM 周期」= 1 ms，「高电平时间」= 200 μs，「占空比」= 20% ✅

5.5 蜂鸣器：把频率变成「参数」算 ​

bsp_buzzer 用的是反推：给定要发出的频率 hz，算 ARR。

c
#define PRESCALER (168 - 1)        // → f_cnt = 168e6/168 = 1 MHz，t_cnt = 1 μs

5.9 串口波特率：16 倍过采样，本质也是分频 ​

UART 是异步通信，收发双方靠「约定的位时间」对齐，所以波特率本质上就是「用总线时钟分出一个位时钟」。

波特率 = f_PCLK / (16 × USARTDIV)          ← 16 倍过采样（默认）
波特率 = f_PCLK / (8  × USARTDIV)          ← 8 倍过采样（USART_CTL0_OVSMOD 置位）
1
2

库函数的做法（gd32f4xx_usart.c）：

c

uclk = rcu_clock_freq_get(CK_APB1);   // USART2 → 42 MHz
udiv = (uclk + baudval / 2U) / baudval;        // 四舍五入
intdiv = udiv & 0xfff0U;                       // 整数部分（12 位）
fradiv = (udiv >> 1U) & 0x7U;                  // 小数部分（3 位，步进 1/8）
USART_BAUD = intdiv | fradiv;

六、反推参数：通用四步法 ​

七、精度与误差：硬件算得准，但源不一定准 ​

公式算得再准，源时钟不准也白搭。 这是「频率计算」里最容易被忽视的一环。

7.1 三类时钟源的精度对比 ​

时钟源类型典型精度影响
HXTAL（8 MHz 晶振）石英晶振±10~50 ppm（0.001~0.005%）很好；本工程 RTC 与系统时钟都用它
LXTAL（32.768 kHz 晶振）石英晶振±20 ppm 级RTC 的最佳选择（但需焊晶振 + 匹配电容）

估个数量级：假设 IRC32K 实际是 32 100 Hz 而代码按 32 000 算：

频率误差 = (32100 - 32000)/32000 = 0.3125%

来源量级怎么减小

7.3 软件时间 vs 硬件时间 ​

这是本篇最值得带走的观念：

硬件时间软件时间
谁在数定时器/看门狗/RTC 的计数器主循环里的代码
精度硬件级，不受代码影响取决于循环耗时是否稳定
例子PWM 周期、RTC 秒、FWDGT 超时消抖 30 ms、状态机 500 ms、呼吸灯 10 ms
风险几乎没有一旦循环里加了耗时操作就漂移

本工程里「软件时间」被硬件逼着改进的两次：

  1. 第 09 篇：数码管扫描需要 1 ms 刷新，如果主循环里有 delay_1ms(10)，一帧就变 80 ms → 闪烁。于是呼吸灯从 delay_1ms(10) 改成 get_us_cnt() 时间戳。
  2. 第 12 篇：WWDGT 的窗口只有 1.66 ms，喂狗周期必须精确在 4.58~6.24 ms 之间。任何「偶尔耗时长」的操作都会导致复位 —— 硬件直接强制了非阻塞。

7.4 第三类时间：物理时间（不靠计数器，但照样要算） ​

前面两类都是"数出来的时间"，还有一类跟时钟、分频、计数全都无关——器件内部物理过程需要的时间。 新增的 SPI Flash（第 24 篇）就是最典型的例子：

操作手册标称（typ）换成"多少个 SPI 时钟"（21 MHz）谁在等
读 14 字节（ID 事务）无额外时间$14 \times 8 = 112$ 个时钟 ≈ 5.3 μs总线
编程 256 B 页0.7 ms命令本身 264 B ≈ 100 μs芯片内部高压电路
擦除 4 KB 扇区45 ms命令只要 4 B ≈ 1.5 μs芯片内部高压电路
芯片全擦约 10 s 量级同上同上

三个结论：

  1. 提高 SPI 时钟对擦写速度毫无帮助：命令 1.5 μs 就发完了，剩下 44.9985 ms 全在等芯片。 想快只有一条路——减少擦除次数（攒满一个扇区再写）。
  2. 它比任何"计数器时间"都长两个数量级：45 ms vs WWDGT 窗口 1.66 ms —— 所以"打开窗口看门狗"和"用 Flash 存数据"在当前代码结构下是互斥的（必然复位）。
  3. bsp_flash_wait_busy() 那个 while 轮询，就是本工程最长的一次"忙等"： 它把 45 ms 硬生生变回了"软件时间"（阻塞主循环）， 处理它的正确方式正是第 05 篇的状态机（发指令 → 返回 → 主循环里查状态 → 完成）。

这张表里藏着的三条约束关系（值得自己推一遍）：

约束说明
喂狗周期必须夹在 4.58 ms 和 6.24 ms 之间所以 5 ms 是唯一舒服的选择，而 printf（8.7 ms）会直接破坏它
数码管刷新（1 ms）必须远小于 41.7 ms（人眼视觉暂留）所以一帧 8 ms 是安全的，125 Hz 远超临界
按键扫描（20 ms）要远小于抖动时间窗口（~30 ms）的相对量所以 20 ms 扫描天然过滤了大部分抖动
188 一帧（5 ms）与数码管一帧（8 ms）都必须远小于 41.7 ms 视觉暂留所以两者都不闪；而 188 的 20% 占空比意味着要靠峰值电流换亮度
Flash 擦除（45 ms）必须避开看门狗窗口（1.66 ms）与超时（100 ms）所以"开看门狗"与"写 Flash"在当前代码结构下互斥（第 24 篇 §7.2）
★ 同一个"1 μs"在裸机和 RTOS 下是两种实现裸机靠 SysTick 1 MHz 中断递减；RTOS 靠 TIMER6 自由运行计数器轮询差值。而 get_us_cnt() 的精度从 µs 退化到 1 ms（tick hook 每 tick 加 1000）—— 第 34 篇 §4
★ 触摸按键的"去抖时间"根本不在 MCU 里RTM3 = 6 个采样周期由 SC12B 芯片内部完成 → 本工程唯一一个"消抖不需要 MCU 定时器"的按键方案（第 31 篇）。对照：独立按键靠 SysTick 时间戳、AD 按键靠 30 ms 时间门、矩阵键盘压根没做

十一、自测题 ​

  1. 用一句话概括所有计时外设的共同套路（源时钟 / 分频 / 计数分别是什么角色）？
  2. 写出 f_cnt、t_cnt、T_out、f_out、占空比 五个公式。哪些地方必须「减 1」或「加 1」？
  3. 本工程的 APB1 和 APB2 分别是多少？TIMER0、TIMER3、USART0、USART2、WWDGT 分别挂在哪条总线上？

  6. PWM 周期 1 ms、占空比 50%，PSC=1680-1 时 ARR 和 CCR 各是多少？推导过程写出来。
  7. 软 PWM 里「中断周期」和「PWM 周期」是同一个东西吗？ARR=20-1、cnt %= 5 时，PWM 周期是多少？
  8. 蜂鸣器用中断里 toggle 的方式发声，为什么输出频率是中断频率的一半？
  9. bsp_buzzer_play(1000) 时 ARR 是多少？为什么 PSC 取 168-1 而不是 1680-1？
  10. RTC 的两级预分频分别叫什么？为什么异步预分频固定取 0x7F？三种时钟源的 FACTOR_S 各是多少？
  11. FWDGT 的 PSC 取 DIV32、RLD 取 100，超时是多少？最大能给到多长？
  12. WWDGT 为什么有个固定的 /4096？它用的是哪条总线的时钟（不是 168 MHz！）？
  13. wwdgt_config(0x7F, 0x50, DIV1) 的最短/最长喂狗时间是多少？为什么本工程取 5 ms？
  14. USART0 和 USART2 都配 115200，为什么 USARTDIV 一个是 45.5、一个是 22.75？实际波特率误差多少？
  15. 115200 下 printf 输出 100 字节要多久？这个数字和「看门狗窗口 1.66 ms」放在一起说明了什么？
  16. 哪些时间是本工程里「软件凑的」而不是「硬件数的」？软件时间有什么风险？

十二、练习题 ​

  1. 反推练习：让 TIMER3 在 PD12 输出 20 kHz、占空比 30% 的 PWM，写出 PSC、ARR、CCR 三个值并验算。
  2. 反推练习：让 TIMER5 每 250 ms 触发一次中断，写出 PSC、ARR。
  3. 反推练习：FWDGT 想要 500 ms 超时，PSC 和 RLD 怎么取？（提示：有没有多种组合？）
  4. 反推练习：WWDGT 想要喂狗窗口大致落在 10~14 ms，counter、window、PSC 怎么取？
  5. 对照实验：用示波器/逻辑分析仪量 a2eeece 的软 PWM（TIMER5 中断翻转 PA2）和 1f76f67 的硬 PWM（TIMER1_CH2），对比两者的周期和抖动，验证「软 PWM 周期 = 模数 × 中断周期」。
  6. 误差实验：把 bsp_buzzer_play() 的 PRESCALER 改成 1680-1（100 kHz tick），再播放 20 Hz 和 20 kHz，观察哪个频率先失真，解释原因。
  7. 时钟树实验：把 APB1 分频从 ÷4 改成 ÷8，重新确认 TIMERSEL 下 TIMER 的时钟变成多少，然后重算所有定时器参数（这就是「改时钟树要全体重算」的实操）。
  8. 写一个小工具：用 C 或 Python 写一个「输入 f_src + 目标周期 + 计数器位数 → 输出候选的 PSC/ARR 组合」的函数，要求 PSC 尽量小（tick 尽量细）、ARR 不溢出。
