学习目标 ​

一、EC12D 是什么 ​

EC12D（常写作 EC11 / EC12）是一种"增量式旋转编码器"：旋钮每转过一格，内部两个触点按固定顺序通断一次。 它长得像"可无限旋转的电位器"，但输出不是模拟量，而是两路方波（A 相 / B 相）。

电位器（PC4，第 19 篇）旋转编码器（本篇）
输出一个模拟电压（ADC）两路数字方波（A / B）
能否无限旋转❌（有机械止点）✅
是否需要 ADC需要不需要（普通 GPIO + EXTI）
能测"转了多少"能（绝对值）能（相对增量，掉电不记得位置）
附加功能—通常带一个按键（按下 = 第三根线）

本工程用的是"带按键"的型号，所以一共 3 根信号线（+ 电源地）：

信号本工程引脚作用中断
APD11方波 A（判断"有没有转"）EXTI11，双边沿
BPD13方波 B（判断"往哪转"）无（只做输入读取）
D（按键）PD15按下（低有效）EXTI15，下降沿

二、★ 正交编码：两个方波怎么判方向 ​

2.1 波形长什么样 ​

A、B 两路方波频率相同、相位差 90°（四分之一周期），这就是"正交"：

正转（顺时针）：
A  ──┐  ┌────┐  ┌────┐  ┌──
      └──┘    └──┘    └──┘
B  ────┐  ┌────┐  ┌────┐  ┌─        ← B 比 A 滞后 90°
       └──┘    └──┘    └──┘

反转（逆时针）：
A  ──┐  ┌────┐  ┌────┐  ┌──
      └──┘    └──┘    └──┘
B  ┐  ┌────┐  ┌────┐  ┌────         ← B 比 A 超前 90°
   └──┘    └──┘    └──┘

关键观察：在 A 的每一个跳变沿上，B 的电平是不同的——

  • 正转时，A 的下降沿上 B 是高；
  • 反转时，A 的下降沿上 B 是低。

于是判方向只需要："A 一动，就立刻看 B 是什么电平"。

2.2 代码里的方向表 ​

c

把它整理成表（这张表要能自己推出来）：

A 的边沿B 的电平结论

注意"上升沿和下降沿的判断正好相反" —— 这不是写错了，正是正交信号的必然结果： A、B 差 90°，所以 A 上升时的 B 电平必然与 A 下降时相反。 如果你只在一个边沿上判断（比如只在下降沿），也能定方向，只是分辨率减半； 本工程两个边沿都判，方向更可靠（但也带来"一格报两次"的副作用，见第六章）。

2.3 为什么"只在 A 上开中断"就够了 ​

方案中断线说明
本工程只 A 双边沿A 一来就读 B（B 只做普通输入）——最省中断，逻辑最简单
常见的"4 倍频"A、B 都双边沿分辨率 ×4，但每格报 4 次，要自己做倍频计数
硬件方案定时器的编码器接口模式硬件自动加减计数，零中断、零错误（第 21 篇 §"隐藏能力"里列过，本工程未用）

结论："只 A 开中断 + 读 B"是最省事、最适合教学的写法； 要"精确测速/大转数"就该上定时器的编码器接口（第 21 篇的"未用能力"之一）。

为什么只配 B？ 因为 A（PD11）和 D（PD15）在 msp_exti_init() 里已经配好了（输入 + 上拉）—— 这个"分工"本身是合理的（谁开中断谁配引脚）。

另一个细节：B 配的是 GPIO_PUPD_NONE（浮空），而 A/D 配的是 GPIO_PUPD_PULLUP。 如果编码器的 B 相是开集/开漏输出（部分型号是），浮空输入就可能读到随机电平； 建议统一成 PULLUP（编码器内部触点是"通到 GND"，上拉才是正确的静态电平）。

4.2 中断处理：时间门 + 边沿判 + 方向表 ​

void on_ec12d_exti()
{
    // ① 旋钮消抖

五、⚠️ 三个问题 ​

5.1 引脚冲突：PD11 / PD13 / PD15 = LED4 / LED6 / LED8 ​

查 Doc/硬件信息汇总.md（PCB 网表为准）：

代码里MCU 引脚板上网络板上连到哪里冲突
APD11LED4R18 → LED4 阴极（低有效）★ 与 bsp_leds 冲突
BPD13LED6R20 → LED6 阴极★ 同上
DPD15LED8R22 → LED8 阴极★ 同上

也就是说：这个旋转编码器是"外接模块"，插在排针上，而它占用的三个脚在本板上已经接了 LED4/LED6/LED8。

三个后果（按严重程度）：

  1. 软件层冲突（最严重）：bsp_leds_config() 会把 PD8~PD15 全部配成推挽输出， 而编码器需要 PD11/PD13/PD15 做输入 + EXTI（见 §5.2）。
  2. 按下按键会"点亮/熄灭 LED8"：按键把 PD15 短到 GND；而 LED8 支路就在同一个网络上 （PD15 —R22→ LED8 —→ +5V 侧的公共阳极，见第 02 篇）。 所以 PD15 输出高时 LED8 会亮、按下按键时 LED8 灭——用编码器按键会"顺带控制一颗 LED"。
  3. LED 与旋钮互相干扰：转动/按下旋钮会改变 PD11/PD15 的电平 → 触发 LED 相关的逻辑； 反之驱动 LED 会产生 EXTI 中断（见 §5.2）。

正确做法：把编码器的 A/B/D 换到板上真正空闲的引脚（如 PB14、PE7，或第 23 篇 §5.4 那种"硬件已具备但代码未实现"的脚）， 或者明确接受"LED4/6/8 与旋钮不能同时用"（在本工程里，LED 是教学用的，可以先让路）。 不管选哪种，都要在笔记和代码注释里写清楚——这正是第 20 篇"代码↔硬件核对"的意义。

5.2 ★ 初始化顺序把引脚模式覆盖了（最隐蔽） ​

看 main.c 的调用顺序（这个顺序是关键）：

...

...
bsp_ec12d_init();       // ③ 只把 PD13 配回"输入"

净结果：

引脚① 之后② 之后③ 之后（最终）期望
PD11（A）输入+上拉输出推挽输出推挽 ❌输入
PD13（B）未配（浮空）输出推挽输入 ✅输入
PD15（D）输入+上拉输出推挽输出推挽 ❌输入

于是：

  1. gpio_input_bit_get(PD11) 读到的是"输出数据寄存器驱动出来的电平"， 而不是编码器 A 相的电平 → 方向判断完全失效（读到的是上次 LED 操作留下的值）。
  2. EXTI11 / EXTI15 仍然使能着，而且触发条件挂在一条被推挽驱动的线上 → 每次 bsp_leds_open()/close() 翻转 PD11/PD15，都会触发一次 EXTI 中断 → 可能凭空报出 clockwise / key press。
  3. 更糟的是 PD15 输出高 + 外部按键按下 → 推挽输出对地短路（靠内部限流，不致命但会发热、压降）。

通用规律：

两个模块共用引脚时，"谁后初始化谁说了算"。 而且这种 bug 在编译期、链接期都不会报错，只在运行时表现为"莫名其妙的逻辑"。 检查方法只有一个：把所有会碰这个引脚的初始化列出来，按 main 里的顺序排一遍，看最终模式是什么。

放在 .c 里但不加 static → 它们在全局符号表里可见， 任何文件只要写个同名 extern 就能改它们，链接时还可能和别人的同名符号撞车。 "只在本文件用的东西就加 static" 是 C 里最便宜的封装。

5.4 中断里直接 printf（违反刚立的规矩） ​

调用链：EXTI10_15_IRQHandler() → on_ec12d_exti() → on_ec12d_clockwise()（默认实现）→ printf。

printf 走的是 msp_uart 的阻塞式发送（第 04 篇），一个字节约 86.8 μs， "counter clockwise\n" 共 18 字节 ≈ 1.6 ms —— 在一颗按键/旋钮动一下的中断里阻塞 1.6 ms，会：

  1. 拖住其它中断（SysTick 的 1 ms 分支里还有 188 数码管 / ADKEY / 数码管扫描）；
  2. 可能撞上看门狗窗口（WWDGT 窗口 1.66 ms，第 12 篇）——1.6 ms 正好顶在窗口上沿；
  3. 在中断里做 IIC 的老问题（如果打印过程中别的代码也访问串口）。

这是第 17 篇 §5.5 那三条规矩的直接违例（"中断里绝不发起软件 IIC/不 printf"）。 同一个工程、相隔 3 天，一次修好了、一次又犯——说明"规矩"光写进笔记不够，还要写进代码评审清单。

六、30 ms 消抖的双重作用 ​

6.1 第一重：常规机械消抖 ​

旋钮内部的金属弹片在转动时会产生数毫秒的抖动，和普通按键一样需要过滤。30 ms 绰绰有余。

6.2 第二重（更关键）：把"一格的两次边沿"合并成"一次" ​

本工程 EXTI11 是 EXTI_TRIG_BOTH（双边沿），而一个"格"（一个完整正交周期）在 A 上会产生 2 个边沿 （一个上升、一个下降）：

一格（一个 detent）= A 的一个完整脉冲：

A  ─┐   ┌───────────┐   ┌──
    └───┘           └───┘
     ↑下降沿        ↑上升沿          ← 同一格里两次中断！

※ 两次中断算出的方向是相同的（因为正交关系，A 上升时的 B 电平与 A 下降时相反，
  而方向表对两个边沿的映射也相反 → 结论一致）

如果不做处理：转一格会回调两次 clockwise()（"转一格跳两格"）。

30 ms 时间门正好解决它：转动一格时两个边沿相隔 = 半个 A 周期。 人手慢转时 A 周期约 10~30 ms（转速 ~30~100 格/秒 以下），半周期 5~15 ms 远小于 30 ms → 第二次边沿被时间门挡掉 → 一格一次回调 ✅。

这解释了"为什么是 30 ms 而不是 5 ms"：5 ms 挡不住慢转时的第二个边沿（会双击计数）， 30 ms 既能挡边沿、又能挡抖动。这个参数同时满足两个约束，是个挺聪明的做法。

6.3 代价：转速上限 ​

约束数
时间门30 ms
最快回调频率$1/30\ \text{ms} \approx 33\ \text{次/秒}$
即最快识别约 33 格/秒

人手快转旋钮可以轻松超过 100 格/秒 → 超过的部分会被直接丢弃（表现为"转快了不跟手/漏格"）。

要解决的话（从易到难）：

方案做法代价
① 只用一个边沿（推荐）把 EXTI_TRIG_BOTH 改成只下降沿，一格只产生 1 次中断改一行，且 30 ms 可以降到 5 ms（只做消抖）
② 缩短时间门 + 软件方向累加消抖降到 2~3 ms，用"边沿计数"自己除 2要处理"两个边沿间隔"的不确定性
③ 定时器编码器接口模式硬件自动加减计数，零中断最优解（第 21 篇列的"未用能力"之一）

"只取下降沿"是最划算的改法：EXTI11_TRIG_TYPE 从 EXTI_TRIG_BOTH 改成 EXTI_TRIG_FALLING， 再把 on_ec12d_exti() 里"上升沿那段"删掉，消抖时间也能从 30 ms 收到 5 ms。

练习题 ​

  1. 修引脚模式：把 bsp_ec12d_init() 改成"同时把 PD11/PD13/PD15 配成输入+上拉"，放到 bsp_leds_config() 之后，验证旋钮与 LED 是否都能正常工作。
  2. 改单边沿：把 EXTI11 改成只下降沿，删掉 on_ec12d_exti() 里的上升沿分支，把时间门收到 5 ms，实测快转是否跟手。
  3. 改成只置标志：把三个回调改成"改全局计数/标志"，主循环里统一 printf，对比串口输出是否更稳定（这就是第 17 篇 §5.5 的修复套路）。
  4. 加按键消抖：给 on_ec12d_key_press() 那条 EXTI15 加上和第 06 篇 KEY4 一样的消抖（时间门 + 电平去重）。
  5. 做成"音量旋钮"：把正/反转回调接到第 07 篇的蜂鸣器 bsp_buzzer_play(freq)，做一个"旋钮调音调"的完整例子（含范围限制与步进）。
  6. 对比实验：查手册配一次定时器编码器接口模式（TIMER2 或 TIMER3），把旋钮计数交给硬件，比较与"中断+软件判方向"两种方案在快转时的丢格情况。
