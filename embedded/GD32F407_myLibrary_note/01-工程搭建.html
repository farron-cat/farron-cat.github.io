1.1 Driver 和 Hardware 的区别（最容易混） ​

这是本工程最核心的一条分界线，用一句话记住：

Driver 里的东西，是别人焊在板子上的；Hardware 里的东西，是长在芯片里的。

Hardware（msp_）Driver（bsp_）
面向对象芯片内部集成的外设板子上的元器件
例子USART0、EXTI、TIMER、DMALED、独立按键、蜂鸣器、数码管、矩阵键盘
引脚固定吗芯片定了，改不了（USART0 就是 PA9/PA10）板子改了就得跟着改（LED 换到别的脚很常见）
本工程文件msp_uart.c、msp_exti.cbsp_leds.c、bsp_keys.c、bsp_buzzer.c

为什么这个区分有价值？ 换一块板子（比如从梁山派换到另一家的 GD32 板），Hardware/ 一个字都不用改，只改 Driver/ 里那几张引脚参数表就够了。第 02、03 篇会看到，作者正是为了这件事，把 LED 和按键的引脚从代码里抽成了数组。

三、从复位到 main()：芯片偷偷干了什么 ​

写代码之前先知道自己的代码是怎么被调起来的，出问题才知道该往哪看。

① 上电 / 按下复位键
        ↓  硬件把 PC 指向 0x0000_0004（复位向量）
② 启动文件 startup_gd32f407_427.s
   ├─ 建立栈指针（__initial_sp）
   ├─ 把 .data 段从 Flash 搬到 RAM，把 .bss 段清零
   ├─ 给 C 库运行环境做准备
   └─ 调用 SystemInit()
        ↓
③ system_gd32f4xx.c 里的 SystemInit()
   ├─ 打开外部晶振（HXTAL，8 MHz）
   ├─ 配置 PLL，把 8 MHz 倍频到 168 MHz
   ├─ 切换系统时钟源到 PLL
   └─ 更新全局变量 SystemCoreClock = 168000000
        ↓
④ 进入 main()

六、systick.c：整个工程的时间基准 ​

这是第一个提交里最有技术含量的一段代码，后面所有 delay_1ms()、非阻塞定时、按键消抖都建立在它之上。

6.1 配置：为什么是 1 MHz ​

c
void systick_config(void)
{
    /* setup systick timer for 1000000Hz interrupts */
    if (SysTick_Config(SystemCoreClock / 1000000U))
    { // 1us
        while (1) { }
    }
    /* configure the systick handler priority */
    NVIC_SetPriority(SysTick_IRQn, 0x00U);
}

SysTick_Config(ticks) 的参数是每多少次内核时钟来一次中断：

SystemCoreClock / 1000000 = 168000000 / 1000000 = 168
1

即「每 168 个内核时钟中断一次」= 每 1 微秒中断一次。

配置中断频率适合做什么
/10001 kHz（1 ms 一次）只做毫秒延时，中断负担最小
/1000000（本工程）1 MHz（1 μs 一次）毫秒 + 微秒都要，且要能读「当前时刻」

代价要知道：1 MHz 中断意味着 CPU 每秒被打断 100 万次，每次进中断都是有开销的（压栈、出栈、函数调用）。本工程选它，是为了同时支持 delay_1us() 和「读时间戳」两件事——串口消抖、wait_us() 都靠它。

NVIC_SetPriority(SysTick_IRQn, 0x00U) 把 SysTick 设成最高优先级，因为它是时间基准，被别的中断拖慢会导致所有延时都不准。

6.2 延时：delay 变量与中断的配合 ​

c
volatile static uint32_t delay;      // 软件计数器
volatile static uint64_t us_cnt;     // 微秒时间戳（后续提交加进来的）

void delay_1ms(uint32_t count)
{
    delay = count * 1000;            // 1ms = 1000 个 1us
    while (0U != delay) { }          // 死等，直到被中断改到 0
}

void delay_1us(uint32_t count)
{
    delay = count;
    while (0U != delay) { }
}

void delay_decrement(void)           // 由 SysTick 中断调用
{
    us_cnt++;                        // 时间戳自增

    if (0U != delay)
    {
        delay--;                     // 每次中断减 1
    }
}

三个关键点：

点说明
为什么 delay 是 volatile它在中断里被改、在 while 里被读。没有 volatile，编译器会认为「循环里没人改它」，直接把循环优化掉或只读一次，delay_1ms 立刻返回
为什么是 while (0U != delay)无符号变量的惯用写法，明确表达「非零即继续」
缺点：这是阻塞式延时空转期间什么都干不了。第 05 篇的充电流水灯、第 09 篇的数码管扫描，都会改用「读时间戳 + 比较」来替代它

系统文件desktop.ini、.DS_Store操作系统生成的垃圾

一个值得养成的小习惯：.gitignore 应该「跟人走」——你在开发过程中发现某类文件总是出现在 git status 里、且不应该提交，就立刻补进 .gitignore。 这两次提交正是这个习惯的产物（同一个改动在两个分支各做了一遍，因为两个分支的 .gitignore 是各自演进的）。

为什么 dma_usart 分支上也做了一次？ 因为那个分支当时还在独立开发（第 08 篇提过它尚未合并）。分支自带的配置改动，会在合并时自然带进主线——如果两个分支都对同一个文件做了「相同语义」的修改，Git 通常能自动合并。

七之二、2026-10-10：main.c 的一次大瘦身（本篇主旨的"回访"） ​

第 01 篇一直强调的那条规律——「每个功能都先在 main.c 落脚，再抽成模块」——到了 10 月已经积累了 10 个模块。 于是 main.c 变成了 453 行：里面躺着 DMA 试验代码、旧版 ADC 实现、看门狗配置、两个没人用的全局变量， 还有大段被注释掉的试验代码。067922c（[整理] 整理main函数）把它砍到 264 行。

这次整理带来的三条"通用经验"（比删了什么更重要）：

  1. 整理前先写方案：同一次提交新增了 Doc/整理操作参考.md（672 行）， 把 main.c 逐行盘点成"行号/名称/类别/问题/目标归属/git 来源"六列表，并先列出两个高危隐患 ——① msp_adc_get 符号冲突（C 不支持重载，链接期报错）；② DMA1_CH0 资源争用。 重构之所以能安全进行，是因为先把"会炸的地方"找了出来。（详见第 20 篇 §14.1）
  2. 迁移顺序要"先建后拆"：这次是先拆（20:08）后建（20:19 / 20:30），中间态不可编译。 之所以没出事，是因为被删的恰好都是"死代码"（调用处早就注释掉了）——碰巧安全，不是设计安全（第 27 篇 §3.3）。
  3. "整理"的边界是"只搬不改行为"：连 bsp_ntc_init() 这种空函数都原样保留， 接口对称性优先于"顺手清理"（第 27 篇 §7）。

回头看第 01 篇开头那句话："目录结构不是装饰，它决定了东西往哪放"。 10 月的这次整理，就是这句话"欠账到期"的样子——当 main.c 里的东西多到需要一份 672 行的整理方案时， 你就知道"每个功能都先在 main.c 落脚"这条路的代价了。

  2. __weak 不只是"某种编译器扩展"：它是本工程**"驱动层给默认实现、应用层可覆盖"**这套机制的地基 （第 03 篇 bsp_keys 的回调、第 17 篇的 on_rtc_alarm、第 29 篇的三个旋钮回调全靠它）；
  3. 放在 User/ 而不是某个 Driver/ 下，语义也正确——它不属于任何器件， 而是"整个工程共用的语言层小工具"。

命名上的小遗留：util_ 前缀是本工程第一次出现（之前只有 bsp_ / msp_）。 将来若再攒出几个类似的小工具（ARRAY_LEN、MIN/MAX、_Static_assert 包装）， 可以一并放进 User/util_*.h，形成一个"工程公共工具"的小角落—— 这正是 模板结构.txt 里 Middleware/（当前为空）预留的位置。

每层的"换掉成本"完全不同（这正是分层的意义）：
