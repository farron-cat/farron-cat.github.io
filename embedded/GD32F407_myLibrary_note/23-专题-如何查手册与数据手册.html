23 · 专题：怎么查手册找图和表、怎么查数据手册找数据和公式 ​

这是一篇"方法"专题：不讲某个外设怎么用，而是讲遇到问题时该翻哪份资料、怎么快速定位到那一张表/那一张图/那一条公式。 素材全部来自本工程的真实查证过程——每一次"参数算对/踩坑修正"的背后，都是一次查资料。 整理日期：2026-10-06

怎么读这份笔记 ​

你的情况建议路线
手上有手册但不知道从哪翻第二章（资料地图）→ 第六章（四步查法）
想知道"这个参数到底该查哪本"第五章（本工程 14 个真实查证案例）
想知道"手册没写怎么办"第七章（三种"查不到"的应对）
只想抄个模板第八章（代码注释里怎么写出处）
找那张温度公式表第五章 案例 5（数据手册表 4-36）

学习目标 ​

  • 说清 6 类资料各自"解决什么问题"，拿到一个疑问能立刻判断该翻哪本
  • 掌握"从问题到那一张表"的四步定位法
  • 记住本工程 14 个真实查证案例（尤其温度公式和TIMERSEL 规则）

一、先破一个误解：不是"一本手册"就够了 ​

新手常以为"看手册"就是看一本书。实际上嵌入式开发至少要跟六类资料打交道，它们的权威性和用途完全不同：

#资料回答什么问题权威性本工程在哪
1数据手册（Datasheet）这个芯片的电参数、引脚、极限值、特性公式厂家一手NOTE/Doc/GD32F407/GD32F407xx_Datasheet_Rev2.7.pdf
2用户手册（User Manual）每个外设怎么工作、寄存器每一位什么意思、有哪些图和表厂家一手NOTE/Doc/GD32F407/GD32F4xx_User_Manual_Rev3.0_CN.pdf
3固件库源码与头文件这个库函数怎么实现、"官方推荐怎么配"最贴近你写的代码Firmware/GD32F4xx_standard_peripheral/
4启动文件中断函数到底该叫什么名字工程一手Firmware/CMSIS/GD/GD32F4xx/Source/ARM/startup_gd32f407_427.s
5原理图 / PCB 网表板子上到底怎么接的（哪个脚被谁占了）硬件唯一真相NOTE/Doc/board/*.pdf、Doc/硬件信息汇总.md
6教材 / 参考笔记入门、梳理、经验（有观点、可能过时）二手，便于上手NOTE/Note/、NOTE/Textbook/

一句话记住各自的位置：

数据手册 = 芯片的"体检报告"（能跑多快、多热、多少伏）
用户手册 = 芯片的"使用说明书"（每个部件怎么用、怎么配寄存器）
库源码   = "别人写好的代码"（最直接能抄，注释常有金句）
启动文件 = "名字的出处"（中断函数名写死在这里）
原理图   = "板子的真相"（代码写得再对，脚接错了也没用）
教材     = "导航"（帮你快速知道该查哪张表，但要用前五类核对）

二、按"问题类型"选资料（最实用的一张表） ​

拿到一个疑问，先判断它属于哪一类，然后直奔对应的资料：

问题类型典型问法该查哪本具体查什么章节/表
A. 引脚 / 复用「PA2 能不能做 TIMER1 的 PWM？」「PB6 还能做别的不？」用户手册 + 数据手册用户手册「引脚复用表 / AF 表」；数据手册「引脚定义表」
B. 寄存器 / 位域「TIMERSEL 这个位选什么？」「I2C 的 ACKPOS 在哪一位？」用户手册对应外设章节的「寄存器映射表」
C. 电气 / 参数「ADC 时钟最高多少？」「内部上拉多大电阻？」「IO 最大灌电流多少？」数据手册「电气特性」章节（DC characteristics）
D. 时序「I2C 的起始条件是什么波形？」「SPI 该用哪个边沿采样？」用户手册（时序图） + 数据手册（时序参数）用户手册外设章节的「时序图」；数据手册的「AC 特性表」
E. 公式 / 换算「ADC 值怎么换成温度？」「波特率怎么算？」数据手册（公式与典型值） + 库源码（实现）数据手册「特性说明」；库源码里同名函数
F. 中断「中断函数该叫什么名字？」「中断号是多少？」启动文件 + 用户手册.s 文件的中断向量表；用户手册中断表
G. 板级连接「这个脚被谁占了？」「按键接上拉还是下拉？」原理图 / PCB 网表网表、Doc/硬件信息汇总.md
H. 工程配置「系统时钟是多少？」「选了哪套时钟配置？」工程源码（CMSIS）system_gd32f4xx.c 的宏开关

判断技巧：问"能不能/在哪"→ A/G；问"怎么配"→ B；问"多少"→ C；问"什么时候"→ D；问"等于"→ E；问"叫什么"→ F。

三、用户手册里要的"图和表" ​

用户手册的价值集中在五类图表上——找手册的本质就是找这五类东西：

类型长什么样用来回答本工程实例
① 功能框图外设内部的方块图（含分频器、寄存器、比较器、引脚）"这个外设内部是怎么工作的"定时器框图 → 理解 PSC/CNT/ARR/CCR 的关系（第 07 篇）
② 时钟树图从晶振到各总线的树状图"这个外设的时钟从哪来、多少 Hz"定时器倍频、APB1/APB2 分频（第 14 篇）
③ 寄存器映射表每个寄存器每个位的名称/读写/复位值"某一位该写几"RCU_CFG1 的 TIMERSEL 位（第 14 篇）
④ 中断向量表中断号 ↔ 中断源 ↔ 函数名"中断函数叫什么、几个中断源共用"TIMER5 与 DAC 共用 → TIMER5_DAC_IRQHandler（第 07 篇）
⑤ 时序图信号随时间的波形图"什么时候采样/什么时候可以变"I2C 起始/停止条件、SPI 的 CPOL/CPHA（第 15/16 篇）

还有一个"表"极其实用：

类型用来回答本工程实例
复用功能表（AF 表）「这个引脚能做哪些外设、用哪个 AF 编号」PA2 = TIMER1_CH2 / AF1；PB9 = TIMER1_CH1 / AF1；PE8/PE9 = TIMER0_CH0 的 N/P / AF1

"复用功能表"是查得最多的一张表——第 07 篇踩的坑（ef6a015 把 PB9 配成 AF2）本质上就是没查这张表。

怎么快速定位这五类图表：

① 先看目录：找到外设章节（如 "16 定时器"）
② 章节内通常有固定顺序：概览 → 功能框图 → 工作模式 → 寄存器 → （时序）
③ 直接搜表号：中文手册的表号形如"表 16-1"，英文是 "Table 16-1"
④ 搜关键词：把"图"换成"Figure"、"表"换成"Table"再搜一遍（有些中文手册保留了英文图表号）

四、数据手册里要的"数据和公式" ​

数据手册（Datasheet）的章节结构也很固定，你要的东西基本集中在这几处：

章节长什么样用来回答本工程实例
引脚定义/描述每种封装的引脚清单表哪个脚是什么功能、有几路20 引脚表（第 20 篇的 80 脚对照就是它 + PCB）
绝对最大额定值电压/电流/温度的"不许超过"表会不会烧（本工程未涉及）
电气特性（DC/AC）供电、IO 电平、上拉电阻、时钟精度、功耗"能跑多快、多准"ADC 时钟上限、IRC32K 精度（第 13 篇 7.1 节）
**特性说明 / 功能描述文字 + 公式怎么换算（温度、电压）内部温度传感器公式（第五章案例 5）
封装与订货信息封装尺寸、料号打板/采购（本工程未涉及）

4.1 数据手册最容易被忽略的一点：典型值 vs 保证值 ​

这是查数据手册最容易犯的错：

类型含义例子
Typical（典型值）大部分芯片的表现，不保证V25 = 1.45 V（温度传感器 25℃ 时的输出电压）
Min / Max（保证值）全温度范围、全批次都满足的边界TL = ±1.5 ℃
仅在某条件下成立表格旁边常有一行"条件""VDD = 3.3 V, TA = 25 ℃"

本工程的真实后果：

c
// main.c 里的温度计算
float temp = (1.45f - vol) * 1000 / 4.1f + 25;
//            ↑ V25 是"典型值"，不同芯片可能是 1.38 V 或 1.52 V

五、本工程 14 个真实查证案例（本章是全文精华） ​

每一个都给出：问题 → 查了什么 → 查到什么 → 影响了哪行代码。

案例 1：定时器时钟到底是 168 MHz 还是 336 MHz？ ​

步骤内容
问题APB1 = 42 MHz、APB2 = 84 MHz，RCU_TIMER_PSC_MUL4 之后定时器时钟是多少？按"×4"算 APB2 会得到 336 MHz（超规格）
查哪本固件库头文件（比手册更直接）：Firmware/.../Include/gd32f4xx_rcu.h
查到什么第 962~969 行注释原文：MUL4 时，若 APB1PSC/APB2PSC ∈ {÷1, ÷2, ÷4}，则 CK_TIMERx = CK_AHB；否则才是 4 × CK_APBx
影响本工程 APB1=÷4、APB2=÷2 都在允许集合内 → 所有定时器统一 168 MHz；也定下了"改 APB 分频必须重算所有定时器参数"这条铁律（第 13/14 篇）

这个案例说明："库源码里的注释"经常比用户手册好用——它直接回答"我这样配会得到什么"，而手册只描述"这个位是什么意思"。

案例 2：中断函数该叫什么名字？ ​

步骤内容
问题TIMER5 的中断服务函数叫什么？
查哪本启动文件：startup_gd32f407_427.s 的中断向量表
查到什么TIMER5_DAC_IRQHandler——TIMER5 和 DAC 共用同一个中断向量
影响写成 TIMER5_IRQHandler 编译能过，但中断永远不触发（第 07 篇反复强调的坑）

同源案例：EXTI5~9 共用 EXTI5_9_IRQHandler（第 17 篇 PCF8563 的 INT 走 EXTI5）。

查法口诀：中断函数名 = 去启动文件的向量表里搜。搜关键词（外设名）最快，比如 grep -n "USART0_IRQHandler" startup_*.s。

案例 3：这个引脚能做哪个定时器的 PWM？ ​

步骤内容
问题PB9 想输出 PWM，用哪个定时器、哪个通道、哪个 AF？
查哪本用户手册的复用功能表（教材整理成了一张查询表：NOTE/Note/TIMER.md 2.3 节）
查到什么PB9 = TIMER1_CH1，AF1（同一引脚还可能是 TIMER3_CH3 / TIMER10_CH0 等，需按 AF 区分）
影响第 07 篇 ef6a015 曾把 PB9 配成 AF_2 + 用 TIMER_CH_2，两个都错 → 引脚毫无波形；b4f56b7 才改成 AF1 + TIMER_CH_1

教训："引脚 → 定时器 → 通道 → AF"是一个四元组，必须一起查、一起改（第 07 篇的"三件套/四件套"）。

案例 4：串口波特率的分频怎么算？ ​

步骤内容
问题USART0（APB2）和 USART2（APB1）都配 115200，分频值一样吗？
查哪本库源码：gd32f4xx_usart.c 的 usart_baudrate_set()
查到什么它按外设分支去取总线频率：USART0 → rcu_clock_freq_get(CK_APB2)；USART2 → CK_APB1；然后 udiv = (uclk + baud/2)/baud，拆成 mantissa + fraction
影响逐位复算后：USART0 的 USARTDIV = 45.5、USART2 = 22.75，实际波特率都是 115384.6（+0.16% 误差）（第 13 篇 5.9 节）

案例 5：ADC 内部温度怎么换算？（数据手册公式的典型） ​

步骤内容
问题ADC 采到的值怎么变成温度？
查哪本数据手册：GD32F407xx_Datasheet_Rev2.7.pdf 的表 4-36（温度传感器特性）
查到什么公式 T(℃) = (V25 − V_sense) / Avg_Slope + 25；参数 V25 = 1.45 V、Avg_Slope = 4.1 mV/℃、tS_temp = 17.1 μs（最小采样时间）、TL = ±1.5 ℃
影响① 代码里的温度公式（含那个容易漏的 ×1000）② 采样时间必须满足 17.1 μs —— 第 19 篇发现温度通道被改成了 15 周期（0.71 μs），不满足要求

这个案例同时演示了两种查法：

  • 查公式 → 数据手册的"特性说明"章节（不是寄存器章节！）
  • 查约束（最小采样时间）→ 数据手册的参数表，并且要把它换算成本工程的条件（17.1 μs 对应 21 MHz 下至少 360 个采样周期）

案例 6：ADC 时钟最高能多少？ ​

步骤内容
问题ADC 分频该取多少？
查哪本用户手册/数据手册的 ADC 电气特性
查到什么代码注释保留了这个结论：/* 设置分频系数 21Mhz(根据时钟树确定要小于49Mhz)*/
影响ADC_ADCCK_PCLK2_DIV4：84 MHz ÷ 4 = 21 MHz（安全）

注意那行注释的写法：结论（21 MHz）+ 依据（小于 49 MHz）+ 依赖（根据时钟树）——三条信息都留给了下一个看代码的人。这就是"把查到的结论写回代码"的正面例子（第八章展开）。

案例 7：I2C 器件的 7 位地址是多少？ ​

步骤内容
问题PCF8563 的 I2C 地址？OLED 的地址？
查哪本器件的数据手册（不是 MCU 手册！）
查到什么PCF8563 = 0x51；SSD1306 OLED = 0x78（8 位形式）→ 0x3C（7 位）
影响代码里 PCF8563_ADDR 0x51、OLED 里写 0x78 >> 1；理解为什么必须右移一位（第 15/18 篇）

⚠️ 一个高频混淆：器件厂商喜欢给"8 位地址"（含读写位，如 0x78/0xA2），而 MCU 库要"7 位地址"（0x3C/0x51）。看到地址先确认它包含几位——这是最经典的"查了手册但还是配错"的坑。

案例 8：代码注释和器件手册"打架"时听谁的？ ​

步骤内容
问题PCF8563 定时器时钟源的编码（0x0E 寄存器 bit[1:0]）到底是什么？
查哪本PCF8563 数据手册
查到什么手册的编码顺序与工程代码注释里写的顺序相反（第 17 篇 4.3 节指出了这处矛盾）
影响结论：以手册为准；代码注释是二手的、可能抄错

这条是全文最重要的一条原则：手册（一手）> 代码注释/教材（二手）。 但要区分是谁的手册：MCU 手册管 MCU，器件手册管器件——查传感器/RTC/Flash 的参数，必须去翻那颗器件自己的数据手册。

案例 9：这个引脚"到底被谁占了"？ ​

步骤内容
问题代码里 printf 用的是 USART0(PA9/PA10)——这两个脚在板上真的接出去了吗？PB10 呢？
查哪本原理图 / PCB 网表（本工程已整理成 Doc/硬件信息汇总.md、Doc/引脚检查测试.md）
查到什么① PA9/PA10 没引出到排针，就是板载 USB-TTL → printf 重定向到它是正确的 ② PB10 是 LCD 背光（LCD_BLK），而代码把它当 USART2_TX → 冲突（P1） ③ MCU 侧没有 32.768 kHz 晶振（焊在 PCF8563 上）
影响解释了第 11 篇"为什么 RTC 用 HXTAL"；第 20 篇的 P1/P2/P3

这一条的关键认识："引脚占用"这类问题在 MCU 手册里查不到——手册只告诉你"这个脚能做哪些功能"，能不能用要问原理图/PCB。

案例 11：SPI Flash 的指令和 ID 在哪张表？ ​

步骤内容
问题bsp_flash.c 里那些 0x90 / 0x06 / 0x05 / 0x20 / 0x02 / 0x03 是什么？读 ID 该期待什么值？为什么读出来是 16 位而不是 24 位？
查哪本器件数据手册（GD25Q32/W25Qxx）：Instruction Set 表 + Read Manufacturer / Device ID 一小节
查到什么① 指令表：06h WREN / 05h RDSR / 03h Read / 02h Page Program / 20h Sector Erase / 90h Read M-ID&D-ID / 9Fh JEDEC ID
② 90h 返回 2 字节（制造商 + 设备），9Fh 返回 3 字节（制造商 + 类型 + 容量）——这就是"为什么本工程是 16 位、官方例程是 24 位"的答案
③ 90h 后面必须跟 3 个"假地址字节"（内容随意，但少一个就整个错位）
影响代码里 spi_read_write_byte(0x90) + 3 个 0x00 + 读 2 字节的写法逐字对应手册；串口期望 ID = C8xx（制造商 C8 = GigaDevice）

补充技巧（很实用）："官方例程"是第三类资料，而且就在本机。 本工程固件库里带着 GigaDevice 官方的 GD25Qxx 驱动： NOTE/Doc/GD32F407/GD32F4xx_Firmware_Library_V3.2.0/Examples/USB/USB_Device/dev_firmware_update/src/gd25qxx.c 它用的是 9Fh（3 字节）并且拉低一次 CS 连续读状态寄存器（比本工程逐次重发 05h 更高效）， 还提醒了"块擦除不只有 64 KB，还有 32 KB"（SPI_FLASH_BLOCK_SIZE 0x8000）。 查手册的同时翻一眼官方例程，往往能直接省掉一次试错（第 24 篇 §3 就是两版对照）。

案例 12：Flash 擦一次要多久？（"物理时间"该怎么查） ​

步骤内容
问题bsp_flash_wait_busy() 要等多久？写 10 个字节花多长时间？
查哪本器件数据手册的 AC Characteristics / 时序表
查到什么tPP（Page Program, 256 B）typ 0.7 ms / max 3 ms；tSE（4 KB 扇区擦除）typ 45 ms / max 400 ms；tBE、tCE 更大
影响★ 换算成"要不要小心"：45 ms ≫ WWDGT 窗口 1.66 ms、≫ FWDGT 超时 100 ms —— "开看门狗"和"写 Flash"在当前代码结构下互斥（第 13 篇 §7.4、第 24 篇 §7.2）

这类"器件内部时间"和"总线时钟"完全无关，是第 13 篇里补的"第三类时间：物理时间"。 查法要点：它的单位是 ms / s，不是"周期数"——看到 ms 级数字就要立刻联想到"看门狗、主循环阻塞、低功耗唤醒"。

案例 13：NTC 的 R-T 表从哪来？ ​

步骤内容
问题bsp_ntc.c 里那 181 个数（58354 … 32）是什么？为什么不用公式算？
查哪本器件规格书（NTC 供应商提供的 R-T 对照表），或整机原理图上标明的型号
查到什么表 = 温度 → 阻值×100（单位 0.01 kΩ），步长 1 ℃，范围 −55 ~ +125 ℃
影响① 换 NTC 型号 → 必须整表替换（第 27 篇练习题 1）
② 这张表替代了 B 值公式——因为真实 NTC 的等效 B 值随温区变化（0→25 ℃ 段 ≈3800 K，25→50 ℃ 段 ≈3960 K，差 4%）
③ 表占 362 B 存储（且必须加 const 才会真的放进 flash，第 27 篇 §7）

这三张表（Flash 指令表 / Flash 时序表 / NTC 的 R-T 表）合起来说明一件事： 只要用到一个"片外器件"，就至少要有三本资料——芯片手册（怎么配 MCU）、 器件手册（怎么和它说话）、器件规格/整机图纸（它到底是什么参数）。 "查不到"的时候，往往不是手册写得差，而是查错了书（第 42 页那句）。

案例 14：WS2812 的时序参数和"分频只能是 2 的幂" ​

步骤内容
问题WS2812 的 '0'/'1' 各要多长的高电平？复位低电平要多久？怎么让 MCU 发出来？
查哪本器件数据手册（WS2812B / WS2812B-V5）：Timing 表 + GD32F4xx_User_Manual（SPI 分频档位）+ gd32f4xx_rcu.h（SPI1 挂哪条总线）
查到什么① T0H = 400±150 ns、T1H = 800±150 ns、位周期 1.25 µs、复位低电平 >50 µs（B）/ >280 µs（V5）
② SPI 分频只能是 2 的幂（SPI_PSC_2/4/8/…），APB1=42 MHz → 只有 21 / 10.5 / 5.25… MHz，没有 8 MHz
③ RCU_APB1EN_SPI1EN → SPI1 挂 APB1（42 MHz），不是 84 MHz
影响★ 三条合起来决定了实现方案：时钟改不了就改"1 个 WS2812 位用几个 SPI 位"（10 → 13），使 13 ÷ 10.5 MHz ≈ 1238 ns；否则时序错 24%，4 颗灯只亮 1 颗（第 30 篇 §4）

这个案例最能说明"一件产品要查三本书"：器件手册给"要求什么"，用户手册给"我能配出什么"， 库头文件给"这个外设挂在哪条总线上"。三者缺一，都会得出错误的参数。

十一、练习题 ​

  1. 查一张表：在用户手册里找到"定时器"章节的复用功能表，查出 PD12/PD13/PD14/PD15 分别对应 TIMER3 的哪个通道、哪个 AF 编号，和 NOTE/Note/TIMER.md 2.3 节的表对一遍。
  2. 查一条公式：打开 GD32F407xx_Datasheet_Rev2.7.pdf，找到表 4-36，抄下 V25、Avg_Slope、tS_temp、TL 四个参数的完整条件行（比如测试条件是什么）。
  3. 查一个电气上限：找出 GD32F407 的 ADC 时钟上限和单个 IO 的最大灌电流，分别写清出处（表号 + 版本）。
  4. 查中断名：用 grep 从启动文件里列出所有含 TIMER 和 EXTI 的中断函数名，找出哪些是"共用向量"的。
  5. 查一次冲突：从 Note/ 或 Textbook/ 里找一条"代码注释与手册不一致"的说法（除了本专题列出的三处），核对后写出正确结论与出处。
