一、中断解决了什么问题 ​

1.1 从轮询说起 ​

没有中断时，程序只能轮询（polling）——不停地问「变了没？变了没？」：

c
while (1)
{
    if (gpio_input_bit_get(GPIOA, GPIO_PIN_0) == SET)   // 问一次
    {
        // 处理
    }
    // ... 顺便干点别的
}

轮询有两个绕不过去的问题：

问题说明
响应不及时你问的间隔是 20 ms，那按一下至少延迟 0~20 ms 才被发现
浪费时间99.99% 的时间答案都是「没变」，CPU 在做无用功

1.2 中断的四个特性 ​

特性白话解释
异步什么时候来不知道，来了立刻跳过去
即时硬件直接通知 CPU，响应是纳秒~微秒级
可嵌套高优先级的中断可以打断低优先级的中断
有优先级同时来多个请求时，按优先级决定谁先处理

1.3 中断 vs 轮询：本工程两种都用 ​

独立按键 KEY1~KEY4核心板按键 PA0 / 扩展板 KE4
实现方式轮询（bsp_keys_scan()，20 ms 一次）中断（EXTI0 / EXTI3）
代码位置第 03 篇本篇
为什么4 个按键一一轮询，资源够用，逻辑简单演示中断、学习消抖；按键事件要求即时
代价20 ms 内的抖动/连击只能靠周期过滤必须自己处理抖动，否则一次按下触发多次

结论：不是「中断一定比轮询好」。普通按键、数量少、对延迟不敏感 → 轮询更简单可靠。中断适合「事件稀少但要即时」或「必须立刻响应」的场景（比如急停、编码器、串口接收）。

2.2 NVIC 与优先级 ​

NVIC（Nested Vectored Interrupt Controller，嵌套向量中断控制器）负责管理所有中断。本工程在 main() 开头统一设置优先级分组：

c
// 配置整个工程优先级分组 抢占:0~3  响应:0~3
nvic_priority_group_set(NVIC_PRIGROUP_PRE2_SUB2);
1
2

4 个 bit 的优先级被分成两段：

  bit3 bit2 │ bit1 bit0
  └─ 抢占 ──┘└─ 响应 ─┘
    0~3        0~3
1
2
3
类型作用规则
抢占优先级决定能不能打断正在执行的中断数值小 = 优先级高。高抢占可以打断低抢占
响应优先级决定同时发生时谁先处理数值小 = 先处理。已开始执行后不能被打断

本工程所有外设中断都用 nvic_irq_enable(xxx_IRQn, 2, 2)，即抢占 2、响应 2——统一水平，互不打断。这样最简单，也最不容易出诡异问题。

⚠️ 但这个分组在 2026-10-19 被改掉了（移植 FreeRTOS 时）：

c
// 裸机（09-16 ~ 10-18）
nvic_priority_group_set(NVIC_PRIGROUP_PRE2_SUB2);   // 2 位抢占 + 2 位响应

// 移植 FreeRTOS 之后（10-19 起）
nvic_priority_group_set(NVIC_PRIGROUP_PRE4_SUB0);   // 4 位全给抢占

两个连带后果（写中断代码时一定要知道）：

后果说明
nvic_irq_enable(irq, pre, sub) 的 sub 失效响应位是 0 位，传什么都一样。msp_exti.c 里那个 2 现在没有意义，实际优先级就是 pre = 2
★ 所有 EXTI 中断（优先级 2）里都不能调 xxxFromISR()FreeRTOS 规定"优先级数值 ≥ 5"的中断才能调 ISR 版 API。优先级 2 < 5 → 调了就破坏内核临界区（详见 第 35 篇 §4.2）

本工程现在的 EXTI 里只置标志（g_rtc_int_flag / g_touch_key_int_flag）——恰好合规 ✅ 但这是"被规则逼出来的正确"，不是设计时就知道的。 哪天想在 EXTI 里直接发队列/信号量，必须先把优先级改成 ≥ 5（比如 6）。

只有在「串口接收不能被某段代码打断」这类需求下，才需要仔细排优先级。参考笔记 EXTI.md 第四章有 5 组优先级对照实验，值得一读。

2.3 EXTI 的 15 条线，一条线只认一个引脚号 ​

EXTI 有 EXTI_0 ~ EXTI_15 共 16 条线，按引脚号（Pin Number）分组：

EXTI_0  ← PA0 / PB0 / PC0 / PD0 ... 中只能选一个
EXTI_3  ← PA3 / PB3 / PC3 / PD3 ... 中只能选一个
1
2

本工程用到：

按键引脚EXTI 线中断号
核心板按键PA0EXTI_0EXTI0_IRQn
扩展板 KEY4PC3EXTI_3EXTI3_IRQn

注意：PC0/PC1/PC2（即 KEY1~KEY3）不能用 EXTI0-2，因为 EXTI_0 已经被 PA0 占了，EXTI_1/EXTI_2 也各只能接一个引脚号——但 PC0/PC1/PC2 的引脚号是 0/1/2，和 PA0 冲突。这正是 KEY1~3 只能轮询的原因之一。

三、提交 7e3862f：第一路外部中断（PA0） ​

提交信息：[更新] PA0(核心板按键)外部中断

这次提交在 main.c 里裸写了一个标准的 EXTI 配置，拆成两个函数：

c
void GPIO_config(void)
{
    // 1.配置引脚GPIO模式
    rcu_periph_clock_enable(RCU_GPIOA);
    gpio_mode_set(GPIOA, GPIO_MODE_INPUT, GPIO_PUPD_NONE, GPIO_PIN_0);
}

void EXTI0_config(void)
{
    // 2.选择EXTI检测线路连接引脚(SYSCFG)
    rcu_periph_clock_enable(RCU_SYSCFG);
    syscfg_exti_line_config(EXTI_SOURCE_GPIOA, EXTI_SOURCE_PIN0);
    // 3. 配置EXTI检测极性(上升沿/下降沿/BOTH触发)
    exti_init(EXTI_0, EXTI_INTERRUPT, EXTI_TRIG_BOTH);
    // 4. 告诉NVIC要处理EXTI中断(NVIC中注册)
    nvic_irq_enable(EXTI0_IRQn, 2, 2);
    // 5. 清除中断标志位
    exti_interrupt_flag_clear(EXTI_0);
    // 打开EXTI中断
    exti_interrupt_enable(EXTI_0);
}

void EXTI_PA0_config(void)
{
    GPIO_config();
    EXTI0_config();
}

3.1 EXTI 五步配置（背下来） ​

步代码干什么漏了会怎样
1rcu_periph_clock_enable(RCU_GPIOA) + gpio_mode_set(...)把引脚配成输入引脚不受控，电平读不对
2rcu_periph_clock_enable(RCU_SYSCFG) + syscfg_exti_line_config(...)把 EXTI 线路接到具体引脚上中断永远不来（最常漏的一步）
3exti_init(EXTI_0, EXTI_INTERRUPT, EXTI_TRIG_BOTH)配触发极性用默认值，可能是「不触发」
4nvic_irq_enable(EXTI0_IRQn, 2, 2)在 NVIC 里打开该中断外设触发了，但 CPU 不理
5exti_interrupt_flag_clear() + exti_interrupt_enable()清残留标志 + 打开 EXTI 中断使能上电就进一次中断 / 完全不来

第 2 步为什么这么容易漏？ 因为它和「配 GPIO」「配 EXTI」看起来不搭边——它是接线动作：

        PA0 引脚 ────[SYSCFG 接线员]──── EXTI_0 线路 ──── NVIC ──── CPU
                     ↑
        这一步就是 syscfg_exti_line_config(EXTI_SOURCE_GPIOA, EXTI_SOURCE_PIN0)
        「把 PA0 这根线，接到 EXTI_0 这条线上」

3.2 触发极性三种 ​

c
exti_init(EXTI_0, EXTI_INTERRUPT, EXTI_TRIG_BOTH);
1
参数含义适用
EXTI_TRIG_RISING只在上升沿触发只关心按下（接下拉的按键）
EXTI_TRIG_FALLING只在下降沿触发只关心按下（接上拉的按键）
EXTI_TRIG_BOTH上下沿都触发本工程用它，按下和松开都能捕获

选 BOTH 的代价：消抖要处理两次（按下一次、松开一次），而且中断次数翻倍。换来的是「能区分按下/松开」。

3.3 怎么区分上升沿还是下降沿 ​

EXTI 只告诉你「有边沿发生了」，不告诉你方向。所以要读一下引脚当前电平：

c
if (gpio_input_bit_get(GPIOA, GPIO_PIN_0) == SET)
{
    // 当前是高电平 → 刚才应该是「从低变高」→ 上升沿
}
else
{
    // 当前是低电平 → 应该是「从高变低」→ 下降沿
}

这个判断只在「边沿刚发生、信号还稳定」时成立——这也是为什么要在中断服务函数最前面就做，不能先干别的事再读。

注意 PA0 的电平含义（回顾第 03 篇）：

按键接法松开按下
PA0（核心板）外部下拉，GPIO_PUPD_NONE低（RESET）高（SET）
PC3（扩展板 KEY4）内部上拉，GPIO_PUPD_PULLUP高（SET）低（RESET）

所以「上升沿 = 按下」只对 PA0 成立，对 PC3 恰好相反。

us_cnt 每隔 1 μs 自增一次（SysTick 配成了 1 MHz），于是全工程有了一个统一的「当前时刻」。后面所有非阻塞定时、消抖、蜂鸣器节拍全靠它。

为什么用 uint64_t 而不是 uint32_t？ uint32_t 存微秒只能表示约 4295 秒（71 分钟），而且减去「上次时刻」时更容易溢出。uint64_t 可以用上几十万年——用空间换掉一整类溢出 bug。

4.2 消抖：两个手段配合 ​

c
uint64_t pre_cnt = 0U;          // 上次有效事件的时间戳
FlagStatus pre_status = SET;    // 上次记录的电平

void EXTI3_IRQHandler(void)
{
    uint64_t cur_cnt = get_us_cnt();

    // 中断处理函数中的套路：先判断中断标志位，再清除中断标志位
    if (exti_interrupt_flag_get(EXTI_3) == SET)
    {
        exti_interrupt_flag_clear(EXTI_3);

        // 消抖
        if (cur_cnt - pre_cnt < 30000)      // ① 时间窗：30 ms 内不再响应
            return;
        pre_cnt = cur_cnt;

        FlagStatus cur_status = gpio_input_bit_get(GPIOC, GPIO_PIN_3);
        if (cur_status == pre_status)       // ② 电平去重：电平没变就不处理
            return;
        pre_status = cur_status;

        if (cur_status == RESET)            // 下降沿 = 按下（PC3 上拉接法）
        {
            printf("EXTI3_IRQHandler: falling edge\r\n");
        }
        else
        {
            printf("EXTI3_IRQHandler: rising edge\r\n");
        }
    }
}

两个手段各自解决什么问题：

手段解决的抖动类型原理
① 时间窗（30 ms）按下/松开瞬间的机械抖动（一串几十~几百 μs 的毛刺）第一次触发后，30 ms 内所有后续触发直接忽略
② 电平去重重复的边沿（比如抖动结束又出现了同方向的边沿）只有「电平真的和上次不一样」才算有效事件
理想信号：       ────┐                    ┌────
                     └────────────────────┘
                     ↑按下                ↑松开

真实信号（有抖动）：──┐  ┌┐ ┌─              ┌──┐ ┌────
                     └──┘└─┘               ──┘  └┘
                     ↑↑↑↑ 4 次边沿触发！

加上消抖后：        ──┐                    ┌────
                     └────────────────────┘
                     只认这一次              只认这一次

if (cur_cnt - pre_cnt < 30000) 这个减法的两个细节：

细节说明
为什么用减法而不是比大小pre_cnt 是「上次时刻」，cur_cnt 是「现在」。直接比大小在计数器回绕时会出错；无符号减法会自动处理回绕（0x00 - 0xFFFFFFFF = 1，结果仍然正确）
为什么是 < 而不是 <=语义上「严格小于 30000 μs 才算太近」，边界值放过去。差别不大，但要前后一致
30000 μs = 30 ms机械按键抖动通常 5~20 ms，取 30 ms 留余量。太大（如 200 ms）会让快速连按失效

为什么不能用 delay_1ms(20) 来消抖？ 因为在中断里调 delay_1ms() 会让 CPU 空转 20 ms，期间所有同级中断都进不来——中断里绝不做延时。

4.3 一次「跑偏」：回调被整段注释掉 ​

这次提交里，main.c 中的 on_key_press() 被整块注释掉了（第 03 篇里刚写好的那段），main() 里 bsp_keys_config()、bsp_battery_flow_init() 等也都被注释，主循环只剩空转。

这不是失误，是「测试模式」——作者当时只想单独验证 EXTI 能不能工作，把其他干扰全部关掉。调试单点问题时隔离变量，是很有效的手段，但代价是：这些注释块需要在 dbb9026 之后清理，否则代码会越来越脏。

可以学的手法：调试时用 #if 0 ... #endif 代替大段注释，语义更清楚；或者干脆建一个分支专门调。

static void EXTI_config(rcu_periph_enum rcu, uint32_t port, uint32_t pin, uint32_t pupd,

    gpio_mode_set(port, GPIO_MODE_INPUT, pupd, pin);

5.3 中断服务函数：把调试打印换成有意义的输出 ​

c
// EXTI0中断处理函数
#if USE_EXTI0
void EXTI0_IRQHandler()
{
    static FlagStatus pre_sta = RESET;
    static uint64_t pre_cnt = 0;

    if (exti_interrupt_flag_get(EXTI0_NUM) == SET)
    {
        exti_interrupt_flag_clear(EXTI0_NUM);

        // 消抖
        uint64_t cur_cnt = get_us_cnt();
        if (cur_cnt - pre_cnt <= 30000)
        {
            return;
        }
        pre_cnt = cur_cnt;
        FlagStatus cur_sta = gpio_input_bit_get(EXTI0_PORT, EXTI0_PIN);
        if (cur_sta == pre_sta)
        {
            return;
        }
        pre_sta = cur_sta;

        if (cur_sta == SET)
        { // 上升沿  按下        ← PA0 是外部下拉，按下为高
            printf("KEYC_D\n");
        }
        else
        { // 下降沿  松开
            printf("KEYC_U\n");
        }
    }
}

八、排查清单 ​

现象优先检查
中断完全不触发漏了 syscfg_exti_line_config()；或中断函数名拼错（必须叫 EXTI0_IRQHandler）
只进一次中断，之后再也进不来中断里没清标志位；或清了但清错了对象
上电立刻进一次中断exti_interrupt_flag_clear() 没在 exti_interrupt_enable() 之前调用
按键一次触发好几次没消抖；或消抖窗口太短（抖动约 5~20 ms，建议 ≥ 20 ms）
快速连按没反应消抖窗口太长（30 ms 已偏保守，别再加到 100 ms 以上）
中断里读到错误的电平判断边的代码放在后面了，信号已经变化；应进中断立刻读
按下/松开判断反了忘了 PA0 是外部下拉（按下=高）、PC3 是内部上拉（按下=低）
中断进不去，但 GPIO 单独读电平正常nvic_irq_enable() 没调；或优先级分组没设导致优先级越界
中断里打印卡死 / 丢字符在中断里用了阻塞的 printf——中断里尽量别打印（本工程为了学习而打，生产代码应改成置标志）
主循环里读中断改的变量读到旧值变量缺 volatile（如 us_cnt、pre_cnt）
加第三路中断时两路互相干扰两条 EXTI 线用了同一个引脚号（EXTI_0 只能接 pin0）
编译报重复定义 EXTI0_IRQHandler关掉的那一路仍被编译，和别处的实现撞名

  1. 新增一路 EXTI（比如 PB5，用一个外部按键），走一遍完整的五步 + 头文件加 9 个宏 + 中断函数。
  2. 把中断里的 printf 改成「置一个标志位」，在主循环里检查标志并打印——体会「中断只做最少的事」。
  3. 用 EXTI_TRIG_FALLING 只捕获按下，观察消抖需要怎么调整（提示：不需要再判上升沿了）。
  4. 给 EXTI_config() 的 9 个参数打包成一个 EXTI_PARAM 结构体，参考第 04 篇串口句柄化的做法。
  5. 把 on_key_press 回调（第 03 篇）和 EXTI 结合起来：让 PA0 中断也触发 on_key_press 那套业务逻辑，而不是直接 printf。
