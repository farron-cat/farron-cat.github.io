学习目标 ​

  1. 说清 NTC 分压电路，并独立推导出 R = 10k × V / (3.3 − V)。
  2. 说出"查表法"相对"B 值公式"的优点与代价，并解释为什么真实 NTC 不能用单一 B 值描述。
  3. 会算 ADC 的采样时间，并判断"某个通道的采样时间够不够"。
  4. 看懂 ADC + 循环 DMA 如何做到"主循环随便读、后台一直在采"。
  5. 记住这次"先删旧、后建新"的迁移顺序带来的风险。

一、硬件：NTC + 分压 + ADC ​

1.1 NTC 是什么 ​

NTC = Negative Temperature Coefficient，负温度系数热敏电阻：温度升高 → 电阻下降（和普通电阻相反）。 它是"用电学量测温度"最便宜的方案，广泛用于电池、电机、充电器、家电。

本板（依据 Doc/硬件信息汇总.md 的引脚表与 5.4 节）：

器件引脚ADC 通道用途
NTC 热敏电阻PA1ADC0_IN1测环境/器件温度（本篇主角）
电位器（可调电阻）PC4ADC0_IN14手动调电压（练习用）
内部温度传感器芯片内部ADC0_IN16测芯片结温（第 19 篇）

1.2 电路与公式 ​

NTC 不可能直接接到 ADC——ADC 只能读"电压"。所以用分压把电阻变成电压：

                    +3.3V
                      │
                    [ 10 kΩ ]      ← 板上固定电阻（上臂）
                      │
                      ├──────────► PA1（ADC0_IN1）
                      │
                    [ NTC ]        ← 电阻随温度变（下臂）
                      │
                     GND

正向公式（分压定律）：

$$V_{PA1} = 3.3 \times \frac{R_{ntc}}{10k + R_{ntc}}$$

反向公式（代码里用的就是它）：

$$R_{ntc} = 10k \times \frac{V_{PA1}}{3.3 - V_{PA1}}$$

性质检查（这四行是理解 NTC 驱动的关键）：

温度NTC 阻值PA1 电压说明
越低越大越大（趋近 3.3 V）低温 → 高电压
越高越小越小（趋近 0 V）高温 → 低电压

所以："ADC 读数大 = 温度低"——和大多数传感器的直觉相反，第一次调的时候很容易搞反。 也正因为如此，NTC 断线（开路）会被读成"极低温"（电压顶到 3.3 V），短路则读成"极高温度"—— 这是 NTC 最经典的两个故障现象，排查时先怀疑接线（第八章第 1 条）。

二、★ 两种换算方法 ​

ADC 给出的是 0~4095 的数字。要变成"℃"，有两条路。

2.1 路线一：B 值公式（数学法） ​

NTC 厂家会给一个 B 值（本类器件典型 3950 K），公式为：

$$\frac{1}{T} = \frac{1}{T_0} + \frac{1}{B}\ln\frac{R}{R_0}$$

其中 $T_0 = 298.15\ \text{K}$（25 ℃）、$R_0$ = 25 ℃ 时的阻值（本例 10 kΩ）、$T$ 用开尔文。

优点：不需要表，两行代码就能算，换器件只改 B 和 R0。 缺点（关键）：① 需要 ln()（浮点数学库，慢且吃空间）；② 真实器件的 B 值不是常数。

用本工程的表来验证第 ② 点（顺手做一次真实数据核算）：

温区表里的阻值反推的等效 B
0 ℃ → 25 ℃32110 Ω → 10000 Ω≈ 3800 K
25 ℃ → 50 ℃10000 Ω → 3580 Ω≈ 3960 K

同一颗 NTC，两段温区算出的 B 差了 160 K（约 4%）。 结论：B 值只是"某个温区内的近似"，用它算全程必然有系统误差。 （这也解释了为什么"抄一个 B=3950 的公式"在实际产品里常常偏 1~2 ℃。）

2.2 路线二：查表 + 最近邻（本工程采用） ​

厂家通常会提供一张 R-T 对照表（每 1 ℃ 一个点，本工程取 −55 ~ +125 ℃，共 181 项）。

代码把这张表直接搬进数组，单位约定为 电阻 × 100（即 3211 表示 32.11 kΩ，步进 0.01 kΩ = 10 Ω）：

c
uint16_t temp_table[] = {
    58354, // -55
    55464, // -54
    ...
    3211,  // 0
    ...
    1000,  // 25       ← 10 kΩ NTC 的标称点
    ...
    32,    // 125
};

换算就是三步（bsp_ntc_get_tem()）：

① 电压：vol = adc * 3.3 / 4096
② 电阻：r   = 10 * vol / (3.3 - vol)      单位 kΩ
③ 查表：temp = search_tem(r * 100)        把 r 变成"×100"再和表比
1
2
3

优点：① 零浮点数学库依赖（只有一次除法）；② 精度 = 厂家表的精度，天然含器件非线性； ③ 温度范围可控、边界明确。

代价：① 占存储（181 × 2 B = 362 B）；② 搜索是 O(n) 线性扫描（181 次比较 + 绝对值）。

search_tem() 的策略是最近邻（找表里和最接近的那一项，直接取它的温度）：

c
int8_t search_tem(uint16_t r)
{
    uint8_t i = 1;
    uint8_t index = 0;                          // 最接近的索引
    uint16_t diff = abs(temp_table[0] - r);     // 最小的误差值（先假定第 0 项最接近）
    for (; i < sizeof(temp_table) / sizeof(temp_table[0]); i++)
    {
        if (abs(temp_table[i] - r) < diff)
        {
            diff = abs(temp_table[i] - r);
            index = i;
        }
    }
    return index - 55;                          // 索引 → 摄氏度（index 0 = -55 ℃）
}

四个细节：

细节说明
index - 55表是按 ℃ 顺序排的，所以"索引减 55"就是温度——表的下标本身就是刻度
abs() 用在 uint16_t 差值上temp_table[i] - r 会整型提升为 int 后再取绝对值，不会因为无符号相减而炸（这里写对了）
uint8_t index181 项刚好塞进 uint8_t（0~255）——但如果以后把表扩到 >256 项，这里就静默溢出（第七章第 2 条）
最近邻的误差相邻两项在低温段差几百、高温段只差几，所以低温段分辨力差、高温段反而更细（和 R-T 曲线的形状一致）

为什么不用二分查找 / 插值？ 表是按温度升序、电阻降序排列的（单调），完全可以二分（O(log n)）或线性插值（精度更高）。 作者选最简单写法是教学取舍——181 项每次多花不了多少时间（几十微秒）， 而"最近邻"的语义比插值更好理解。练习题 2、3 就是让你做这两个升级。

4.2 DMA 配置（外设 → 内存，循环模式） ​

c
static void msp_adc_dma_config()
{
    dma_deinit(DMA1, DMA_CH0);                    // 复位通道
    rcu_periph_clock_enable(RCU_DMA1);
    dma_single_data_parameter_struct init_struct;
    dma_single_data_para_struct_init(&init_struct);

    init_struct.direction = DMA_PERIPH_TO_MEMORY;                     // P2M
    init_struct.periph_addr = (uint32_t)(&ADC_RDATA(ADC0));           // 源：ADC 数据寄存器
    init_struct.memory0_addr = (uint32_t)encodes;                     // 目的：数组
    init_struct.periph_memory_width = DMA_PERIPH_WIDTH_16BIT;         // 16 位宽
    init_struct.number = ADC_LEN;                                     // 搬 ADC_LEN 次（现在是 4）
    init_struct.periph_inc = DMA_PERIPH_INCREASE_DISABLE;             // 外设地址固定
    init_struct.memory_inc = DMA_MEMORY_INCREASE_ENABLE;              // 内存地址递增
    init_struct.circular_mode = DMA_CIRCULAR_MODE_ENABLE;             // ★ 循环模式
    init_struct.priority = DMA_PRIORITY_LOW;

    dma_single_data_mode_init(DMA1, DMA_CH0, &init_struct);
    dma_channel_subperipheral_select(DMA1, DMA_CH0, DMA_SUBPERI0);    // ★ 通道映射查表
    dma_flag_clear(DMA1, DMA_CH0, DMA_FLAG_FTF);
    dma_channel_enable(DMA1, DMA_CH0);                                // 启动
}

四个不能错的点：

项值错了会怎样
directionPERIPH_TO_MEMORY设错则数据反向，全是垃圾
periph_inc / memory_inc外设不变 / 内存递增外设递增会读到不存在的寄存器
circular_modeENABLE关了就是"搬 3 次就停"（第 08 篇 P2M 的老问题）
subperipheral_select(..., DMA_SUBPERI0)DMA_SUBPERI0选错子外设 = DMA 永远收不到请求（第 08 篇重点讲过的"通道映射表"）

循环模式是本篇最舒服的一点：DMA 自己不停地搬，encodes[] 里的三个值永远是最新的—— 主循环随时读、不用等、不用触发。（第 19 篇的"每次转换完要触发一次"是手动版，这里是自动版。）

共享资源的坑（整理操作参考.md 已经点出）：ADC 用的是 DMA1_CH0 + SUBPERI0， 而第 08 篇的 DMA M2M 试验也占 DMA1_CH0。两者配置互斥，不可能同时存在—— 这也是 067922c 顺手删掉 DMA_m2m_config() 的硬件理由。

4.3 ADC 配置 ​

c
static void msp_adc_config()
{
    // 引脚：PC4（电位器）与 PA1（NTC）都配成"模拟"模式
    rcu_periph_clock_enable(RCU_GPIOC);
    gpio_mode_set(GPIOC, GPIO_MODE_ANALOG, GPIO_PUPD_NONE, GPIO_PIN_4);
    rcu_periph_clock_enable(RCU_GPIOA);
    gpio_mode_set(GPIOA, GPIO_MODE_ANALOG, GPIO_PUPD_NONE, GPIO_PIN_1);

    adc_deinit();
    rcu_periph_clock_enable(RCU_ADC0);
    adc_clock_config(ADC_ADCCK_PCLK2_DIV4);              // ★ APB2/4 = 84/4 = 21 MHz
    adc_sync_mode_config(ADC_SYNC_MODE_INDEPENDENT);
    adc_special_function_config(ADC0, ADC_CONTINUOUS_MODE, ENABLE);   // 连续转换
    adc_special_function_config(ADC0, ADC_SCAN_MODE, ENABLE);         // 扫描（多通道）
    adc_special_function_config(ADC0, ADC_INSERTED_CHANNEL_AUTO, DISABLE);
    adc_resolution_config(ADC0, ADC_RESOLUTION_12B);
    adc_data_alignment_config(ADC0, ADC_DATAALIGN_RIGHT);
    adc_channel_length_config(ADC0, ADC_ROUTINE_CHANNEL, ADC_LEN);    // ★ 通道数 = ADC_LEN（现在是 4）
    adc_routine_channel_config(ADC0, 0, ADC_CHANNEL_14, ADC_SAMPLETIME_15);   // 电位器 PC4
    adc_routine_channel_config(ADC0, 1, ADC_CHANNEL_16, ADC_SAMPLETIME_480);  // 内部温度
    adc_routine_channel_config(ADC0, 2, ADC_CHANNEL_1, ADC_SAMPLETIME_15);    // NTC PA1
    adc_channel_16_to_18(ADC_TEMP_VREF_CHANNEL_SWITCH, ENABLE);      // 内部通道要单独开

    adc_dma_request_after_last_enable(ADC0);   // DMA 请求相关（见下方说明）
    adc_dma_mode_enable(ADC0);                 // 打开 ADC 的 DMA 请求

    adc_enable(ADC0);
    delay_1ms(1);                              // 内部校准需要等待
    adc_calibration_enable(ADC0);
    adc_software_trigger_enable(ADC0, ADC_ROUTINE_CHANNEL);   // 启动
}

主循环什么都不用做，读 msp_adc_get(2) 就是最新温度。

两处需要留意的细节：

  1. 通道注释与代码不符：注释把 ADC_CHANNEL_14 和 ADC_CHANNEL_16 都标成"内部温度传感器 17.1us"， 而 ADC_CHANNEL_1（NTC）没有注释。按引脚表实际是：CH14 = 电位器、CH16 = 内部温度、CH1 = NTC。 —— 移植时如果照着注释改，很可能把 NTC 当成内部温度通道。注释也会骗人（第 23 篇的老话题）。
  2. adc_dma_request_after_last_enable() 的语义在库源码里是矛盾的： 函数名和 ADC_CTL1_DDM（DMA disable mode）的 enable/disable 两个版本的文档注释互相打架 （一个说"每次常规转换结束都发请求"，另一个说"检测到 DMA 传输结束信号后关闭 DMA 引擎"）。 遇到这种"名字和注释对不上"的情况，唯一可靠的办法是实测（换个通道数、看 encodes[] 会不会错位）。

4.4 NTC 侧换算 ​

c
int8_t bsp_ntc_get_tem(void)
{
    uint16_t adc_dat = 0;
    float vol = 0.0, r = 0.0;
    int8_t tem = 0;

    adc_dat = NTC_GET_ENCODE();          // = msp_adc_get(2)（第 3 个通道）
    vol = adc_dat * VREF / 4096;         // ① 数字 → 电压（VREF = 3.3）
    r = 10 * vol / (3.3 - vol);          // ② 电压 → 电阻（kΩ）
    tem = search_tem((uint16_t)(r * 100)); // ③ 电阻×100 → 查表得温度
    return tem;
}

#define NTC_GET_ENCODE() msp_adc_get(2)   // 通道号 2 = 序列里的第 3 个 = NTC(PA1)

为什么是 msp_adc_get(2) 而不是"通道 1"？ 这个 2 是 序列里的序号（adc_routine_channel_config(ADC0, 2, ADC_CHANNEL_1, ...) 的那个 2）， 不是通道号。两个编号体系混在一起是这个接口最容易踩的坑—— 一旦有人调换了序列顺序，NTC 就读到电位器的值（反之亦然）。练习题 4 就是把这件事显式化。

五、采样时间与精度的账 ​

ADC 时钟：ADC_ADCCK_PCLK2_DIV4，APB2 = 84 MHz → ADC 时钟 = 21 MHz。

一次转换的耗时 = 采样时间 + 12 个转换周期（12 位逐次逼近）：

序列通道采样周期采样时间一次转换总时间
0CH14（电位器）1515/21M = 0.714 µs27/21M = 1.29 µs
1CH16（内部温度）480480/21M = 22.86 µs492/21M = 23.43 µs
2CH1（NTC）1515/21M = 0.714 µs27/21M = 1.29 µs
合计≈ 26 µs / 轮

核对两件事：

  1. 内部温度通道必须 ≥ 17.1 µs 采样（数据手册对温度传感器的最小采样时间要求）： 480 周期 = 22.86 µs ≥ 17.1 µs ✅ 满足。

    这正是第 19 篇留下的那个问题的修复：d502d82 曾把温度通道改成 15 周期（0.714 µs，远不满足）， 现在这一版把它改回了 480。（当时笔记里标红的"不满足手册要求"，现在已被改好。）

  2. 外部通道（电位器 / NTC）用 15 周期（0.714 µs）是否够： 外部通道没有"17.1 µs"这种硬要求，但要求"采样时间 ≥ 源阻抗 × 采样电容的充电时间常数"。 15 周期的下限对应较低的源阻抗。分压电路里上臂是 10 kΩ， 源阻抗偏低（几 kΩ 量级），15 周期属于"快但偏紧"的选择—— 如果读出来的值跳得厉害，第一件事就是把采样时间加大到 ADC_SAMPLETIME_56 或以上（第八章第 3 条）。

换算成"刷新率"：一轮 26 µs → 一轮/26 µs ≈ 38 kHz。 也就是说 encodes[2] 每 26 µs 就被更新一次，远远快于任何温度变化的物理速度。 所以精度瓶颈完全不在采样速度，而在 NTC 表本身与分压电阻的精度（典型 ±1~2 ℃）。

七、遗留问题（3 个） ​

#问题位置后果 / 修法
13.3 - vol 可能为 0bsp_ntc_get_tem()NTC 开路时 vol → 3.3，浮点除零得 inf，再 (uint16_t)(inf) 是未定义行为。修法：if (vol > 3.29) vol = 3.29; 或先判"越界就返回上一次的值/错误码"
2表没有 constuint16_t temp_table[]数组被初始化过的全局变量默认放在 .data（RAM），而不是 flash——362 字节白占 RAM，与代码里"定义数组放到flash中"的注释相反。改成 static const uint16_t temp_table[] 才会进 flash 的 .rodata
3bsp_ntc_init() 是空函数bsp_ntc.c初始化责任全在 msp_adc_init()。留着空函数是为了接口对称（六个 bsp_*_init() 一字排开很好看），但对读者是误导——建议加注释说明"初始化在 msp_adc"

另外一个"设计层面"的观察：

bsp_ntc_get_tem() 返回 int8_t（−128~127，够 −55~125），而 bsp_188_leds_set_num() 收 uint8_t 且只接受 0~199 （第 26 篇）。于是在 main.c 里：

c
bsp_188_leds_set_num(bsp_ntc_get_tem());   // 负数会被隐式转成 255 附近的数 → 函数直接 return
1

后果：温度低于 0 ℃ 时数码管不更新（保留上一次的显示）——不是崩溃，是"沉默地不动"。 要显示负温，得先把 get_tem() 的结果做映射（例如 tem < 0 ? 199 : tem，或点亮 K1 当负号）。 两个模块各自的接口都没错，错在中间没做"单位/值域对齐"——这是多模块协作时最常见的缝隙。

练习题 ​

  1. 换一颗 NTC：把表换成另一规格（例如 10 kΩ B=3435）的 R-T 表，说明要改哪几行、不改会有什么后果。
  2. 换成二分查找：把 search_tem() 改成二分（提示：温度升序 ⇒ 电阻降序，是单调的），并比较比较次数。
  3. 加线性插值：在最近邻的基础上，用相邻两点做插值，把分辨力从 1 ℃ 提到 0.1 ℃（返回类型也要改）。
  4. 消除序号魔数：给 msp_adc_get() 增加枚举（如 ADC_SEQ_POT、ADC_SEQ_TEMP、ADC_SEQ_NTC），让 NTC_GET_ENCODE() 不再依赖裸数字 2。
  5. 修 3 个遗留：给 temp_table 加 static const；给 vol 加饱和保护；给 bsp_ntc_init() 加说明注释（或干脆删掉它并在头文件注明）。
  6. 做一次标定实验：把 NTC 放进冰水（0 ℃）和沸水（≈100 ℃，注意器件耐温）各测一次，记录串口值与真实温度的偏差，判断误差主要来自表还是来自 VREF。
