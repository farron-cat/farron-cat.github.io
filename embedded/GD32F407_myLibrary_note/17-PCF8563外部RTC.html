一、PCF8563 是什么 ​

一颗挂在 I2C 总线上的独立实时时钟芯片。MCU 通过 I2C 读写它的寄存器，就能设置/读取年月日时分秒，还能用它的闹钟和定时器。

        VDD ──┬── 主电源
              ├── 备电（纽扣电池/超级电容）   ← 主电源掉电后靠它继续走时
   MCU ───────┼── SCL  (PB6)
              ├── SDA  (PB7)
              └── INT ──→ PB5 ──→ EXTI5（闹钟/定时器到点时拉低）
              │
        ┌─────┴─────┐
        │  PCF8563  │  + 外接 32.768 kHz 晶振
        └───────────┘

特性说明
I2C 地址0x51（7 位）→ 写 0xA2、读 0xA3
时间格式BCD（和 MCU 内置 RTC 一样）
时间范围年 00~99（世纪位区分 19xx / 20xx）、月、日、星期、时、分、秒
中断输出INT 引脚（开漏、低有效），可被闹钟/定时器触发
特殊功能闹钟（Alarm）、定时器（Timer）、CLKOUT 输出、掉电检测
备电板上给了一路备电（第 20 篇的硬件文档里记作"外置 RTC PCF8563 + 备电"）

二、和 MCU 内置 RTC 的关系 ​

本工程已经有一个内部 RTC（Hardware/msp_rtc，第 11 篇），现在又用了一颗外部 RTC 芯片——这不是重复劳动，两种方案各有取舍。

MCU 内置 RTC（第 11 篇）PCF8563 外部芯片（本篇）
位置芯片内部（备份域）独立芯片
时钟源可选 HXTAL÷25 / LXTAL / IRC32K自带专用 32.768 kHz 晶振输入
掉电保持需要 VBAT 供电（板上有无电池决定成败）芯片自带备电引脚，用纽扣电池/超级电容即可
中断能力闹钟中断要绕到 EXTI_17（第 11 篇 7.3 节）有专用 INT 引脚，直接接任意 EXTI 线
额外功能亚秒、唤醒定时器闹钟、可编程定时器、CLKOUT 时钟输出、掉电检测
成本/占板面积0（内置）一颗芯片 + 晶振 + 备电
换 MCU 时要重新配驱动照搬（只要能接 I2C）

选型建议：

只要"系统知道现在几点"、且板上有 VBAT 电池        → 用内置 RTC（省器件）
要求"绝对时间准确、掉电必须走、还要定时中断"        → 用 PCF8563 这类独立 RTC
产品要换 MCU/换平台                              → 独立 RTC 的软件资产可复用

三、寄存器映射（本篇最需要背的东西） ​

PCF8563 一共 16 个寄存器（0x00 ~ 0x0F）：

地址名称位域说明
0x00控制寄存器 1TEST1 / STOP / TESTC / ...一般用默认值
0x01控制/状态寄存器 2TIE / AIE / TF / AF / TI_TP / ...中断使能与标志位（关键）
0x02秒VL sss ssssVL = 电压低标志（要掩掉）
0x03分x mmm mmmm掩 0x7F
0x04时xx hh hhhh掩 0x3F
0x05日xx DD DDDD掩 0x3F
0x06星期xxxx xwww掩 0x07（不是 BCD，就是 0~6）
0x07月C xxM MMMM掩 0x1F；C 是世纪位
0x08年xx YY YYYY掩 0x3F（BCD）
0x09闹钟-分AE mmm mmmmAE = 屏蔽位
0x0A闹钟-时AE hh hhhhh→AE hh hhhh同上
0x0B闹钟-日AE DD DDDD同上
0x0C闹钟-星期x xxxx www（bit7 也是屏蔽位）同上
0x0DCLKOUT 频率FE ffff...本工程未用
0x0E定时器控制TE pppp ccccTE 开关 + 时钟源选择
0x0F定时器计数值NNNN NNNN00~FF

3.1 为什么读时间必须"掩码" ​

因为一个字节里既有时间又有标志位：

秒寄存器 0x02： VL sss ssss
               │  └──┬────┘
               │     └── 秒的 BCD 值（0~59）
               └── 电压低标志（VL=1 表示备电电压过低，时间可能不准）

如果直接 BCD2DEC(整个字节) → 高位的 VL 会被当成十位数字 → 秒数错得离谱

4

所以代码里逐个字段都做了掩码：

c
void bsp_pcf8563_read_time(Time_pcf *t)
{
    uint8_t timeBuffer[7] = {0};

    msp_iic_read_nbyte(PCF8563_ADDR, 0x02, timeBuffer, 7);   // 一次读 7 个寄存器

    t->second  = BCD2DEC(timeBuffer[0] & 0x7F);  // VLsss ssss   → 掩掉 VL
    t->minutes = BCD2DEC(timeBuffer[1] & 0x7F);  // xmmm mmmm
    t->hour    = BCD2DEC(timeBuffer[2] & 0x3F);  // xxhh hhhh
    t->day     = BCD2DEC(timeBuffer[3] & 0x3F);  // xxDD DDDD
    t->week    = timeBuffer[4] & 0x07;           // xxxx xwww    → 星期不是 BCD！
    t->month   = BCD2DEC(timeBuffer[5] & 0x1F);  // CxxM MMMM    → 掩掉世纪位

    t->year    = BCD2DEC(timeBuffer[6]);         // xxYY YYYY

    if ((timeBuffer[5] >> 7) & 0x01)             // 单独取世纪位
        t->year += 2000;
    else
        t->year += 1900;
}

三个要点：

要点说明
msp_iic_read_nbyte(..., 0x02, buf, 7) 一次读 7 个因为 I2C 支持"地址自动递增"，读完秒会自动指向分——这比读 7 次（每次都要起始+地址+寄存器）高效得多
每个字段的掩码不同不能统一用一个 &0x7F，要按数据手册的位域逐个掩
星期不做 BCD 转换0x06 低 3 位是"0~6"的普通数字，不是 BCD。这是最容易搞混的一点

3.2 世纪位：百年后怎么办 ​

月寄存器 0x07 的 bit7 = C（Century）
    C = 1 → 20xx 年
    C = 0 → 19xx 年

所以 PCF8563 只能表达 1900~2099 这 200 年。
代码里读的时候补世纪，写的时候设置世纪位：

和第 11 篇内部 RTC 的对照：内部 RTC 是"year 两位 + 软件 +2000"，硬编码只支持 20xx；PCF8563 多了一个世纪位，能区分 19xx/20xx。两种方案都是"两位年 + 世纪信息"，只是世纪信息的存放位置不同。

3.3 写时间：一次写 7 个字节 ​

c
void bsp_pcf8563_set_time(Time_pcf *t)
{
    if (t->year < 1900 || t->year > 2099)
        return;                          // ← 范围校验（超出就静默返回）

    uint8_t timeBuffer[7] = {0};

    timeBuffer[0] = DEC2BCD(t->second);  // 秒
    timeBuffer[1] = DEC2BCD(t->minutes); // 分
    timeBuffer[2] = DEC2BCD(t->hour);    // 时
    timeBuffer[3] = DEC2BCD(t->day);     // 日
    timeBuffer[4] = t->week & 0x07;      // 周(0~6，非BCD)
    timeBuffer[5] = DEC2BCD(t->month);   // 月

    if (t->year > 1999)
        timeBuffer[5] |= (1 << 7);       // 世纪位

    timeBuffer[6] = DEC2BCD(t->year % 100);  // 年后两位

    msp_iic_write_nbyte(PCF8563_ADDR, 0x02, timeBuffer, 7);
}

读写是对称的（都按 0x02 起始、连续 7 个字节），只是方向不同：

读（read_time）写（set_time）
数据处理顺序先 & 掩码，再 BCD2DEC先 DEC2BCD，再 `
星期字段& 0x07& 0x07
世纪位从月寄存器 bit7 取出往月寄存器 bit7 写入

⚠️ 一个真实的边界问题：set_time() 里的范围校验失败时是 return 静默返回——调用方无法知道"设置没生效"。更好的做法是返回 uint8_t 错误码（像 I2C 那样有 IIC_STA 枚举）。这在调试时很关键："时间没设进去"和"设置成功了但读出来不对"是两条完全不同的排查路径。

四、闹钟与定时器 ​

4.1 闹钟：屏蔽位是关键 ​

PCF8563 的闹钟有 4 个寄存器（分、时、日、星期），每个寄存器的 bit7 是"屏蔽位（AE）"：

AE = 1 → 这个字段不参与比较（忽略）
AE = 0 → 这个字段参与比较
1
2

这和第 11 篇内部 RTC 的 alarm_mask 是同一个设计思想（那里是"mask 位 = 忽略该字段"）：

c
void bsp_pcf8563_set_alarm(Alarm *alarm)
{
    uint8_t timeBuffer[4] = {0};

    timeBuffer[0] = DEC2BCD(alarm->min & 0x7F);
    timeBuffer[1] = DEC2BCD(alarm->hour & 0x7F);

    // day：如果 bit7=1（屏蔽），原样保留；否则 BCD 转换
    if (alarm->day & 0x80)
        timeBuffer[2] = alarm->day;      // 屏蔽位原样透传
    else
        timeBuffer[2] = DEC2BCD(alarm->day);

    // week：保留 bit7，低 3 位有效
    if (alarm->week & 0x80)
        timeBuffer[3] = 0x80;
    else
        timeBuffer[3] = alarm->week & 0x07;

    msp_iic_write_nbyte(PCF8563_ADDR, 0x09, timeBuffer, 4);
}

但 PCF8563 的"日"和"星期"不能同时有效（硬件上按"日比较"或"星期比较"二选一，由控制寄存器 1 的 bit7 决定）。同时写 day 和 week 时，只有一个真正生效——这是"读手册才能发现"的细节。想做成"每周一 15:00 响"，必须去配那一位。

4.2 中断使能与标志：状态寄存器 0x01 ​

c
// 开启闹钟
void bsp_pcf8563_alarm_enable(void)
{
    msp_iic_read_nbyte(PCF8563_ADDR, 0x01, &sta_c2, 1);   // 先读回原值
    sta_c2 |= (1 << 1);   // AIE = 1，允许闹钟中断
    sta_c2 &= ~(1 << 3);  // AF  = 0，清标志
    msp_iic_write_nbyte(PCF8563_ADDR, 0x01, &sta_c2, 1);  // 再写回去
}

0x01 的四个关键位：

位名称含义
bit0TIE定时器中断使能
bit1AIE闹钟中断使能
bit2TF定时器标志（到点了硬件置 1，软件要清）
bit3AF闹钟标志（同上）

"读-改-写"这个模式很常见（和第 03 篇按键的位图、第 09 篇数码管缓冲区是一个思路）：只改我要改的那一位，其余位保持原样。

如果直接 write(0x01, 0x02) 会怎样？ 会把 TIE 和别的位一起清掉——这正是"读改写入必须用 |= / &=~ 而不是直接赋值"的经典案例。

4.3 定时器：一个可编程的周期中断 ​

c
// 配置定时器
// clock: 0x80=1Hz  0x81=64Hz  0x82=1/60Hz  0x83=1/3600Hz
void bsp_pcf8563_set_timer(uint8_t clock, uint8_t cnt)
{
    uint8_t timeBuffer[2] = {0};

    timeBuffer[0] = 0x80 | (clock & 0x7F); // 打开定时器 + 时钟频率
    timeBuffer[1] = cnt;                   // 计数值

    msp_iic_write_nbyte(PCF8563_ADDR, 0x0E, timeBuffer, 2);
}

0x82（0x81）1/60 Hz1 ~ 2551 ~ 255 分钟

上表括号里的值是按 PCF8563 数据手册的 0x0E bit[1:0] 编码（00=1/3600Hz、01=1/60Hz、10=64Hz、11=1Hz）推的。 ⚠️ 本工程代码注释里给的是 0x80=1Hz / 0x81=64Hz / 0x82=1/60Hz / 0x83=1/3600Hz——两种说法正好相反。 代码里 timeBuffer[0] = 0x80 | (clock & 0x7F) 把 clock 的低 2 位直接当编码用，所以实际频率取决于你传进去的低 2 位。 这正是"写驱动必须先核对数据手册"的活例子：注释是二手的、可能抄错，手册才是一手的。（对照方法见第 23 篇「怎么查手册」。）

改之前：on_rtc_int      →  "RTC 中断"（像是中断服务函数，其实是主循环调用的处理函数）
                        →  而 87da7e0 之后它已经"不在中断里"了，名字开始撒谎

改之后：on_rtc_interrupt →  "RTC 中断【事件】处理"（一个"处理某类事件"的普通函数）
                        →  身份诚实，和 on_touch_key_interrupt 同族

七、排查清单 ​

现象优先检查
读时间全是 0 或 0xFFI2C 没通（先看第 15 篇）；地址写错（0x51 要左移）；器件没供电
读出来是乱码 / 数值明显偏大忘了按位掩码（尤其秒的 VL 位、月的世纪位）
秒一直在 60 以上把 VL 位当成十位了（只掩 0x7F 不够？检查是否用 BCD2DEC(整个字节)）
星期显示成 8 以上星期位域是低 3 位（&0x07），且不是 BCD
年份变成 1900 多世纪位没读到/没写对（月寄存器 bit7）
时间设不进去set_time() 的范围校验失败静默 return（传了非法年月日）；或 I2C 写失败
时间不走字32.768 kHz 晶振没起振；或控制寄存器 1 的 STOP 位被置 1
闹钟不触发① AIE 没置 1 ② AF 标志没清（会一直"认为已触发"）③ 闹钟寄存器屏蔽位写错 ④ EXTI5 没配
闹钟触发了但不知道是哪个事件on_rtc_interrupt() 里要读 0x01 判 AF/TF（两个共用一个 INT 脚）
定时器不启动0x0E 的 bit7（TE）没置 1；或计数值为 0
定时器周期和预期差很多时钟源编码搞反了（代码注释与手册的说法相反，必须以手册为准，见第 23 篇）
中断进了但反复进AF/TF 标志没清；或 EXTI 标志没清
中断里卡住/系统复位中断里做 I2C + printf（阻塞几十 μs ~ 几 ms），可能撑爆看门狗窗口
每次闹钟触发后都报 IIC device not acknowledged!★ 软件 IIC 重入：中断里发起了 IIC，打断了主循环正在进行的软 IIC 时序（已由 87da7e0 修复，见 §5.5）
闹钟日志一次打两条读状态失败后仍用静态缓存旧值判断（应改成局部变量 + 检查返回值）
PCF8563 与 OLED 同时用 IIC 时互相干扰两者共用 PB6/PB7 与 msp_iic，没有总线互斥（改成"只在主循环访问"或加忙标志）
日/星期闹钟只有一个生效PCF8563 的"日比较"和"星期比较"是二选一（控制寄存器 1 有一位决定），不能同时用
编译报 Time 重定义msp_rtc.h 与 bsp_pcf8563.h 各有一个时间结构体，注意区分 Time / Time_pcf

九、练习题 ​

  1. 读手册修正编码：找到 PCF8563 数据手册的 0x0E 寄存器说明，确认四个时钟源的正确编码，修正 bsp_pcf8563_set_timer() 的注释（或代码）。
  2. 消抖无关的可靠性：给 on_rtc_interrupt() 改成"中断里只置标志、主循环处理"，避免在中断里做 I2C 与 printf。

    ✅ 已由 87da7e0 完成（§5.5）。可再对照真实改动，检查你自己写的版本有没有漏掉"读失败就返回"这一条。

  3. 做一次"每周一 15:00"闹钟：查手册找到"日/星期比较选择"那一位，配出每周一触发的闹钟并实测。
  4. 用上 bsp_pcf8563_read_byte()：它现在读的是秒寄存器（0x02），写个小测试每 100 ms 读一次，验证秒在递增（不依赖 OLED）。
  5. 加掉电检测：读秒寄存器时顺便检查 VL 位，如果为 1 就在 OLED 上显示"备电电压低"，提示更换纽扣电池。
  6. 统一时间结构体：把 Time 和 Time_pcf 合并成一个公共 rtc_time_t，放在共享头文件里，两个 RTC 驱动都改用它（注意 min/minutes、sec/second 的命名分歧）。
  7. 接上蜂鸣器（第 07 篇）：重定义 on_rtc_alarm()，让闹钟响一声（体会 __weak 回调的用法）。
  8. 关掉内部 RTC：把 msp_rtc_init(HXTAL) 注释掉，只留 PCF8563，观察系统是否正常（理解"两个 RTC 是否真的都需要"）。
