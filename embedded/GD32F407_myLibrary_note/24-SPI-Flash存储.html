学习目标 ​

  1. 说清「为什么 Flash 必须先擦后写」，以及「擦除的单位是扇区、写入的单位是页」这两件事带来什么后果。
  2. 能独立写出「读 ID → 写使能 → 等待忙 → 擦扇区 → 写页 → 读回校验」这套最小闭环。
  3. 看懂本工程 2 次提交分别解决了什么问题，特别是为什么第二次要把自带 SPI 初始化整段注释掉。
  4. 记住 SPI Flash 的耗时在物理擦写而不是总线速度，并算出它和看门狗/主循环调度的冲突。

一、为什么要外挂一颗存储器 ​

1.1 易失 vs 非易失 ​

分类断电后代表本工程角色
易失（RAM）数据丢失SRAM / SDRAM / DDRGD32F407 内部 192 KB SRAM，跑程序用
非易失（ROM/Flash）数据保留Flash / EEPROM存程序（内部 Flash）、存数据（本篇的片外 Flash）

GD32F407VET6 内部有 512 KB Flash（存程序）+ 192 KB SRAM，但都不适合存"运行中产生的数据"：

  • 内部 Flash 要"顺便"存程序，擦写它容易把自己正在执行的代码擦掉（而且擦写寿命只有约 1 万次）；
  • 需要存的是配置、日志、字库、图片这类断电也不能丢的数据。

所以就有了这颗片外 SPI Flash。

1.2 Flash 的家族关系（教材《存储器介绍》的骨架） ​

存储器
├─ 易失   RAM ── DRAM（SDRAM / DDR / DDR2 / DDR3）、SRAM
└─ 非易失 ROM ── MASK ROM、PROM/EPROM/OTPROM、EEPROM
            └─ FLASH ── NOR FLASH（≡本篇这颗）、NAND FLASH

EEPROMNOR FlashNAND Flash
擦除单位字节扇区/块块
能否按字节随机读能能（所以程序可以直接在 NOR 上跑）不能，按页读

一句话结论：要"按字节改一点小数据"选 EEPROM（内部的 PCF8563 里就有一小块，见第 17 篇）；要"大块存、顺序写"选 NOR Flash（本篇）。

二、GD25Q32 是什么 ​

2.1 容量与组织 ​

项目数值换算
标称容量32 Mbit= 4 MByte = 4096 KB
页 Page256 B4096 KB / 256 B = 16384 页
扇区 Sector4 KB4096 KB / 4 KB = 1024 个扇区
块 Block64 KB（也有 32 KB 的块）4096 KB / 64 KB = 64 个块
地址宽度24 位（3 字节）0x000000 ~ 0x3FFFFF

这三个"单位"是理解整个驱动的前提：

一次擦除最小 = 1 个扇区 = 4 KB（不能只擦 1 个字节！）
一次写入最大 = 1 页     = 256 B（超过就回卷到本页开头！）
一次读取无限制         = 给地址就一直读下去

⚠️ 代码里 bsp_flash_erase_sector() 的注释写着「addr=擦除的扇区号，范围=0~15」—— 0~15 这个范围是 64 KB 容量芯片（16 个扇区）才成立。GD25Q32 有 1024 个扇区（0~1023）， W25Q128 有 4096 个扇区。这条注释是从别处抄来的，直接忽略了容量差异（第八章第 6 条）。

2.2 引脚（8 脚 SOP-8） ​

引脚名称方向说明（教材原文）
1CS输入高电平时其它引脚高阻态；低电平时才能读写
2DO输出串行数据输出，时钟下降沿输出
3WP输入写保护，有效时禁止写（低有效）
4GND—地
5DI输入串行数据输入，时钟上升沿采样
6CLK输入时钟
7HOLD输入暂停保持（低有效），允许芯片暂停工作
8VCC—3.3 V

「DO 在下降沿输出、DI 在上升沿采样」→ 这就是 SPI Mode 0（CPOL=0 空闲低 + CPHA=0 前沿采样）的定义。 所以软件 SPI 的 msp_spi_read_write_byte()（SCL 低写、SCL 高读）天然就是对的； 硬件分支用的 SPI_CK_PL_HIGH_PH_2EDGE（Mode 3）也能用——W25Q/GD25Q 系列两种 Mode 都支持 （见第 16 篇第三章，以及第八章第 5 条里那个"两种 Mode 并存"的遗留）。

2.3 指令集（用到的 7 条） ​

指令码后面跟作用
Write Enable06h—置 WEL 位；每次擦/写之前都必须发一次
Read Status Reg05h→ 1 字节读状态寄存器，bit0 = WIP（忙）
Read Data03h3 字节地址 + 数据普通读，无频率上限直到几十 MHz
Page Program02h3 字节地址 + ≤256 B编程一页
Sector Erase20h3 字节地址擦除 4 KB 扇区（一个扇区只能整块擦）
Read Manufacturer / Device ID90h3 字节 0 + 读 2 字节本工程用的就是它，返回 制造商ID + 设备ID
Read Identification (JEDEC)9Fh读 3 字节官方例程用的是它，返回 制造商 + 存储类型 + 容量

一次性指令与地址型指令的区别：擦除/编程的 3 字节地址是"绝对字节地址"，而 bsp_flash_erase_sector() 收的却是"扇区号"，所以它内部要 addr *= 4096——这是本篇最容易看错的一处（见 §5.5）。

2.4 同族芯片速查 ​

型号容量扇区数(4KB)页数90h 设备 ID
GD25Q162 MB512819214h
GD25Q32（本篇）4 MB10241638415h
GD25Q648 MB20483276816h
GD25Q12816 MB40966553617h
W25Q128（教材用它举例）16 MB40966553617h（制造商 EFh）

制造商 ID：本工程这颗是 GigaDevice → C8h；教材举例的 W25Q 是 Winbond → EFh。 所以串口应该打印 ID = C815（制造商 C8 + 设备 15）。 具体数值以你手上芯片的手册 Read Manufacturer/Device ID 表为准——但判据很好用： 只要高位是 C8（或 EF），就说明 Flash 已经应答了；FFFF/0000 才是接线或时序问题。

对比项官方 gd25qxx.c本工程 bsp_flash.c
读 ID 指令9Fh（JEDEC，读 3 字节）90h（读 2 字节）
ID 返回24 位：制造商 + 类型 + 容量16 位：制造商 + 设备

两边都合法的差异不必统一（比如 9Fh vs 90h）；但性能与风格上的差异值得学：

  • 官方在 wait_for_write_end() 里只拉低一次 CS，然后连续读状态寄存器——一轮擦除期间几百次轮询都不重新发指令；
  • 本工程每轮都"CS 高 → CS 低 → 发 05h"（一个完整的读事务）——功能正确但每次多花 4 个字节的时钟。 对 45 ms 的擦除来说这点开销可忽略，但它是"懂得协议边界"和"照着抄"的区别。
  • 官方代码里那条 SPI_FLASH_BLOCK_SIZE = 0x8000（32 KB）说明块擦除不止 64 KB 一种， 教材只讲了 64 KB ——手册的 Block Erase 表里 32 KB/64 KB 两行都要看。

调用顺序有讲究：main.c 里 msp_spi_init() 在前、bsp_flash_init() 在后。 先让 SPI 把 PA5/PA6/PA7 配成 SPI 状态，再单独配 CS —— 两者互不干扰。

GPIO_PUPD_PULLUP 对输出脚其实没有上拉作用（内部上下拉只在输入模式生效）， 这里写它属于"照抄例程"；真正有意义的是上电瞬间 CS 不能是低—— 芯片规格要求 CS 在电源稳定前保持高，否则可能误进入某条指令。靠 gpio_bit_write(..., SET) 保证。

5.2 bsp_flash_read_id() —— 唯一的"自检"手段 ​

c
uint16_t bsp_flash_read_id(void)
{
    uint16_t temp = 0;
    W25QXX_CS_ON(0);                            // CS 低：开始事务
    spi_read_write_byte(0x90);                  // 指令：读制造商/设备 ID
    spi_read_write_byte(0x00);                  // 3 字节"假地址"（90h 要求）
    spi_read_write_byte(0x00);
    spi_read_write_byte(0x00);
    temp  = spi_read_write_byte(0xFF) << 8;     // 读制造商 ID（发什么无所谓）
    temp |= spi_read_write_byte(0xFF);          // 读设备 ID
    W25QXX_CS_ON(1);                            // CS 高：结束事务
    return temp;
}

三个细节：

  1. 0x90 后面必须跟 3 个地址字节（内容不重要，通常 0），少了就整个错位；
  2. 读的时候"发送"的 0xFF 只是时钟（dummy），从机不关心——SPI 是全双工，你不发就没有时钟；
  3. CS 拉高才结束这次读，否则芯片会一直往下吐数据。

这也是 SPI 与 I2C 的根本差别（第 22 篇）：I2C 从机每字节应答（ACK），SPI 没有任何应答。 所以 SPI 器件只能靠"读回 ID / 读状态寄存器"来证明它还活着——read_id() 就是这条"生命线"。

5.3 bsp_flash_write_enable() —— 09h 家族的通行证 ​

c
void bsp_flash_write_enable(void)
{
    W25QXX_CS_ON(0);
    spi_read_write_byte(0x06);   // WREN
    W25QXX_CS_ON(1);
}

规则：任何"会改变芯片内容"的指令（02h 编程、20h 擦除、01h 写状态寄存器）执行前， 都必须先发一次 06h，把状态寄存器的 WEL 位置 1。指令结束后 WEL 自动清零 —— 所以每写一次就要发一次，不能"发一次管一天"。

5.4 bsp_flash_wait_busy() —— 唯一的"同步"手段 ​

c
void bsp_flash_wait_busy(void)
{
    unsigned char byte = 0;
    do {
        W25QXX_CS_ON(0);
        spi_read_write_byte(0x05);          // RDSR：读状态寄存器
        byte = spi_read_write_byte(0xFF);   // bit0 = WIP（1 = 正在干活）
        W25QXX_CS_ON(1);
    } while ((byte & 0x01) == 1);
}

  • 为什么需要它：擦除/编程是芯片内部的高压操作，MCU 发完指令就可以走人，但芯片还在忙； 期间只接受 05h（读状态），别的指令一律不理。所以"发完就拉倒"必然失败。
  • 为什么它是"同步手段"：这是整篇代码里唯一一处被动等硬件的地方（while 轮询）， 也是所有耗时问题的根源（第七章会说它带来多少毫秒）。
  • 与官方实现的差别：官方在 CS 拉低的状态下连续读（只发 dummy），本工程每轮重发 05h。 两者都符合手册（CS 高电平结束读事务），但重发版把"事务"切碎了——功能对，效率低。

5.5 bsp_flash_erase_sector() —— 注意参数是"扇区号"！ ​

c
void bsp_flash_erase_sector(uint32_t addr)   // ← 参数名骗人：其实是扇区号
{
    addr *= 4096;                            // 换算成字节地址
    bsp_flash_write_enable();                // 06h
    bsp_flash_wait_busy();                   // 此时没有正在进行的操作，立即返回（冗余但无害）
    W25QXX_CS_ON(0);
    spi_read_write_byte(0x20);               // 20h：扇区擦除
    spi_read_write_byte((uint8_t)(addr >> 16));
    spi_read_write_byte((uint8_t)(addr >> 8));
    spi_read_write_byte((uint8_t)addr);      // 24 位地址，高→中→低
    W25QXX_CS_ON(1);                         // ★ CS 上升沿真正启动擦除
    bsp_flash_wait_busy();                   // 等擦完（几毫秒 ~ 几百毫秒）
}

三个必须记住的点：

  1. 参数是扇区号（bsp_flash_write 内部做 addr / 4096 才得到它）， 和其它函数的"字节地址"语义不一致——这是最容易读错的一个函数；
  2. bsp_flash_write_enable() 后面的那次 wait_busy() 是多余的（还没有开始任何操作）， 真正起作用的是 末尾那次 wait_busy()；
  3. CS 拉高的上升沿是"发令枪"：20h + 地址 只是把指令装进芯片，CS 一抬高才开始擦。 ——所有"写完没效果"的现场，十有八九是 CS 忘了拉高。

5.6 bsp_flash_write() —— 先擦后写 ​

c
void bsp_flash_write(uint8_t *buffer, uint32_t addr, uint16_t numbyte)
{
    bsp_flash_erase_sector(addr / 4096);   // ① 先把这块 4 KB 全擦成 0xFF
    bsp_flash_write_enable();              // ② 06h
    bsp_flash_wait_busy();                 // ③ 等擦除结束
    W25QXX_CS_ON(0);
    spi_read_write_byte(0x02);             // ④ 02h：页编程
    spi_read_write_byte((uint8_t)(addr >> 16));
    spi_read_write_byte((uint8_t)(addr >> 8));
    spi_read_write_byte((uint8_t)addr);
    for (i = 0; i < numbyte; i++)
        spi_read_write_byte(buffer[i]);    // ⑤ 连续写数据
    W25QXX_CS_ON(1);                       // ⑥ CS 上升沿启动编程
    bsp_flash_wait_busy();                 // ⑦ 等编完
}

为什么必须"先擦后写"：Flash 的存储单元只能把 1 写成 0，不能把 0 写回 1； 擦除是唯一能把 0 变回 1 的操作，而擦除的最小单位是 4 KB 扇区。 于是：改 1 个字节 = 擦掉 4 KB + 重写这 4 KB。

这条特性带来两个"课本不会讲、但一定会踩"的后果：

后果说明本工程的现状
① 覆盖写会误删邻居write("A", 0x0000) 再 write("B", 0x0010)，第二次会把扇区 0 擦掉，"A" 也没了⚠️ 代码就是这样：每次 write 都无脑擦整个扇区（第八章第 2 条）
② 跨页写会回卷一页只有 256 B；从 0x00F0 开始写 32 字节，后 16 字节会绕回 0x0000⚠️ 代码没有页边界检查（第八章第 4 条）

正确的工程做法是"读-改-写"或"日志式写入"（先把整个扇区读到 RAM，改一个字节，擦，再整块写回）。

5.7 bsp_flash_read() —— 唯一没有长度限制的操作 ​

c
void bsp_flash_read(uint8_t *buffer, uint32_t read_addr, uint16_t read_length)
{
    W25QXX_CS_ON(0);
    spi_read_write_byte(0x03);                     // 03h：读数据
    spi_read_write_byte((uint8_t)(read_addr >> 16));
    spi_read_write_byte((uint8_t)(read_addr >> 8));
    spi_read_write_byte((uint8_t)read_addr);
    for (i = 0; i < read_length; i++)
        buffer[i] = spi_read_write_byte(0xFF);     // 一直读，地址自动递增
    W25QXX_CS_ON(1);
}

读不需要写使能、不需要等忙、可以跨页跨扇区一路读到底（地址自动递增）。 唯一的限制是 read_length 是 uint16_t（最大 65535 字节）——想读更多要分段。

补充：03h 普通读有频率上限（GD25Q32 手册给 50 MHz 量级）， 更高频要用 0Bh（Fast Read，读之前要发 1 个 dummy 字节）或 6Bh（Quad）。本工程 21 MHz，用 03h 完全够。

七、时序是这里最大的坑 ​

7.1 三个数量级差 ​

操作手册标称（typ / max，需自行核对手册）本工程 SPI 21 MHz 下的"通信时间"
读 14 字节（ID 事务）无额外时间$14 \times 8 / 21\text{ MHz} \approx 5.3\ \mu s$
编程 256 B 页0.7 ms / 3 ms264 B ≈ 100 µs
擦除 4 KB 扇区45 ms / 400 ms4 字节 ≈ 1.5 µs
擦除 64 KB 块约 150 ms / 2 s同上
芯片全擦约 10 s 量级同上

结论：擦一个扇区 45 ms，而命令本身只花 1.5 µs —— 99.997% 的时间在等芯片内部的高压电路。

所以：

SPI Flash 的性能瓶颈从来不是总线速度，而是擦写的物理时间。 想"更快"，提高 SPI 时钟毫无用处，只能减少擦除次数（攒够一整扇区再写 / 用日志式追加写）。

7.3 谁在总线上等："轮到我才发" ​

同一时刻 CS 只能有一个是低的。本板的 SPI0 总线上挂着三个器件：

            PA5 (SCK) ──┬──── U4  SPI-OLED   (CS = PA3)
            PA7 (MOSI)──┼──── U10 LCD        (CS = ?)
                        └──── U?  GD25Q32     (CS = PA4)
            PA6 (MISO) ────── GD25Q32        (只有它会"回话")

2
3
4

推论：

  1. SCK/MOSI 是共享的，所以"任何时刻只能有一个 CS 有效"——OLED 刷新和 Flash 读写不能并发（裸机天然满足）；
  2. MISO 只有 Flash 用（OLED 侧那句 OLED_READ_FS0() 是注释掉的），所以 Flash 的"回话"不会被别人抢；
  3. PA4 在原理图上只连到 P3 排针（PA4 :: P3.5, U9.5），板上 BOM 里没有任何 Flash 器件—— 说明这颗 GD25Q32 是外接模块，通过排针接到 CS=PA4 上。 这一点很关键：代码能编译、能跑通 ID = C815 的前提是"模块插上了"， 没插就得到 FFFF（第八章第 1 条）。 （Doc/硬件信息汇总.md 的 5.4 节列了"硬件已具备但代码未实现"，本篇正好是反过来的情形：代码已实现，硬件靠外接。）

练习题 ​

  1. 修 3 个 bug：bsp_flash_write((uint8_t *)"hello", 0, 10) 的越界、erase_sector 的注释范围、msp_spi_hard_read_write_byte() 的 dat，各写一版修正并说明理由。
  2. 加"读-改-写"：写一个 bsp_flash_write_byte_keep(addr, byte)，保证只改目标字节、不破坏同扇区其它数据。
  3. 加页内分割：写一个能跨页安全写入的 bsp_flash_write_crosspage()，内部按 256 B 切分。
  4. 做一次耗时实测：用 SysTick 微秒计时（第 01 篇）量出"擦 1 个扇区""编程 256 B""读 4 KB"的真实耗时，和 §7.1 的手册值对照（这是理解"物理时间"最直接的一次实验）。
  5. 非阻塞化：把 bsp_flash_write() 改造成状态机（空闲 → 擦除中 → 编程中 → 完成），主循环里轮询 05h，期间继续喂狗并刷新 OLED（综合用到第 05、12、21 篇）。
  6. 移植 W25Q128：按 §2.4 改容量相关常数，并加一句"读 9Fh 校验容量码"的自检。
