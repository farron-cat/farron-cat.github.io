## 一、EC12D 是什么

**EC12D（常写作 EC11 / EC12）是一种"增量式旋转编码器"**：旋钮每转过一格，内部两个触点按**固定顺序**通断一次。
它长得像"可无限旋转的电位器"，但输出**不是模拟量，而是两路方波（A 相 / B 相）**。

| | 电位器（PC4，第 19 篇） | **旋转编码器（本篇）** |
| --- | --- | --- |
| 输出 | 一个模拟电压（ADC） | **两路数字方波（A / B）** |
| 能否无限旋转 | ❌（有机械止点） | ✅ |
| 是否需要 ADC | 需要 | **不需要**（普通 GPIO + EXTI） |
| 能测"转了多少" | 能（绝对值） | 能（**相对**增量，掉电不记得位置） |
| 附加功能 | — | 通常**带一个按键**（按下 = 第三根线） |

本工程用的是"**带按键**"的型号，所以一共 3 根信号线（+ 电源地）：

| 信号 | 本工程引脚 | 作用 | 中断 |
| --- | --- | --- | --- |
| **A** | **PD11** | 方波 A（判断"有没有转"） | **EXTI11，双边沿** |
| **B** | **PD13** | 方波 B（判断"往哪转"） | 无（只做输入读取） |
| **D（按键）** | **PD15** | 按下（低有效） | **EXTI15，下降沿** |

```c
// Driver/bsp_ec12d/bsp_ec12d.c 文件头注释
// A PD11 EXTI11
// B PD13
// D PD15 EXTI15
```

> ⚠️ **先在硬件文档里查一眼这三个脚**——这一步非常关键（第五章会看到后果）：
> `PD11 = LED4`、`PD13 = LED6`、`PD15 = LED8`（板上 8 颗 LED 中的 3 颗，`bsp_leds` 正在使用）。

## 二、★ 正交编码：两个方波怎么判方向

### 2.1 波形长什么样

A、B 两路方波**频率相同、相位差 90°（四分之一周期）**，这就是"正交"：

```
正转（顺时针）：
A  ──┐  ┌────┐  ┌────┐  ┌──
      └──┘    └──┘    └──┘
B  ────┐  ┌────┐  ┌────┐  ┌─        ← B 比 A 滞后 90°
       └──┘    └──┘    └──┘

反转（逆时针）：
A  ──┐  ┌────┐  ┌────┐  ┌──
      └──┘    └──┘    └──┘
B  ┐  ┌────┐  ┌────┐  ┌────         ← B 比 A 超前 90°
   └──┘    └──┘    └──┘
```

**关键观察**：**在 A 的每一个跳变沿上，B 的电平是不同的**——
- 正转时，A 的**下降沿**上 B 是**高**；
- 反转时，A 的**下降沿**上 B 是**低**。

于是判方向只需要：**"A 一动，就立刻看 B 是什么电平"**。

### 2.2 代码里的方向表

```c
FlagStatus cur_state_a = gpio_input_bit_get(GPIOD, GPIO_PIN_11);   // 读 A（判边沿）
...
if (cur_state_a == RESET)   // A 下降沿
{
    if (SET == GET_CUR_STATE_B)   // B 高电平
        on_ec12d_clockwise();     // 正转
    else
        on_ec12d_counter_clockwise(); // 反转
}
else                        // A 上升沿
{
    if (SET == GET_CUR_STATE_B)   // B 高电平
        on_ec12d_counter_clockwise(); // 反转  ← ★ 和上面相反
    else
        on_ec12d_clockwise();         // 正转
}
```

把它整理成表（**这张表要能自己推出来**）：

| A 的边沿 | B 的电平 | 结论 |
| --- | --- | --- |
| **下降沿** | B = 高 | **正转**（顺时针） |
| **下降沿** | B = 低 | 反转 |
| **上升沿** | B = 高 | 反转 |
| **上升沿** | B = 低 | **正转** |

> **注意"上升沿和下降沿的判断正好相反"** —— 这不是写错了，正是正交信号的必然结果：
> A、B 差 90°，所以 A 上升时的 B 电平必然与 A 下降时相反。
> **如果你只在一个边沿上判断（比如只在下降沿），也能定方向**，只是分辨率减半；
> 本工程两个边沿都判，**方向更可靠**（但也带来"一格报两次"的副作用，见第六章）。

### 2.3 为什么"只在 A 上开中断"就够了

| 方案 | 中断线 | 说明 |
| --- | --- | --- |
| **本工程** | **只 A 双边沿** | A 一来就读 B（B 只做普通输入）——**最省中断**，逻辑最简单 |
| 常见的"4 倍频" | A、B 都双边沿 | 分辨率 ×4，但每格报 4 次，要自己做倍频计数 |
| 硬件方案 | **定时器的编码器接口模式** | 硬件自动加减计数，**零中断、零错误**（第 21 篇 §"隐藏能力"里列过，本工程未用） |

**结论**：**"只 A 开中断 + 读 B"是最省事、最适合教学的写法**；
要"精确测速/大转数"就该上定时器的编码器接口（第 21 篇的"未用能力"之一）。

## 三、提交演进

### 3.1 `1772f82`（10-13 11:48）：先配中断

**先把两条 EXTI 线配出来**（改 `msp_exti.h` + `msp_exti.c`，+65 行），一次加了 5 个 `USE_EXTI*` 开关：

```c
#define USE_EXTI0  1 // 核心板按键 KEYC
#define USE_EXTI3  1 // 独立按键 KEY4
#define USE_EXTI5  1 // PCF8563
#define USE_EXTI11 1 // 旋转编码器引脚A
#define USE_EXTI15 1 // 旋转编码器引脚B   ← 注释写错了，实际是"引脚D（按键）"
```

| 线 | 引脚 | 上下拉 | 触发 | IRQ |
| --- | --- | --- | --- | --- |
| EXTI11 | PD11 | **PULLUP** | **`EXTI_TRIG_BOTH`（双边沿）** | `EXTI10_15_IRQn` |
| EXTI15 | PD15 | **PULLUP** | **`EXTI_TRIG_FALLING`（下降沿）** | `EXTI10_15_IRQn` |

**这一步和之前几篇的"EXTI 五步"完全同构**（第 06 篇）：
`开 GPIO 时钟 → 配输入+上下拉 → SYSCFG 选线 → 配触发沿 → NVIC + 使能`。

同时在 `msp_exti.c` 里加了 `EXTI10_15_IRQHandler()`（`EXTI11` 和 `EXTI15` **共用一个 IRQ 向量**，函数里分别判标志）：

```c
void EXTI10_15_IRQHandler()
{
#if USE_EXTI15
    if (exti_interrupt_flag_get(EXTI_15) == SET)
    {
        exti_interrupt_flag_clear(EXTI_15);
        on_ec12d_key_press();          // ← 按键（但没消抖！）
    }
#endif
#if USE_EXTI11
    if (exti_interrupt_flag_get(EXTI_11) == SET)
    {
        exti_interrupt_flag_clear(EXTI_11);
        on_ec12d_exti();               // ← 旋钮
    }
#endif
}
```

> **注意两件事**：
> ① **`GPIO_PIN_11` 和 `GPIO_PIN_15` 在同一个 IRQ 里**（芯片把 EXTI10~15 打包成一个向量）
> —— 所以一个 Handler 里必须**逐个判标志**，不能"进了中断就当 A 动了"。
> ② **按键（D）这条线没有消抖**（第 06 篇 KEY4 那套 30 ms + 电平去重在这里没做）。

### 3.2 `78c0dd1`（10-13 13:39）：封装 + 边沿判方向

**新建 `Driver/bsp_ec12d/`**（`.c` 82 + `.h` 16），把"判方向"的逻辑写进 `on_ec12d_exti()`，
`msp_exti.c` 里只留一行调用（**中断服务函数只负责"转发"**）。

**这次提交的一个附带影响**：`msp_exti.c` 顶部出现了

```c
#include "bsp_ec12d.h"     // ← Hardware 层 include 了 Driver 层
```

**这是分层方向的反转**——本工程自己的约定（`模板结构.txt` / `README.md`）是：

```
Hardware/  ← 片上外设驱动（msp_*）      硬件层
Driver/    ← 片外器件驱动（bsp_*）      驱动层
```

**片上层不该知道"片外接了什么器件"**。更干净的做法是：
`msp_exti` 定义一个 `__weak void on_exti11(void)`（或把 `on_ec12d_exti` 声明成弱符号），
由 `bsp_ec12d` 去覆盖——**和 `msp_rtc` 用 `Time` 结构体、`msp_uart` 用回调是同一个思路**（第 04/11 篇）。

## 四、代码逐段解读

### 4.1 初始化：只配了 B

```c
void bsp_ec12d_init()
{
    // 配置旋转编码器引脚B
    rcu_periph_clock_enable(RCU_GPIOD);
    gpio_mode_set(GPIOD, GPIO_MODE_INPUT, GPIO_PUPD_NONE, GPIO_PIN_13);
}
```

**为什么只配 B？** 因为 A（PD11）和 D（PD15）**在 `msp_exti_init()` 里已经配好了**（输入 + 上拉）——
**这个"分工"本身是合理的**（谁开中断谁配引脚）。

> ⚠️ **但这个前提在 `main.c` 的调用顺序下不成立**（`bsp_leds_config()` 夹在中间，会把 PD11/PD13/PD15 重新配成输出）——见第五章第 2 条。

**另一个细节**：B 配的是 `GPIO_PUPD_NONE`（**浮空**），而 A/D 配的是 `GPIO_PUPD_PULLUP`。
如果编码器的 B 相是**开集/开漏输出**（部分型号是），浮空输入就可能读到随机电平；
**建议统一成 `PULLUP`**（编码器内部触点是"通到 GND"，上拉才是正确的静态电平）。

### 4.2 中断处理：时间门 + 边沿判 + 方向表

```c
uint64_t   last_time    = 0;              // ← 全局（非 static，见 §5.3）
FlagStatus last_state_a = SET;            // ← 默认 A 空闲为高
#define GET_CUR_STATE_B gpio_input_bit_get(GPIOD, GPIO_PIN_13)

void on_ec12d_exti()
{
    // ① 旋钮消抖
    uint64_t cur_time = get_us_cnt();
    if (cur_time - last_time <= 30000)    // 30 ms 内不再响应
        return;
    last_time = cur_time;

    // ② 读 A 并判断"真的发生边沿了吗"
    FlagStatus cur_state_a = gpio_input_bit_get(GPIOD, GPIO_PIN_11);
    if (cur_state_a == last_state_a)      // 电平没变 → 不是真边沿（抖动）
        return;
    last_state_a = cur_state_a;

    // ③ 按"边沿 + B 电平"查方向表
    ...
}
```

**三个设计点**：

| 点 | 作用 |
| --- | --- |
| **① 30 ms 时间门** | 既去抖，又把"一格的两次边沿"合并成一次（§6.2） |
| **② `last_state_a` 电平去重** | 抖动能产生**同一个边沿的重复中断**（比如下降沿抖出多次下降沿），靠"和上次记的电平比"滤掉 |
| **③ 边沿 + B 电平** | 正交解码的正题 |

> **这个"两级过滤"是第 06 篇 EXTI 消抖套路的复用**（时间窗 + 电平去重），
> 只是把阈值从 KEY4 的 30 ms 沿用过来——**巧合地正好适合旋钮**（§6.2）。

### 4.3 回调（`__weak`）

```c
__weak void on_ec12d_clockwise()         { printf("clockwise\n"); }
__weak void on_ec12d_counter_clockwise() { printf("counter clockwise\n"); }
__weak void on_ec12d_key_press()         { printf("key press\n"); }
```

**问题**：**默认实现是 `printf`，而它们是在中断里被调用的**（详见 §5.4）。第 17 篇 §5.5 刚刚
把"中断里不许 printf / 不许做重活"写成了规矩，这里又违反了。

**正确的默认实现应该是**（照搬第 17 篇的修复思路）：

```c
// 方案 A：只置标志，主循环处理
volatile int8_t g_ec12d_delta = 0;      // +1 正转 / -1 反转
__weak void on_ec12d_clockwise(void)         { g_ec12d_delta++; }
__weak void on_ec12d_counter_clockwise(void) { g_ec12d_delta--; }
// 主循环：if (g_ec12d_delta) { printf(...); g_ec12d_delta = 0; }
```

## 五、⚠️ 三个问题

### 5.1 引脚冲突：PD11 / PD13 / PD15 = **LED4 / LED6 / LED8**

查 `Doc/硬件信息汇总.md`（PCB 网表为准）：

| 代码里 | MCU 引脚 | 板上网络 | 板上连到哪里 | 冲突 |
| --- | --- | --- | --- | --- |
| A | **PD11** | `LED4` | `R18` → **LED4 阴极**（低有效） | ★ **与 `bsp_leds` 冲突** |
| B | **PD13** | `LED6` | `R20` → **LED6 阴极** | ★ 同上 |
| D | **PD15** | `LED8` | `R22` → **LED8 阴极** | ★ 同上 |

**也就是说：这个旋转编码器是"外接模块"，插在排针上，而它占用的三个脚在本板上已经接了 LED4/LED6/LED8。**

**三个后果**（按严重程度）：

1. **软件层冲突（最严重）**：`bsp_leds_config()` 会把 PD8~PD15 **全部配成推挽输出**，
   而编码器需要 PD11/PD13/PD15 做**输入 + EXTI**（见 §5.2）。
2. **按下按键会"点亮/熄灭 LED8"**：按键把 PD15 短到 GND；而 LED8 支路就在同一个网络上
   （PD15 —R22→ LED8 —→ +5V 侧的公共阳极，见第 02 篇）。
   所以 **PD15 输出高时 LED8 会亮、按下按键时 LED8 灭**——用编码器按键会"顺带控制一颗 LED"。
3. **LED 与旋钮互相干扰**：转动/按下旋钮会改变 PD11/PD15 的电平 → **触发 LED 相关的逻辑**；
   反之驱动 LED 会**产生 EXTI 中断**（见 §5.2）。

> **正确做法**：把编码器的 A/B/D 换到板上**真正空闲**的引脚（如 `PB14`、`PE7`，或第 23 篇 §5.4 那种"硬件已具备但代码未实现"的脚），
> 或者**明确接受"LED4/6/8 与旋钮不能同时用"**（在本工程里，LED 是教学用的，可以先让路）。
> **不管选哪种，都要在笔记和代码注释里写清楚**——这正是第 20 篇"代码↔硬件核对"的意义。

### 5.2 ★ 初始化顺序把引脚模式覆盖了（最隐蔽）

看 `main.c` 的调用顺序（**这个顺序是关键**）：

```c
msp_exti_init();        // ① 把 PD11/PD15 配成"输入 + 上拉"，并打开 EXTI11/EXTI15
...
bsp_leds_config();      // ② ★ 把 PD8~PD15 全部配成"推挽输出"（含 PD11/PD13/PD15）
...
bsp_ec12d_init();       // ③ 只把 PD13 配回"输入"
```

**净结果**：

| 引脚 | ① 之后 | ② 之后 | ③ 之后（最终） | 期望 |
| --- | --- | --- | --- | --- |
| PD11（A） | 输入+上拉 | **输出推挽** | **输出推挽** ❌ | 输入 |
| PD13（B） | 未配（浮空） | **输出推挽** | **输入** ✅ | 输入 |
| PD15（D） | 输入+上拉 | **输出推挽** | **输出推挽** ❌ | 输入 |

**于是**：

1. **`gpio_input_bit_get(PD11)` 读到的是"输出数据寄存器驱动出来的电平"**，
   而不是编码器 A 相的电平 → **方向判断完全失效**（读到的是上次 LED 操作留下的值）。
2. **EXTI11 / EXTI15 仍然使能着**，而且触发条件挂在**一条被推挽驱动的线**上 →
   **每次 `bsp_leds_open()/close()` 翻转 PD11/PD15，都会触发一次 EXTI 中断** →
   可能凭空报出 `clockwise` / `key press`。
3. 更糟的是 **PD15 输出高 + 外部按键按下** → **推挽输出对地短路**（靠内部限流，不致命但会发热、压降）。

**通用规律**：

> **两个模块共用引脚时，"谁后初始化谁说了算"。**
> 而且**这种 bug 在编译期、链接期都不会报错**，只在运行时表现为"莫名其妙的逻辑"。
> 检查方法只有一个：**把所有会碰这个引脚的初始化列出来，按 main 里的顺序排一遍，看最终模式是什么。**

**修法（三选一）**：

```c
// ① 调整顺序：把 bsp_ec12d_init() 挪到 bsp_leds_config() 之后，并让它把 A/B/D 都配成输入
void bsp_ec12d_init(void)
{
    rcu_periph_clock_enable(RCU_GPIOD);
    gpio_mode_set(GPIOD, GPIO_MODE_INPUT, GPIO_PUPD_PULLUP,
                  GPIO_PIN_11 | GPIO_PIN_13 | GPIO_PIN_15);   // 三个都配
}

// ② 把 LED 的引脚范围缩小（PD8~PD10、PD12、PD14），避开编码器的三个脚
// ③ 换引脚（最干净，见 §5.1）
```

### 5.3 两个全局变量没有 `static`

```c
uint64_t   last_time    = 0;        // ← 应该是 static uint64_t
FlagStatus last_state_a = SET;      // ← 应该是 static FlagStatus
```

放在 `.c` 里但**不加 `static`** → 它们在**全局符号表**里可见，
任何文件只要写个同名 `extern` 就能改它们，链接时还可能和别人的同名符号撞车。
**"只在本文件用的东西就加 `static`"** 是 C 里最便宜的封装。

### 5.4 中断里直接 `printf`（违反刚立的规矩）

调用链：`EXTI10_15_IRQHandler()` → `on_ec12d_exti()` → `on_ec12d_clockwise()`（默认实现）→ **`printf`**。

`printf` 走的是 `msp_uart` 的**阻塞式发送**（第 04 篇），一个字节约 86.8 μs，
`"counter clockwise\n"` 共 18 字节 ≈ **1.6 ms** ——
**在一颗按键/旋钮动一下的中断里阻塞 1.6 ms**，会：

1. **拖住其它中断**（SysTick 的 1 ms 分支里还有 188 数码管 / ADKEY / 数码管扫描）；
2. **可能撞上看门狗窗口**（WWDGT 窗口 1.66 ms，第 12 篇）——**1.6 ms 正好顶在窗口上沿**；
3. **在中断里做 IIC 的老问题**（如果打印过程中别的代码也访问串口）。

> **这是第 17 篇 §5.5 那三条规矩的直接违例**（"中断里绝不发起软件 IIC/不 printf"）。
> 同一个工程、相隔 3 天，一次修好了、一次又犯——**说明"规矩"光写进笔记不够，还要写进代码评审清单**。

## 六、30 ms 消抖的双重作用

### 6.1 第一重：常规机械消抖

旋钮内部的**金属弹片**在转动时会产生**数毫秒的抖动**，和普通按键一样需要过滤。30 ms 绰绰有余。

### 6.2 第二重（更关键）：把"一格的两次边沿"合并成"一次"

本工程 EXTI11 是 **`EXTI_TRIG_BOTH`（双边沿）**，而**一个"格"（一个完整正交周期）在 A 上会产生 2 个边沿**
（一个上升、一个下降）：

```
一格（一个 detent）= A 的一个完整脉冲：

A  ─┐   ┌───────────┐   ┌──
    └───┘           └───┘
     ↑下降沿        ↑上升沿          ← 同一格里两次中断！

※ 两次中断算出的方向是相同的（因为正交关系，A 上升时的 B 电平与 A 下降时相反，
  而方向表对两个边沿的映射也相反 → 结论一致）
```

**如果不做处理**：转一格会**回调两次** `clockwise()`（"转一格跳两格"）。

**30 ms 时间门正好解决它**：转动一格时两个边沿相隔 = 半个 A 周期。
人手慢转时 A 周期约 10~30 ms（转速 ~30~100 格/秒 以下），半周期 5~15 ms **远小于 30 ms** →
**第二次边沿被时间门挡掉** → **一格一次回调** ✅。

> **这解释了"为什么是 30 ms 而不是 5 ms"**：5 ms 挡不住慢转时的第二个边沿（会双击计数），
> 30 ms 既能挡边沿、又能挡抖动。**这个参数同时满足两个约束，是个挺聪明的做法。**

### 6.3 代价：转速上限

| 约束 | 数 |
| --- | --- |
| 时间门 | **30 ms** |
| 最快回调频率 | $1/30\ \text{ms} \approx 33\ \text{次/秒}$ |
| 即最快识别 | **约 33 格/秒** |

**人手快转旋钮可以轻松超过 100 格/秒** → 超过的部分**会被直接丢弃**（表现为"转快了不跟手/漏格"）。

**要解决的话**（从易到难）：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| ① 只用一个边沿（推荐） | 把 `EXTI_TRIG_BOTH` 改成**只下降沿**，一格只产生 1 次中断 | **改一行**，且 30 ms 可以降到 5 ms（只做消抖） |
| ② 缩短时间门 + 软件方向累加 | 消抖降到 2~3 ms，用"边沿计数"自己除 2 | 要处理"两个边沿间隔"的不确定性 |
| ③ **定时器编码器接口模式** | 硬件自动加减计数，零中断 | **最优解**（第 21 篇列的"未用能力"之一） |

> **"只取下降沿"是最划算的改法**：`EXTI11_TRIG_TYPE` 从 `EXTI_TRIG_BOTH` 改成 `EXTI_TRIG_FALLING`，
> 再把 `on_ec12d_exti()` 里"上升沿那段"删掉，消抖时间也能从 30 ms 收到 5 ms。

## 七、最终代码速查

| 接口 | 作用 | 备注 |
| --- | --- | --- |
| `bsp_ec12d_init()` | 只把 **B(PD13)** 配成输入 | A/D 由 `msp_exti_init()` 配置 |
| `on_ec12d_exti()` | **由 EXTI11 中断调用**：消抖 + 判边沿 + 查方向表 | 定义在 `bsp_ec12d.c`，被 `msp_exti.c` 调用 |
| `on_ec12d_clockwise()` | 正转回调 | `__weak`，默认 `printf` ⚠️ |
| `on_ec12d_counter_clockwise()` | 反转回调 | 同上 |
| `on_ec12d_key_press()` | 按键回调（EXTI15） | 同上，且**无消抖** |

**关键常数**：消抖/时间门 **30 ms**、`EXTI11` 双边沿、`EXTI15` 下降沿、均 **内部上拉**、NVIC 优先级 `(2,2)`。

**时序链**：

```
转一格 → A 边沿（EXTI11） → EXTI10_15_IRQHandler → on_ec12d_exti()
      → 30ms 门 → last_state_a 去重 → 读 B → on_ec12d_clockwise()/counter()
按下   → D 下降沿（EXTI15） → 同一个 Handler → on_ec12d_key_press()   （无消抖）
```

### 练习题

1. **修引脚模式**：把 `bsp_ec12d_init()` 改成"同时把 PD11/PD13/PD15 配成输入+上拉"，放到 `bsp_leds_config()` 之后，验证旋钮与 LED 是否都能正常工作。
2. **改单边沿**：把 EXTI11 改成只下降沿，删掉 `on_ec12d_exti()` 里的上升沿分支，把时间门收到 5 ms，实测快转是否跟手。
3. **改成只置标志**：把三个回调改成"改全局计数/标志"，主循环里统一 `printf`，对比串口输出是否更稳定（**这就是第 17 篇 §5.5 的修复套路**）。
4. **加按键消抖**：给 `on_ec12d_key_press()` 那条 EXTI15 加上和第 06 篇 KEY4 一样的消抖（时间门 + 电平去重）。
5. **做成"音量旋钮"**：把正/反转回调接到第 07 篇的蜂鸣器 `bsp_buzzer_play(freq)`，做一个"旋钮调音调"的完整例子（含范围限制与步进）。
6. **对比实验**：查手册配一次**定时器编码器接口模式**（TIMER2 或 TIMER3），把旋钮计数交给硬件，比较与"中断+软件判方向"两种方案在快转时的丢格情况。
