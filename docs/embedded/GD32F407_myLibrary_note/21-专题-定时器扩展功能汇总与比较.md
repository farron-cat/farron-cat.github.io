## 一、先看"定时器"到底是什么

**一句话**：定时器 = **一个会自动数数的计数器**（第 07 篇）。

但从"数数"这一个动作出发，可以扩展出一整类功能——

```
                      ┌─→ 数到某个数就中断一下 ──────────→ 【定时中断】时间基准
                      │
                      ├─→ 数到某个数就翻转引脚 ──────────→ 【方波 / 软 PWM】声音、亮度
                      │
一块定时器（计数器）──┼─→ 数数与比较值比大小，硬件自己输出 ─→ 【硬件 PWM】亮度、转速、音量
                      │
                      ├─→ 数到 0 就复位系统 ─────────────→ 【看门狗】可靠性
                      │
                      ├─→ 数满 1 秒就进位成年月日时分秒 ──→ 【RTC】日历时钟
                      │
                      └─→ 记录外部信号跳变时的计数值 ────→ 【输入捕获】测频率/占空比 ★本工程未用
```

> **注**：#3 和 #4 是"同一块定时器做两件事"（都是 TIMER5 中断 + GPIO），差别在**翻转频率的意图**不同（一个为调亮度，一个为发声）。
> **#15 是"同一个 SysTick 做三件事"**：它原本只负责"1 μs 时间基准"（#1），
> 从 `c630553` 起在同一个 `SysTick_Handler()` 里数到 1000（1 ms）后依次调用三个扫描：
>
> ```c
> void SysTick_Handler(void)
> {
>     static uint16_t div = 0;
>     delay_decrement();                 // ① 1 μs 时基（第 01 篇）
>     if (++div >= 1000)                 // 1 ms
>     {
>         div = 0;
>         bsp_188_leds_scan();           // ② 188 数码管（第 26 篇）
>         bsp_adkey_scan();              // ③ AD 按键（第 28 篇）
>         bsp_digital_leds_scan();       // ④ 74HC595 数码管（第 09 篇）
>     }
> }
> ```
>
> **"定时器兼职"很省资源（不用多配三个定时器），但代价要看清**：
>
> | 代价 | 说明 |
> | --- | --- |
> | `delay_1us()` 的时基被推迟 | 三个扫描加起来几微秒~十几微秒，**每毫秒一次** → 时基有周期性抖动 |
> | SysTick 优先级最高（异常号 -1） | 它**抢占所有外设中断**；Handler 越长，别人被推迟得越久 |
> | 与 WS2812 位流冲突 | 第 30 篇必须用 `__disable_irq()` 包住 119 µs 的数据段，**正是因为 1 ms 分支里的这几个扫描会拉长位宽** |
>
> **判据**：Handler 里**只能放"几微秒级"的 GPIO/数组操作**；一旦要 `printf`、IIC、Flash 擦写，就必须挪出去（第 17/24/30 篇各有一个例子）。

### 2.1 从这张表能提炼出的 6 类功能

| 类别 | 本质 | 本工程例子 | 关键寄存器 | 典型用途 |
| --- | --- | --- | --- | --- |
| **A. 定时中断** | 到点喊一声 | SysTick(1μs)、TIMER5(1s) | PSC + ARR | 时间基准、周期任务、消抖计时 |
| **B. PWM 波形** | 硬件按比例输出高低 | TIMER1/3/9 的 PWM 输出 | **PSC + ARR + CCR** | 亮度、转速、功率 |
| **C. 方波/音调** | 固定占空比、变频率 | 蜂鸣器 PB9 | ARR（改频率） | 发声、时钟输出 |
| **D. 互补输出** | 一对反相信号 | TIMER0 P/N（PE8/PE9） | `outputnstate` + 死区 | H 桥/半桥驱动 |
| **E. 计数/复位** | 数到 0 触发复位 | FWDGT、WWDGT | PSC + RLD/窗口 | 可靠性兜底 |
| **F. 日历** | 计数 1 秒 + 日历进位 | 内置 RTC、PCF8563 | 两级预分频 | 绝对时间、闹钟 |
| **G. 输入捕获** ★ | 记录外部跳变的时刻 | **未用** | CCR（捕获值） | 测频率/占空比/编码器 |

### 2.2 五条比较维度（选型时按这五条比）

| 维度 | 为什么重要 | 举例说明 |
| --- | --- | --- |
| **① 计数时钟源** | 决定"能不能在异常时还工作" | FWDGT 用 **IRC32K**（主时钟挂了它照样跑）；WWDGT 用 **PCLK1**（主时钟挂了它也挂） |
| **② 计数器位数** | 决定"最长能数多久" | SysTick 24 位（最长 99.9 ms）、TIMER 16 位、FWDGT 12 位、WWDGT **7 位** |
| **③ 有没有输出通道** | 决定"能不能产生波形" | **基本定时器（TIMER5/6）没有通道** → 只能中断，做不了硬件 PWM |
| **④ 中断能力** | 决定"软件能不能知道到了" | 都有中断，但**看门狗的中断不影响复位**（复位才是目的） |
| **⑤ 精度** | 决定"时间可不可信" | 晶振 vs RC：IRC32K 有 ±1%~5% 偏差（第 13 篇 7.1 节） |

## 三、同一个功能的多种实现（软 vs 硬）

**这是本工程最值得回味的一条线**：**同一个需求，往往有"软件模拟"和"硬件外设"两种做法**，而作者在几次提交里**把三种做法都试了一遍**。

### 3.1 对照一：产生方波（让蜂鸣器响）

| 做法 | 实现 | 优点 | 缺点 | 出处 |
| --- | --- | --- | --- | --- |
| **A. 定时器中断 + `gpio_bit_toggle`** | TIMER5 每 1 ms 中断一次，翻转 PB9 | 简单直观，一根普通 GPIO 就能发声 | **占 CPU**、抖动大、**改频率要重配定时器**、只能一个固定频率 | `698a2c6`（第 07 篇） |
| **B. 硬件 PWM** | TIMER1_CH1 输出 PWM，ARR 决定频率 | **零 CPU**、精确、**改频率只改 ARR** | 需要引脚支持定时器复用（AF） | `b4f56b7`（第 07 篇） |

**为什么最终选了 B？** 因为蜂鸣器要**播放音乐**——需要不断变频。做法 A 每换一个音都要"改中断周期"，而且中断里还有 `printf`；做法 B 只要 `bsp_buzzer_play(hz)` 改一个寄存器。

> **判断准则**：**"需要变频/精度要求高/数据流大" → 用硬件外设**；"一次性验证、极低频、引脚不支持复用" → 软件模拟也能应急。

### 3.2 对照二：定时 1 秒

| 做法 | 实现 | 精度 | CPU 占用 | 适合 |
| --- | --- | --- | --- | --- |
| **A. SysTick 中断 + 软件计数** | `delay` 变量减到 0（第 01 篇） | 高（1 μs 节拍） | 中断每秒 100 万次 | 通用延时（阻塞） |
| **B. SysTick 时间戳差值** | `get_us_cnt()` 差值判断 | 高 | 同上，但**不阻塞** | **非阻塞周期任务（推荐）** |
| **C. TIMER5 定时中断 1 s** | PSC=16800-1/ARR=10000-1 | 高 | 每秒 1 次中断 | 独立周期任务 |
| **D. RTC 秒中断** | 内置 RTC 的 1 Hz | 取决于时钟源 | 每秒 1 次 | 需要绝对时间时 |

**本工程实际用得最多的是 B**（第 05/09/12/20 篇的主循环都是"时间戳差值"）——**因为它不依赖主循环周期、也不阻塞**。

> **回顾这条演进线**：第 01 篇只会 `delay_1ms()`（阻塞）→ 第 05 篇用"20 ms × 25"凑 500 ms（依赖循环周期）→ 第 09 篇改用 `get_us_cnt()` 差值（不依赖周期）→ 第 20 篇正式定型。**这就是"裸机定时"的三级进化。**

### 3.3 对照三：调亮度（PWM 的软硬实现）

| 做法 | 实现 | 一处典型代价 | 出处 |
| --- | --- | --- | --- |
| **软 PWM** | TIMER5 中断里按 `cnt%5` 决定 GPIO 高低 | 中断频率 = PWM 周期的 5 倍，**CPU 被吃光** | `a2eeece` |
| **硬 PWM** | TIMER1/3 的通道输出，硬件比较 CNT 与 CCR | 换引脚要整套核对（AF + 通道） | `1f76f67` |

**算一下差距**：软 PWM 的中断是 200 μs 一次（5 kHz），硬 PWM 的 CPU 占用是 **0**。

> **这是全工程最典型的一组对照**：**同一块板、同一个目标（调亮度），两种实现的 CPU 代价差了"5 kHz 的中断"这个量级。**

### 3.4 三条通用判断准则

| 需求特征 | 选谁 |
| --- | --- |
| **需要"精确、连续、长时间、多路"** | **硬件外设**（PWM/捕获/看门狗/RTC） |
| **只是"验证一下、极低频、引脚不支持复用"** | 软件模拟也可（GPIO 翻转） |
| **只要"到点了通知我一下"** | 定时中断 + 软件状态机（**别在中断里干活**） |

**第 06 篇的那句话在这里同样适用**：**"中断里只做最少的、最快的事"**——**软 PWM 之所以被淘汰，一半原因是中断太频繁，另一半是中断里还加了 `printf`。**

## 四、定时器的"隐藏能力"（本工程还没用的）

**这块板子上的定时器还有几张牌没打**——列出来是为了让"能力谱系"完整：

| 能力 | 说明 | 典型用途 | 本工程状态 |
| --- | --- | --- | --- |
| **输入捕获** | 记录外部信号跳变瞬间的计数值，能算出**频率、周期、占空比** | 测外部脉冲频率、红外遥控解码、超声测距 | ❌ 未用 |
| **编码器接口模式** | 硬件解正交编码器的 A/B 相 | 电机测速、旋钮 | ❌ 未用 |
| **PWM 输入模式** | 测 PWM 的高电平时间和周期 | 读舵机信号、读传感器 | ❌ 未用 |
| **死区时间（dead time）** | 互补输出的两路之间插入一段"都关断"的时间 | **H 桥/半桥驱动**（防上下管直通短路） | ⚠️ 用了 P/N 互补，**没配死区** |
| **单脉冲模式** | 触发一次只输出一个脉冲 | 精确脉冲发生器 | ❌ 未用 |
| **从模式（Slave mode）** | 被外部信号触发/门控/复位计数 | 门控测频、外部事件计数 | ❌ 未用 |
| **定时器级联** | 一个定时器的溢出去驱动另一个 | 扩展计数长度（16 位 → 32 位） | ❌ 未用 |
| **重复计数器（高级定时器）** | 每 N 次溢出才产生一次中断/更新 | 降低中断频率 | ❌ 未用 |

**其中最值得补的两个**：

| 能力 | 为什么值得补 |
| --- | --- |
| **输入捕获** | 它是"定时器"这条线上唯一还没接触的大类——**PWM 是"输出"、捕获是"输入"**。学会它就补齐了定时器的双向能力 |
| **死区时间** | 本工程已经做了 P/N 互补输出，但**没配死区**——**如果真接 H 桥，没死区会直通短路烧管子**。这是"知道有这个概念"和"敢用"之间的差距 |

> **一个判断题**：**你的项目里"定时器只用来做定时和 PWM"——那大概率有优化空间。** 输入捕获能让很多"软件轮询测频率"的活儿变成硬件自动完成。

## 五、按"计数时钟源"再看一次（决定可靠性）

**同样是定时器，时钟源不同，故障时的表现完全不同**：

| 时钟源 | 谁在用 | 主时钟失效时 | 精度 |
| --- | --- | --- | --- |
| **内核时钟（CK_AHB 168 MHz）** | SysTick | ❌ 停 | 高 |
| **定时器时钟（CK_TIMER 168 MHz）** | TIMER0~13 | ❌ 停 | 高 |
| **PCLK1（42 MHz）** | **WWDGT** | ❌ 停 | 高（但依赖主时钟） |
| **IRC32K（32 kHz，独立 RC）** | **FWDGT**、RTC 可选 | **✅ 继续工作** | 低（±1%~5%） |
| **RTCCLK（外部 32.768 kHz 晶振）** | RTC / PCF8563 | ✅（备份域 + 备电） | **最高** |

**这张表解释了看门狗为什么要分两个**：

```
FWDGT 用独立时钟 → 就算系统时钟坏了、PLL 失锁了，它照样能"咬人"  → 适合"整机兜底"
WWDGT 用 PCLK1   → 它本身就是"系统时钟的监督者"，时钟异常时它也会挂 → 适合"抓程序跑飞"
```

> 详细对比见第 12 篇第二章；本专题只强调一点：**"时钟源"是看门狗选型的决定性因素**，而不是"哪个功能多"。

## 六、选型决策树（实用）

拿到需求，按这棵树走：

```
需求是"多久之后提醒我一下"（周期任务）
 ├─ 需要绝对时间（年月日时）？
 │   ├─ 是 → 【RTC】/【PCF8563】的秒/闹钟        （第 11 / 17 篇）
 │   └─ 否 → 需要独立于主循环的节拍？
 │           ├─ 是 → 【SysTick 时间戳】get_us_cnt() 差值（最推荐）
 │           └─ 否 → 【TIMERx 定时中断】
 │
需求是"产生一个可调波形"
 ├─ 要调"亮度/转速/功率"（占空比变）→ 【硬件 PWM + CCR】    （第 07 篇）
 ├─ 要调"音调/频率"（频率变）      → 【硬件 PWM + ARR】    （蜂鸣器）
 ├─ 要一对反相信号驱动桥式电路     → 【高级定时器 P/N + 死区】（第 07 篇 #9）
 └─ 只是验证、引脚不支持复用        → 软 PWM（中断 + GPIO）  ⚠️ 注意 CPU 代价
 │
需求是"测量外部信号"
 └─ 测频率/周期/占空比 → 【输入捕获】（本工程未实现，值得补）
 │
需求是"设备别死机"
 ├─ 要"就算时钟坏了也能复位" → 【FWDGT】（独立时钟）        （第 12 篇）
 ├─ 要"抓程序跑飞/时序错乱"  → 【WWDGT】（窗口）            （第 12 篇）
 └─ 要"让外设自动搬数据"    → 不是定时器，是【DMA】         （第 08 / 19 篇）
```

**最后一行很重要**：**"让 CPU 少干活"这件事，定时器只能做到"到点叫我"，真正的"批量搬运"要靠 DMA。** 两者是配合关系——**ADC + 定时器触发 + DMA** 是工业上最常见的组合（本工程只做了 ADC + DMA，触发用的是软件触发，第 19 篇）。

> **想更进一步**：把 ADC 的触发源从"软件触发"改成"定时器触发"（TIMER 的 TRGO 事件），就能得到**严格等间隔的采样**——这是"定时器 + ADC + DMA"三件套的完整形态，也是本工程可以继续做的一个练习。

## 七、一张"能力 × 代价"总表

最后用两个维度把所有方案摆在一张图上：

| 方案 | CPU 代价 | 精度 | 灵活性 | 适合 |
| --- | --- | --- | --- | --- |
| 软件延时 `delay_1ms()` | **高（空转阻塞）** | 中 | 低 | 只在初始化阶段用 |
| 定时器中断 + 软件状态机 | 中（中断开销） | 高 | **高** | 周期任务、状态推进 |
| 时间戳差值（`get_us_cnt()`） | **低** | 高 | **高** | **裸机周期任务首选** |
| 硬件 PWM | **≈0** | **最高** | 中 | 波形输出 |
| 硬件捕获 | ≈0 | 最高 | 低 | 测外部信号 |
| 看门狗（FWDGT/WWDGT） | ≈0 | — | 低 | 可靠性兜底 |
| RTC（内置/PCF8563） | ≈0 | 高（晶振） | 低 | 绝对时间 |
| DMA + 外设 | ≈0（搬运） | 高 | 中 | 数据流（串口/ADC） |

**读这张表的三个结论**：

1. **"软件延时"是唯一 CPU 代价高、灵活性又差的方案**——**只在初始化时用**（本工程所有 `delay_1ms` 都只在 init 阶段或调试代码里）。
2. **"时间戳差值"是裸机周期任务的最优解**——CPU 代价低、精度高、灵活（不依赖主循环周期）。
3. **CPU 代价 ≈ 0 的方案（PWM/捕获/看门狗/RTC/DMA）都是"外设自己会干活"**——**这就是嵌入式设计的核心思想：让硬件干活，CPU 只做决策**。

## 九、练习题

1. **补一个"输入捕获"**：用 TIMER 的输入捕获测一个外部方波的频率（可用另一个定时器的 PWM 输出接到捕获引脚，自己发自己收）。
2. **加死区**：给第 07 篇的 TIMER0 P/N 互补输出加上死区时间（`timer_break_config` / `timer_channel_output_deadtime_config`），并用示波器观察两路之间的间隙。
3. **定时器触发 ADC**：把第 19 篇的 ADC 软件触发改成"定时器 TRGO 触发"，得到严格等间隔采样；再配合 DMA，做成一个"定时采样 + 后台搬运"的完整链路。
4. **三法对比实验**：用三种方式实现"500 Hz 方波"（中断 toggle / 软件 PWM / 硬件 PWM），用逻辑分析仪对比**抖动**和**主循环卡顿**程度。
5. **把马达 bug 修掉**（第 20 篇）：改对定时器号后实测马达振动，再把 `bsp_vibration_motor` 改成"参数化定时器"的写法（参照第 04 篇句柄化），避免同类错误。
6. **给蜂鸣器加"节拍器"**：用 TIMER 定时中断（而不是第 07 篇的 `wait_us` 阻塞等待）驱动《小星星》播放，让主循环完全不被阻塞（这是第 07 篇遗留练习题的状态机版）。
7. **画一张自己的选型表**：把本章第二章的总表按你的理解重排一次（比如按"时钟源"排序），看看是否会有新的发现。
