## 一、先破一个误解：不是"一本手册"就够了

新手常以为"看手册"就是看一本书。实际上嵌入式开发至少要跟**六类资料**打交道，**它们的权威性和用途完全不同**：

| # | 资料 | 回答什么问题 | 权威性 | 本工程在哪 |
| --- | --- | --- | --- | --- |
| 1 | **数据手册**（Datasheet） | **这个芯片的电参数、引脚、极限值、特性公式** | 厂家一手 | `NOTE/Doc/GD32F407/GD32F407xx_Datasheet_Rev2.7.pdf` |
| 2 | **用户手册**（User Manual） | **每个外设怎么工作、寄存器每一位什么意思、有哪些图和表** | 厂家一手 | `NOTE/Doc/GD32F407/GD32F4xx_User_Manual_Rev3.0_CN.pdf` |
| 3 | **固件库源码与头文件** | **这个库函数怎么实现、"官方推荐怎么配"** | **最贴近你写的代码** | `Firmware/GD32F4xx_standard_peripheral/` |
| 4 | **启动文件** | **中断函数到底该叫什么名字** | 工程一手 | `Firmware/CMSIS/GD/GD32F4xx/Source/ARM/startup_gd32f407_427.s` |
| 5 | **原理图 / PCB 网表** | **板子上到底怎么接的**（哪个脚被谁占了） | **硬件唯一真相** | `NOTE/Doc/board/*.pdf`、`Doc/硬件信息汇总.md` |
| 6 | **教材 / 参考笔记** | **入门、梳理、经验**（有观点、可能过时） | 二手，便于上手 | `NOTE/Note/`、`NOTE/Textbook/` |

**一句话记住各自的位置**：

```
数据手册 = 芯片的"体检报告"（能跑多快、多热、多少伏）
用户手册 = 芯片的"使用说明书"（每个部件怎么用、怎么配寄存器）
库源码   = "别人写好的代码"（最直接能抄，注释常有金句）
启动文件 = "名字的出处"（中断函数名写死在这里）
原理图   = "板子的真相"（代码写得再对，脚接错了也没用）
教材     = "导航"（帮你快速知道该查哪张表，但要用前五类核对）
```

## 二、按"问题类型"选资料（最实用的一张表）

**拿到一个疑问，先判断它属于哪一类**，然后直奔对应的资料：

| 问题类型 | 典型问法 | **该查哪本** | 具体查什么章节/表 |
| --- | --- | --- | --- |
| **A. 引脚 / 复用** | 「PA2 能不能做 TIMER1 的 PWM？」「PB6 还能做别的不？」 | **用户手册 + 数据手册** | 用户手册「引脚复用表 / AF 表」；数据手册「引脚定义表」 |
| **B. 寄存器 / 位域** | 「TIMERSEL 这个位选什么？」「I2C 的 ACKPOS 在哪一位？」 | **用户手册** | 对应外设章节的「寄存器映射表」 |
| **C. 电气 / 参数** | 「ADC 时钟最高多少？」「内部上拉多大电阻？」「IO 最大灌电流多少？」 | **数据手册** | 「电气特性」章节（DC characteristics） |
| **D. 时序** | 「I2C 的起始条件是什么波形？」「SPI 该用哪个边沿采样？」 | **用户手册（时序图） + 数据手册（时序参数）** | 用户手册外设章节的「时序图」；数据手册的「AC 特性表」 |
| **E. 公式 / 换算** | 「ADC 值怎么换成温度？」「波特率怎么算？」 | **数据手册（公式与典型值） + 库源码（实现）** | 数据手册「特性说明」；库源码里同名函数 |
| **F. 中断** | 「中断函数该叫什么名字？」「中断号是多少？」 | **启动文件 + 用户手册** | `.s` 文件的中断向量表；用户手册中断表 |
| **G. 板级连接** | 「这个脚被谁占了？」「按键接上拉还是下拉？」 | **原理图 / PCB 网表** | 网表、`Doc/硬件信息汇总.md` |
| **H. 工程配置** | 「系统时钟是多少？」「选了哪套时钟配置？」 | **工程源码（CMSIS）** | `system_gd32f4xx.c` 的宏开关 |

> **判断技巧**：**问"能不能/在哪"→ A/G；问"怎么配"→ B；问"多少"→ C；问"什么时候"→ D；问"等于"→ E；问"叫什么"→ F。**

## 三、用户手册里要的"图和表"

用户手册的价值集中在**五类图表**上——**找手册的本质就是找这五类东西**：

| 类型 | 长什么样 | 用来回答 | 本工程实例 |
| --- | --- | --- | --- |
| **① 功能框图** | 外设内部的方块图（含分频器、寄存器、比较器、引脚） | "这个外设内部是怎么工作的" | 定时器框图 → 理解 PSC/CNT/ARR/CCR 的关系（第 07 篇） |
| **② 时钟树图** | 从晶振到各总线的树状图 | "这个外设的时钟从哪来、多少 Hz" | 定时器倍频、APB1/APB2 分频（第 14 篇） |
| **③ 寄存器映射表** | 每个寄存器每个位的名称/读写/复位值 | "某一位该写几" | `RCU_CFG1` 的 TIMERSEL 位（第 14 篇） |
| **④ 中断向量表** | 中断号 ↔ 中断源 ↔ 函数名 | "中断函数叫什么、几个中断源共用" | TIMER5 与 DAC 共用 → `TIMER5_DAC_IRQHandler`（第 07 篇） |
| **⑤ 时序图** | 信号随时间的波形图 | "什么时候采样/什么时候可以变" | I2C 起始/停止条件、SPI 的 CPOL/CPHA（第 15/16 篇） |

**还有一个"表"极其实用**：

| 类型 | 用来回答 | 本工程实例 |
| --- | --- | --- |
| **复用功能表（AF 表）** | 「这个引脚能做哪些外设、用哪个 AF 编号」 | PA2 = TIMER1_CH2 / AF1；PB9 = TIMER1_CH1 / AF1；PE8/PE9 = TIMER0_CH0 的 N/P / AF1 |

**"复用功能表"是查得最多的一张表**——第 07 篇踩的坑（`ef6a015` 把 PB9 配成 AF2）本质上就是**没查这张表**。

**怎么快速定位这五类图表**：

```
① 先看目录：找到外设章节（如 "16 定时器"）
② 章节内通常有固定顺序：概览 → 功能框图 → 工作模式 → 寄存器 → （时序）
③ 直接搜表号：中文手册的表号形如"表 16-1"，英文是 "Table 16-1"
④ 搜关键词：把"图"换成"Figure"、"表"换成"Table"再搜一遍（有些中文手册保留了英文图表号）
```

## 四、数据手册里要的"数据和公式"

数据手册（Datasheet）的章节结构也很固定，**你要的东西基本集中在这几处**：

| 章节 | 长什么样 | 用来回答 | 本工程实例 |
| --- | --- | --- | --- |
| **引脚定义/描述** | 每种封装的引脚清单表 | 哪个脚是什么功能、有几路 | 20 引脚表（第 20 篇的 80 脚对照就是它 + PCB） |
| **绝对最大额定值** | 电压/电流/温度的"不许超过"表 | 会不会烧 | （本工程未涉及） |
| **电气特性（DC/AC）** | 供电、IO 电平、上拉电阻、时钟精度、功耗 | "能跑多快、多准" | ADC 时钟上限、IRC32K 精度（第 13 篇 7.1 节） |
| ****特性说明 / 功能描述** | 文字 + 公式 | **怎么换算（温度、电压）** | **内部温度传感器公式（第五章案例 5）** |
| **封装与订货信息** | 封装尺寸、料号 | 打板/采购 | （本工程未涉及） |

### 4.1 数据手册最容易被忽略的一点：**典型值 vs 保证值**

**这是查数据手册最容易犯的错**：

| 类型 | 含义 | 例子 |
| --- | --- | --- |
| **Typical（典型值）** | 大部分芯片的表现，**不保证** | V25 = **1.45 V**（温度传感器 25℃ 时的输出电压） |
| **Min / Max（保证值）** | 全温度范围、全批次都满足的边界 | `TL = ±1.5 ℃` |
| **仅在某条件下成立** | 表格旁边常有一行"条件" | "VDD = 3.3 V, TA = 25 ℃" |

**本工程的真实后果**：

```c
// main.c 里的温度计算
float temp = (1.45f - vol) * 1000 / 4.1f + 25;
//            ↑ V25 是"典型值"，不同芯片可能是 1.38 V 或 1.52 V
```

```
V25 典型 1.45 V，工艺分散可能 ±0.07 V
⇒ 换算成温度误差：0.07 V / 4.1 mV/℃ ≈ 17 ℃！
⇒ 结论：用这个公式只能"估个大概"，想准必须做"单点校准"
   （把板子放在已知温度下读一次，反推你这颗芯片的 V25）
```

> **这才是"读懂数据手册"的关键**：**看到数字先问三件事**——**这是典型值还是保证值？测试条件是什么？我的应用满足这个条件吗？**
> 只抄数字不问条件，等于没查。

## 五、本工程 14 个真实查证案例（本章是全文精华）

**每一个都给出：问题 → 查了什么 → 查到什么 → 影响了哪行代码。**

### 案例 1：定时器时钟到底是 168 MHz 还是 336 MHz？

| 步骤 | 内容 |
| --- | --- |
| **问题** | APB1 = 42 MHz、APB2 = 84 MHz，`RCU_TIMER_PSC_MUL4` 之后定时器时钟是多少？按"×4"算 APB2 会得到 336 MHz（超规格） |
| **查哪本** | **固件库头文件**（比手册更直接）：`Firmware/.../Include/gd32f4xx_rcu.h` |
| **查到什么** | 第 962~969 行注释原文：MUL4 时，**若 APB1PSC/APB2PSC ∈ {÷1, ÷2, ÷4}，则 `CK_TIMERx = CK_AHB`**；否则才是 `4 × CK_APBx` |
| **影响** | 本工程 APB1=÷4、APB2=÷2 都在允许集合内 → **所有定时器统一 168 MHz**；也定下了"改 APB 分频必须重算所有定时器参数"这条铁律（第 13/14 篇） |

> **这个案例说明**：**"库源码里的注释"经常比用户手册好用**——它直接回答"我这样配会得到什么"，而手册只描述"这个位是什么意思"。

### 案例 2：中断函数该叫什么名字？

| 步骤 | 内容 |
| --- | --- |
| **问题** | TIMER5 的中断服务函数叫什么？ |
| **查哪本** | **启动文件**：`startup_gd32f407_427.s` 的中断向量表 |
| **查到什么** | **`TIMER5_DAC_IRQHandler`**——TIMER5 和 DAC 共用同一个中断向量 |
| **影响** | 写成 `TIMER5_IRQHandler` 编译能过，但**中断永远不触发**（第 07 篇反复强调的坑） |

**同源案例**：EXTI5~9 共用 `EXTI5_9_IRQHandler`（第 17 篇 PCF8563 的 INT 走 EXTI5）。

> **查法口诀**：**中断函数名 = 去启动文件的向量表里搜**。搜关键词（外设名）最快，比如 `grep -n "USART0_IRQHandler" startup_*.s`。

### 案例 3：这个引脚能做哪个定时器的 PWM？

| 步骤 | 内容 |
| --- | --- |
| **问题** | PB9 想输出 PWM，用哪个定时器、哪个通道、哪个 AF？ |
| **查哪本** | **用户手册的复用功能表**（教材整理成了一张查询表：`NOTE/Note/TIMER.md` 2.3 节） |
| **查到什么** | **PB9 = TIMER1_CH1，AF1**（同一引脚还可能是 TIMER3_CH3 / TIMER10_CH0 等，需按 AF 区分） |
| **影响** | 第 07 篇 `ef6a015` 曾把 PB9 配成 `AF_2` + 用 `TIMER_CH_2`，**两个都错** → 引脚毫无波形；`b4f56b7` 才改成 `AF1` + `TIMER_CH_1` |

> **教训**：**"引脚 → 定时器 → 通道 → AF"是一个四元组**，必须一起查、一起改（第 07 篇的"三件套/四件套"）。

### 案例 4：串口波特率的分频怎么算？

| 步骤 | 内容 |
| --- | --- |
| **问题** | USART0（APB2）和 USART2（APB1）都配 115200，分频值一样吗？ |
| **查哪本** | **库源码**：`gd32f4xx_usart.c` 的 `usart_baudrate_set()` |
| **查到什么** | 它**按外设分支去取总线频率**：USART0 → `rcu_clock_freq_get(CK_APB2)`；USART2 → `CK_APB1`；然后 `udiv = (uclk + baud/2)/baud`，拆成 mantissa + fraction |
| **影响** | 逐位复算后：USART0 的 USARTDIV = **45.5**、USART2 = **22.75**，实际波特率都是 115384.6（**+0.16% 误差**）（第 13 篇 5.9 节） |

### 案例 5：ADC 内部温度怎么换算？（**数据手册公式的典型**）

| 步骤 | 内容 |
| --- | --- |
| **问题** | ADC 采到的值怎么变成温度？ |
| **查哪本** | **数据手册**：`GD32F407xx_Datasheet_Rev2.7.pdf` 的**表 4-36**（温度传感器特性） |
| **查到什么** | 公式 `T(℃) = (V25 − V_sense) / Avg_Slope + 25`；参数 **V25 = 1.45 V**、**Avg_Slope = 4.1 mV/℃**、**`tS_temp` = 17.1 μs（最小采样时间）**、`TL = ±1.5 ℃` |
| **影响** | ① 代码里的温度公式（含那个容易漏的 `×1000`）② **采样时间必须满足 17.1 μs** —— 第 19 篇发现温度通道被改成了 15 周期（0.71 μs），**不满足要求** |

> **这个案例同时演示了两种查法**：
> - **查公式** → 数据手册的"特性说明"章节（不是寄存器章节！）
> - **查约束**（最小采样时间）→ 数据手册的参数表，**并且要把它换算成本工程的条件**（17.1 μs 对应 21 MHz 下至少 360 个采样周期）

### 案例 6：ADC 时钟最高能多少？

| 步骤 | 内容 |
| --- | --- |
| **问题** | ADC 分频该取多少？ |
| **查哪本** | 用户手册/数据手册的 ADC 电气特性 |
| **查到什么** | 代码注释保留了这个结论：`/* 设置分频系数 21Mhz(根据时钟树确定要小于49Mhz)*/` |
| **影响** | `ADC_ADCCK_PCLK2_DIV4`：84 MHz ÷ 4 = **21 MHz**（安全） |

> **注意那行注释的写法**：**结论（21 MHz）+ 依据（小于 49 MHz）+ 依赖（根据时钟树）**——三条信息都留给了下一个看代码的人。**这就是"把查到的结论写回代码"的正面例子**（第八章展开）。

### 案例 7：I2C 器件的 7 位地址是多少？

| 步骤 | 内容 |
| --- | --- |
| **问题** | PCF8563 的 I2C 地址？OLED 的地址？ |
| **查哪本** | **器件的数据手册**（不是 MCU 手册！） |
| **查到什么** | PCF8563 = **0x51**；SSD1306 OLED = **0x78（8 位形式）→ 0x3C（7 位）** |
| **影响** | 代码里 `PCF8563_ADDR 0x51`、OLED 里写 `0x78 >> 1`；**理解为什么必须右移一位**（第 15/18 篇） |

> **⚠️ 一个高频混淆**：**器件厂商喜欢给"8 位地址"**（含读写位，如 0x78/0xA2），**而 MCU 库要"7 位地址"**（0x3C/0x51）。**看到地址先确认它包含几位**——这是最经典的"查了手册但还是配错"的坑。

### 案例 8：代码注释和器件手册"打架"时听谁的？

| 步骤 | 内容 |
| --- | --- |
| **问题** | PCF8563 定时器时钟源的编码（`0x0E` 寄存器 bit[1:0]）到底是什么？ |
| **查哪本** | PCF8563 数据手册 |
| **查到什么** | 手册的编码顺序与**工程代码注释里写的顺序相反**（第 17 篇 4.3 节指出了这处矛盾） |
| **影响** | 结论：**以手册为准**；代码注释是二手的、可能抄错 |

> **这条是全文最重要的一条原则**：**手册（一手）> 代码注释/教材（二手）**。
> 但要**区分是谁的手册**：MCU 手册管 MCU，**器件手册管器件**——查传感器/RTC/Flash 的参数，必须去翻**那颗器件自己的数据手册**。

### 案例 9：这个引脚"到底被谁占了"？

| 步骤 | 内容 |
| --- | --- |
| **问题** | 代码里 `printf` 用的是 USART0(PA9/PA10)——这两个脚在板上真的接出去了吗？PB10 呢？ |
| **查哪本** | **原理图 / PCB 网表**（本工程已整理成 `Doc/硬件信息汇总.md`、`Doc/引脚检查测试.md`） |
| **查到什么** | ① PA9/PA10 **没引出到排针，就是板载 USB-TTL** → `printf` 重定向到它是**正确**的 ② **PB10 是 LCD 背光（LCD_BLK）**，而代码把它当 USART2_TX → 冲突（P1） ③ MCU 侧**没有** 32.768 kHz 晶振（焊在 PCF8563 上） |
| **影响** | 解释了第 11 篇"为什么 RTC 用 HXTAL"；第 20 篇的 P1/P2/P3 |

> **这一条的关键认识**：**"引脚占用"这类问题在 MCU 手册里查不到**——手册只告诉你"这个脚能做哪些功能"，**能不能用要问原理图/PCB**。

### 案例 10：系统时钟到底是多少？

| 步骤 | 内容 |
| --- | --- |
| **问题** | `SystemCoreClock` 是多少？为什么所有定时器都按 168 MHz 算？ |
| **查哪本** | **工程源码**：`Firmware/CMSIS/GD/GD32F4xx/Source/system_gd32f4xx.c` |
| **查到什么** | 第 51 行启用了 `__SYSTEM_CLOCK_168M_PLL_8M_HXTAL`；同文件还有 120M/200M/240M 选项；`system_clock_168m_8m_hxtal()` 里 PSC=8 / PLL_N=336 / PLL_P=2 / PLL_Q=7 |
| **影响** | PLL 三级计算、AHB/APB 分频、**以及"跑高频还要开 LDO 档位和 high-drive"**（第 14 篇） |

### 案例 11：SPI Flash 的指令和 ID 在哪张表？

| 步骤 | 内容 |
| --- | --- |
| **问题** | `bsp_flash.c` 里那些 `0x90` / `0x06` / `0x05` / `0x20` / `0x02` / `0x03` 是什么？读 ID 该期待什么值？为什么读出来是 16 位而不是 24 位？ |
| **查哪本** | **器件数据手册**（GD25Q32/W25Qxx）：`Instruction Set` 表 + `Read Manufacturer / Device ID` 一小节 |
| **查到什么** | ① 指令表：`06h` WREN / `05h` RDSR / `03h` Read / `02h` Page Program / `20h` Sector Erase / `90h` Read M-ID&D-ID / `9Fh` JEDEC ID<br>② **`90h` 返回 2 字节**（制造商 + 设备），**`9Fh` 返回 3 字节**（制造商 + 类型 + 容量）——这就是"为什么本工程是 16 位、官方例程是 24 位"的答案<br>③ `90h` 后面必须跟 3 个"假地址字节"（内容随意，但**少一个就整个错位**） |
| **影响** | 代码里 `spi_read_write_byte(0x90)` + 3 个 `0x00` + 读 2 字节的写法**逐字对应手册**；串口期望 `ID = C8xx`（制造商 `C8` = GigaDevice） |

> **补充技巧（很实用）**：**"官方例程"是第三类资料，而且就在本机**。
> 本工程固件库里带着 GigaDevice 官方的 GD25Qxx 驱动：
> `NOTE/Doc/GD32F407/GD32F4xx_Firmware_Library_V3.2.0/Examples/USB/USB_Device/dev_firmware_update/src/gd25qxx.c`
> 它用的是 `9Fh`（3 字节）**并且拉低一次 CS 连续读状态寄存器**（比本工程逐次重发 `05h` 更高效），
> 还提醒了"块擦除不只有 64 KB，还有 32 KB"（`SPI_FLASH_BLOCK_SIZE 0x8000`）。
> **查手册的同时翻一眼官方例程，往往能直接省掉一次试错**（第 24 篇 §3 就是两版对照）。

### 案例 12：Flash 擦一次要多久？（**"物理时间"该怎么查**）

| 步骤 | 内容 |
| --- | --- |
| **问题** | `bsp_flash_wait_busy()` 要等多久？写 10 个字节花多长时间？ |
| **查哪本** | **器件数据手册**的 **AC Characteristics / 时序表** |
| **查到什么** | `tPP`（Page Program, 256 B）typ **0.7 ms** / max 3 ms；`tSE`（4 KB 扇区擦除）typ **45 ms** / max 400 ms；`tBE`、`tCE` 更大 |
| **影响** | ★ **换算成"要不要小心"**：45 ms ≫ WWDGT 窗口 1.66 ms、≫ FWDGT 超时 100 ms —— **"开看门狗"和"写 Flash"在当前代码结构下互斥**（第 13 篇 §7.4、第 24 篇 §7.2） |

> **这类"器件内部时间"和"总线时钟"完全无关**，是第 13 篇里补的"第三类时间：物理时间"。
> **查法要点**：它的单位是 **ms / s**，不是"周期数"——**看到 ms 级数字就要立刻联想到"看门狗、主循环阻塞、低功耗唤醒"**。

### 案例 13：NTC 的 R-T 表从哪来？

| 步骤 | 内容 |
| --- | --- |
| **问题** | `bsp_ntc.c` 里那 181 个数（`58354` … `32`）是什么？为什么不用公式算？ |
| **查哪本** | **器件规格书**（NTC 供应商提供的 `R-T` 对照表），或整机原理图上标明的型号 |
| **查到什么** | 表 = **温度 → 阻值×100**（单位 0.01 kΩ），步长 1 ℃，范围 −55 ~ +125 ℃ |
| **影响** | ① 换 NTC 型号 → **必须整表替换**（第 27 篇练习题 1）<br>② 这张表**替代了 B 值公式**——因为真实 NTC 的等效 B 值随温区变化（0→25 ℃ 段 ≈3800 K，25→50 ℃ 段 ≈3960 K，差 4%）<br>③ 表占 **362 B** 存储（且**必须加 `const` 才会真的放进 flash**，第 27 篇 §7） |

> **这三张表（Flash 指令表 / Flash 时序表 / NTC 的 R-T 表）合起来说明一件事**：
> **只要用到一个"片外器件"，就至少要有三本资料**——芯片手册（怎么配 MCU）、
> 器件手册（怎么和它说话）、器件规格/整机图纸（它到底是什么参数）。
> **"查不到"的时候，往往不是手册写得差，而是查错了书**（第 42 页那句）。

### 案例 14：WS2812 的时序参数和"分频只能是 2 的幂"

| 步骤 | 内容 |
| --- | --- |
| **问题** | WS2812 的 `'0'`/`'1'` 各要多长的高电平？复位低电平要多久？怎么让 MCU 发出来？ |
| **查哪本** | **器件数据手册**（WS2812B / WS2812B-V5）：`Timing` 表 + **`GD32F4xx_User_Manual`**（SPI 分频档位）+ **`gd32f4xx_rcu.h`**（SPI1 挂哪条总线） |
| **查到什么** | ① `T0H = 400±150 ns`、`T1H = 800±150 ns`、位周期 **1.25 µs**、复位低电平 **>50 µs（B）/ >280 µs（V5）**<br>② SPI 分频**只能是 2 的幂**（`SPI_PSC_2/4/8/…`），APB1=42 MHz → 只有 **21 / 10.5 / 5.25… MHz**，**没有 8 MHz**<br>③ `RCU_APB1EN_SPI1EN` → **SPI1 挂 APB1（42 MHz）**，不是 84 MHz |
| **影响** | ★ 三条合起来决定了实现方案：**时钟改不了就改"1 个 WS2812 位用几个 SPI 位"**（10 → **13**），使 13 ÷ 10.5 MHz ≈ **1238 ns**；否则时序错 24%，**4 颗灯只亮 1 颗**（第 30 篇 §4） |

> **这个案例最能说明"一件产品要查三本书"**：器件手册给"要求什么"，用户手册给"我能配出什么"，
> 库头文件给"这个外设挂在哪条总线上"。**三者缺一，都会得出错误的参数**。

## 六、"从问题到那一张表"的四步查法

**把它当成流程来走，不要瞎翻**：

```
第 1 步：把疑问"归类"→ 用第二章的表判断该查哪本资料
         （引脚类？寄存器类？参数类？时序类？公式类？中断名？板级？工程配置？）
              ↓
第 2 步：选定文档，先看目录（不要直接翻页）
         · 用户手册：按外设分章（"16 定时器"、"22 串口"…）
         · 数据手册：按"引脚→电气→封装"的固定顺序，公式一般在"特性说明"里
         · 库源码：按外设找同名文件（gd32f4xx_<外设>.c/.h）
              ↓
第 3 步：在章节内定位到"表/图"
         · 中文搜"表 x-y"/"图 x-y"，再换英文 "Table x-y"/"Figure x-y" 各搜一遍
         · 表格标题里通常含关键词（如 "Temperature sensor characteristics"）
         · 找不到就在同一章节内搜信号名/寄存器名（如 "TIMERSEL"、"tS_temp"）
              ↓
第 4 步：把结论抄进代码注释，顺手记下"表号 + 版本 + 条件"
         （否则下一个人要重查一遍——第八章给模板）
```

**四个提高效率的小技巧**：

| 技巧 | 说明 |
| --- | --- |
| **优先搜库源码的注释** | 库注释经常直接写"这样配会得到什么"，比手册的描述更贴合代码语法 |
| **中英双关键词各搜一遍** | 中文手册里的参数名（"平均斜率"）和英文（"Avg_Slope"）都对一下 |
| **先看"图表清单"** | 很多手册正文前面有"图目录/表目录"，直接跳到目标表 |
| **核对版本号** | `GD32F4xx_User_Manual_Rev3.0_CN.pdf` 的 Rev 数字要与你的芯片/库版本匹配（第 20 篇遇到过"原理图与 PCB 不同步"的类似问题） |

## 七、"查不到"怎么办（三种真实情况）

### 7.1 手册没写 / 没写清楚 → 改查库源码

**这是本工程最有效的一招**。库源码里藏着大量"实际怎么配"的信息：

```bash
# 倍频规则原文（比手册更直接回答"配了会怎样"）
grep -n "RCU_TIMER_PSC_MUL4" -B 3 -A 4 Firmware/.../Include/gd32f4xx_rcu.h

# 波特率分频算法（含 16×/8× 过采样分支）
grep -n "usart_baudrate_set" -A 45 Firmware/.../Source/gd32f4xx_usart.c

# 某个外设挂在哪条总线（看使能位在哪个寄存器组）
grep -n "APB1EN_\|APB2EN_\|AHB1EN_" Firmware/.../Include/gd32f4xx_rcu.h | grep -i usart

# 中断函数的"官方名字"
grep -n "IRQHandler" Firmware/CMSIS/GD/GD32F4xx/Source/ARM/startup_gd32f407_427.s
```

> **注意**：库源码是**二手**（是 GigaDevice 写的，不是芯片本身），**它可能与手册/芯片行为有出入**——所以它是"快速定位"的工具，**最终结论仍应与手册对上**。

### 7.2 代码注释与手册冲突 → 以手册为准

本工程有两处明确冲突：

| 冲突 | 手册说 | 代码注释说 | 怎么处理 |
| --- | --- | --- | --- |
| PCF8563 定时器时钟编码（第 17 篇） | 一种顺序 | **相反的顺序** | 以手册为准，修正注释/代码 |
| 软件 I2C 的延时（第 15 篇） | —（协议决定"宁慢勿快"） | "SCL 高低各 5 μs"，代码却是 `delay_1us(2)` | 追查实际周期，注释跟着代码改 |

**原则**：**一手资料 > 二手资料**。

```
一手：芯片本身（实测波形）、数据手册、用户手册、原理图/PCB
二手：库源码、代码注释、教材、网上抄来的代码
```

### 7.3 手册与实物不符 → 以实物/PCB 为准

第 20 篇的例子：**代码注释写着"PA0 外部接了下拉"，硬件核对发现 PA0 根本没有上下拉**。

```
注释里的假设 → 错的
```c
#define EXTI0_PUPD GPIO_PUPD_NONE    // 注释："外部接了下拉，不用内部下拉"
```

**处理**：**改代码（加内部上拉）或改注释（说明真实情况）**——**但不能让它继续错着**。

**这正是"文档是快照，不是真相"的另一个版本**：**真相在实物上**。

## 八、把结论写回代码：注释模板

**查完资料不写在代码里，等于没查**——下一个人（可能是三个月后的你）还得重查一遍。

### 8.1 本工程的正面例子

```c
/* 设置分频系数 21Mhz(根据时钟树确定要小于49Mhz)*/      // 结论 + 依据 + 依赖
adc_clock_config(ADC_ADCCK_PCLK2_DIV4);
```
```c
// 计算得到温度值 (datasheet中找到公式)
// (v25 - v) / avg_slope + 25                          // 公式 + 出处（datasheet）
float temp = (1.45f - vol) * 1000 / 4.1f + 25;
```
```c
// 扫描相位后的稳定延时（us）
// 行/列释放后要靠内部上拉（典型几十 kΩ）把线拉高，
// 与排线+键盘的寄生电容（约 50~150pF）形成数 us 的上升时间，
// 2us 往往还没越过输入门限……                          // 参数 + 原理 + 踩坑记录
#define KP_SETTLE_US 20
```
```c
// USART0中断处理函数必须叫这个
// 在startup.s中配置了中断向量表 line124                // 名字 + 依据（甚至给了行号）
```

### 8.2 推荐的注释模板（比本工程现有做法再进一步）

```c
/*-------------------------------------------------------------
 * 参数/结论：ADC 时钟 = 21 MHz
 * 依据    ：GD32F407xx_Datasheet Rev2.7 表 xx-xx（ADC 特性）
 * 条件    ：VDD=3.3V, ADCCK 上限 49 MHz
 * 推导    ：PCLK2 = 84 MHz（见 msp 时钟树）÷ 4 = 21 MHz
 * 备注    ：改 APB2 分频后此值需重算
 *-----------------------------------------------------------*/
adc_clock_config(ADC_ADCCK_PCLK2_DIV4);
```

**模板的五个要素**（**结论 / 依据 / 条件 / 推导 / 备注**）——按重要性排序：

| 要素 | 为什么必须写 |
| --- | --- |
| **结论** | 别人一眼看到结果 |
| **依据（表号 + 手册版本）** | 别人能自己复核；手册改版时知道要重查 |
| **条件** | 数据手册里的数字都带条件，脱离条件就是错的 |
| **推导** | 把"从哪来"写清楚（如 84 MHz ÷ 4） |
| **备注（改动影响）** | 提醒"改了 A 要重算 B"（第 13/14 篇的"影响面"） |

### 8.3 反例：本工程里那些"数字没有出处"的注释

```c
// PWM 周期1ms 占空比20% 0.2ms        ← 与代码实际不符（第 07 篇）
// 100kbit/s ... SCL高低分别持续5us    ← 与 delay_1us(2) 不符（第 15 篇）
// clock: 0x80=1Hz 0x81=64Hz ...      ← 与器件手册相反（第 17 篇）
```

**三个反例的共同点**：**只写了"结论"，没写"依据"**——所以**没人能判断它对不对**，于是一直错着。

> **一句话**：**"带出处的注释"能让别人复核，"不带出处的注释"只能让人猜。** 前者是资产，后者是负债。

8. 本工程的 `Doc/引脚检查测试.md` 依据什么数据编写？它给自己标注了哪些局限？为什么这些标注很重要？
9. 一条好的"参数注释"应该包含哪五个要素？
10. 本工程有三处"数字没有出处的注释"（软 PWM、I2C 延时、PCF8563 时钟编码），它们的共同问题是什么？

## 十一、练习题

1. **查一张表**：在用户手册里找到"定时器"章节的**复用功能表**，查出 `PD12/PD13/PD14/PD15` 分别对应 TIMER3 的哪个通道、哪个 AF 编号，和 `NOTE/Note/TIMER.md` 2.3 节的表对一遍。
2. **查一条公式**：打开 `GD32F407xx_Datasheet_Rev2.7.pdf`，找到**表 4-36**，抄下 `V25`、`Avg_Slope`、`tS_temp`、`TL` 四个参数的**完整条件行**（比如测试条件是什么）。
3. **查一个电气上限**：找出 GD32F407 的 **ADC 时钟上限**和**单个 IO 的最大灌电流**，分别写清出处（表号 + 版本）。
4. **查中断名**：用 `grep` 从启动文件里列出所有含 `TIMER` 和 `EXTI` 的中断函数名，找出哪些是"共用向量"的。
5. **查一次冲突**：从 `Note/` 或 `Textbook/` 里找一条"代码注释与手册不一致"的说法（除了本专题列出的三处），核对后写出正确结论与出处。
6. **写一条合格的注释**：挑你工程里一个"靠查资料才敢写"的参数，按第八章的**五要素模板**补一条注释。
7. **建一个"资料索引"文件**：在自己的项目里建 `Doc/资料索引.md`，把"问题类型 → 查哪本 → 表号/章节"整理成一张表（本专题第二章 + 第九章可以直接当模板）。
8. **查一遍"未实现"的器件**：从硬件文档的功能缺口表里挑一个（比如 NTC 热敏电阻或 DHT11），找到它的数据手册，抄出"测什么、怎么换算"的公式和参数，评估要改哪些代码。
