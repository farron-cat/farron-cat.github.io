## 知识点地图

```
时钟树与总线
├── 总线分层            AHB（大巴士）+ APB（小巴士），中间靠桥接器
├── 总线矩阵            多个 master（CPU、DMA）→ 仲裁 → 多个 slave
├── 「总线」在代码里    = 时钟使能寄存器的分组（RCU_AHB1EN / APB1EN / APB2EN / BDCTL）
├── 时钟源（6 个）      HXTAL 8M / IRC16M / IRC48M / IRC32K / LXTAL 32.768k / PLL
├── 复位默认时钟        上电先跑 IRC16M 16 MHz，SystemInit() 才切到 PLL 168 MHz
├── PLL 倍频            PSC(/8) → VCO ×336 → PLLP(/2)=168M、PLLQ(/7)=48M
├── 分频链              AHB ÷1 → APB1 ÷4 → APB2 ÷2（对应 168/42/84 MHz）
├── 电源配合            LDO 电压档位 + PMU high-drive（168 MHz 的额外要求）
├── TIMERSEL            定时器时钟统一到 168 MHz 的精确规则与边界反例
├── 时钟查询            rcu_clock_freq_get(CK_SYS / CK_AHB / CK_APB1 / CK_APB2)
├── 代码里的时钟使能    每个外设初始化第一行的 rcu_periph_clock_enable()
└── 改动影响面          改时钟树 = 所有基于时间的参数全部重算（联动第 13 篇）
```

| # | 岔路 | 决定什么 |

## 二、总线：什么是「总线」，它在代码里长什么样

### 2.1 两个总线，一大一小

教材的比喻非常贴切，值得复述一遍：

> **把芯片内部想象成一条大街，街上有很多房子：**
> - **每座房子 = 一个功能外设**（GPIO、SRAM、USART……）；
> - **房子里的灯 = 这个外设有没有被使能**（这就是 `rcu_periph_clock_enable()` 干的事）；
> - **房子门口的招呼员 = 该外设的工作频率**（有的房子招手快，有的慢）；
> - **大巴士 = AHB 总线**：24 小时准时发车，看到哪家房子亮灯并招手，就停下来给谁运东西。

| 总线 | 全称 | 角色 | 挂什么 |
| --- | --- | --- | --- |
| **AHB** | Advanced High-performance Bus | **大巴士**（高速） | 处理器、Flash/SRAM、DMA、GPIO、USB、以太网 |
| **APB** | Advanced Peripheral Bus | **小巴士**（低速） | USART、TIMER、I2C、SPI、ADC、看门狗…… |

**为什么要分层（而不是全都挂最快的那条）？**

```
所有设备都挂 AHB：成本高、功耗高、时序难做（慢设备拖累整条总线）
分层之后：快设备走快车道、慢设备走慢车道，中间用「桥接器」连接
        ⇒ 这是芯片设计的通用做法：速度匹配 + 成本/功耗折中
```

### 2.2 AHB 其实还分了组，而且支持「多主设备」

**① AHB 分三组**（本工程库源码 `rcu.h` 第 53~55 行）：`RCU_AHB1EN` / `RCU_AHB2EN` / `RCU_AHB3EN`。

| 分组 | 本工程会碰到的外设 | 库里的使能位 |
| --- | --- | --- |
| **AHB1** | **GPIOA~GPIOI**、**DMA0/DMA1**、CRC、IPA、ENET、USBHS | `RCU_AHB1EN_PAEN`…`RCU_AHB1EN_DMA1EN` |
| **AHB2** | DCI、TRNG、USBFS | `RCU_AHB2EN_*` |
| **AHB3** | EXMC（外部存储控制器） | `RCU_AHB3EN_EXMCEN` |

**② 总线上有多个「主设备（master）」** —— 这一点解释了第 08 篇的 DMA：

```
        ┌──── Cortex-M4（CPU）──┐        ┌── DMA0 / DMA1 ──┐
        │       master          │        │     master       │
        └───────────┬───────────┘        └────────┬─────────┘
                    │      AHB INTERCONNECT MATRIX（仲裁器） │
                    │            FMAX = 168 MHz             │
                    └──────────────┬─────────────────────────┘
                                   ▼
              slave：Flash、SRAM0/1、GPIO、各外设寄存器……
```

**结论**：**CPU 和 DMA 都能主动访问内存/外设**，两者靠总线矩阵仲裁。这就是「DMA 能在后台搬数据，CPU 同时干别的」的硬件基础 —— 它们本来就在总线上平级。

### 2.3 「总线」在代码里到底体现成什么

这是本篇最实用的一个认知转换：

> **在代码里，「总线」= 「时钟使能寄存器属于哪一组」。**

```c
rcu_periph_clock_enable(RCU_GPIOA);   // 位在 RCU_AHB1EN  → GPIOA 挂在 AHB1
rcu_periph_clock_enable(RCU_DMA1);    // 位在 RCU_AHB1EN  → DMA1  挂在 AHB1
rcu_periph_clock_enable(RCU_USART0);  // 位在 RCU_APB2EN  → USART0 挂在 APB2
rcu_periph_clock_enable(RCU_USART2);  // 位在 RCU_APB1EN  → USART2 挂在 APB1
rcu_periph_clock_enable(RCU_WWDGT);   // 位在 RCU_APB1EN  → WWDGT  挂在 APB1
rcu_periph_clock_enable(RCU_RTC);     // 位在 RCU_BDCTL   → RTC 在「备份域」，不属于 APB
```

**所以「查一个外设挂哪条总线」只需要两步**：

```bash
# ① 找到这个外设的时钟 id 定义（ID 里带寄存器偏移）
grep -n "RCU_USART2\b" Firmware/.../Include/gd32f4xx_rcu.h
#   → RCU_USART2 = RCU_REGIDX_BIT(APB1_REG_OFFSET, 18U)     ← 一眼看出是 APB1

# ② 或者直接看使能位分组
grep -n "APB1EN_USART2EN\|APB2EN_USART0EN" Firmware/.../Include/gd32f4xx_rcu.h
```

**⚠️ 一个容易忽略的点**：`rcu_periph_clock_enable()` **只是「打开外设的门」（时钟门控），不等于配置外设**。所以每个初始化函数的第一行几乎都是它 —— **时钟没开，后面所有寄存器写入都无效**（写进去石沉大海，读出来全是 0）。这就是「外设完全没反应」类问题的第一嫌疑犯。

## 三、时钟源清单（本工程一共 6 个）

| 名称 | 频率 | 位置 | 类型 | 精度 | 本工程用途 |
| --- | --- | --- | --- | --- | --- |
| **HXTAL** | **8 MHz** | 板载外部高速晶振（SMD3225-4P，20 pF × 2） | 石英晶振 | 高（ppm 级） | **系统主时钟源**（经 PLL → 168 MHz）；**RTC 时钟源**（÷25 → 320 kHz） |
| **IRC16M** | 16 MHz | 芯片内部 RC | RC | 中 | **复位后的默认系统时钟**；HXTAL 坏掉时的备胎 |
| **IRC48M** | 48 MHz | 芯片内部 RC（GD32 的增强，寄存器在 `RCU_ADDCTL`） | RC | 中 | 备用的 48 MHz（USB 等） |
| **IRC32K** | 32 kHz | 芯片内部 RC | RC | **低（±1%~5%）** | **FWDGT 专用**；RTC 的一个可选时钟源 |
| **LXTAL** | **32.768 kHz** | 外部低速晶振（SMD3215-2P，12 pF × 2） | 石英晶振 | **最高** | RTC 的最佳时钟源（本工程未装/未用） |
| **PLL** | 可编程 | 芯片内部 | 锁相环 | 取决于输入 | 8 MHz → **168 MHz**（系统）、48 MHz（USB） |

### 3.1 为什么 RTC 偏偏用 32.768 kHz

```
32 768 = 2^15

⇒ RTC 内部只要做一个 15 级二进制分频器，就能精确得到 1 Hz
⇒ 用二进制电路实现极为简单（比 10^6 分频省事得多）

所以全世界的 RTC 都用 32.768 kHz —— 这是行业惯例，不是巧合。
```

### 3.2 为什么不用「168 MHz 晶振」直接接上去

| 方案 | 问题 |
| --- | --- |
| 直接买 168 MHz 晶振 | 高频晶振**贵、难做、易受干扰**；而且一块板子往往需要多个频率（8M/32.768k/48M…），不可能每样都配一颗 |
| **低频精准晶振 + PLL 倍频** | 一颗 8 MHz 搞定所有频率，**便宜、可靠、灵活** —— 业界标准做法 |

### 3.3 复位后先跑哪个？—— 上电时序的第一环

```
上电/复位
   ↓
CK_SYS 默认 = IRC16M = 16 MHz      ← 寄存器 SCS 复位值 = 0（`RCU_CKSYSSRC_IRC16M`）
   ↓  启动文件里的 SystemInit() 调用 system_clock_168m_8m_hxtal()
CK_SYS = PLL = 168 MHz
   ↓  进入 main()，systick_config() 已经能用 168 MHz 算节拍
```

**为什么要先跑 IRC16M？** 因为芯片刚上电时，**外部晶振需要几毫秒才能起振稳定**（有的板子更久）。用内部 RC 先把内核跑起来，再去等晶振 —— 这样即使晶振坏了，芯片也还能跑（只是慢）。

**⚠️ 这条时序也解释了一个常见现象**：如果 `main()` 里打印出来的 `SystemCoreClock` 不是 168 000 000，说明 `system_gd32f4xx.c` 里选中的宏不对（下面第四章）。

## 四、【核心】逐行拆解本工程的时钟配置

### 4.1 第一步：确定用的是哪套配置（宏开关）

`system_gd32f4xx.c` 顶部有一排**互斥的宏**，注释掉哪个、启用哪个，决定了整颗芯片的主频：

```c
//#define __SYSTEM_CLOCK_IRC16M                   (uint32_t)(__IRC16M)
//#define __SYSTEM_CLOCK_HXTAL                    (uint32_t)(__HXTAL)
//#define __SYSTEM_CLOCK_120M_PLL_IRC16M          (uint32_t)(120000000)
//#define __SYSTEM_CLOCK_120M_PLL_8M_HXTAL        (uint32_t)(120000000)
//#define __SYSTEM_CLOCK_120M_PLL_25M_HXTAL       (uint32_t)(120000000)
//#define __SYSTEM_CLOCK_168M_PLL_IRC16M          (uint32_t)(168000000)
#define __SYSTEM_CLOCK_168M_PLL_8M_HXTAL        (uint32_t)(168000000)      // ★ 本工程启用
//#define __SYSTEM_CLOCK_168M_PLL_25M_HXTAL       (uint32_t)(168000000)
//#define __SYSTEM_CLOCK_200M_PLL_IRC16M          (uint32_t)(200000000)      // ← 这颗芯片还能跑 200M
//#define __SYSTEM_CLOCK_200M_PLL_8M_HXTAL        (uint32_t)(200000000)
//#define __SYSTEM_CLOCK_240M_PLL_8M_HXTAL        (uint32_t)(240000000)      // ← 甚至 240M
```

**三个信息量很大的点**：

| 点 | 说明 |
| --- | --- |
| 本工程选的是 **`168M_PLL_8M_HXTAL`** | 168 MHz，PLL 源是 **8 MHz 的 HXTAL** |
| **同一颗芯片还有 120M / 200M / 240M 选项** | GD32F407 最高可跑到 200 MHz（240M 选项也列出来了）——**本工程选 168 MHz 是为了与 STM32F4 对齐**（外设参数、教材算式都按 168 MHz 走） |
| 同一个主频还有 **IRC16M 版本** | 说明「用内部 RC 当 PLL 源」也是合法配置，只是精度差 |

> **这解释了教材那句「本教材配置下，系统时钟 168 MHz」的出处** —— 它不是芯片的限制，而是**工程里选定的配置**。
> **改主频只需要换宏，但换完所有时间参数都要重算**（第 13 篇）。

### 4.2 第二步：逐行看时钟配置函数

```c
static void system_clock_168m_8m_hxtal(void)
{
    uint32_t timeout = 0U;

    /* ① 打开 HXTAL（外部 8 MHz 晶振） */
    RCU_CTL |= RCU_CTL_HXTALEN;

    /* ② 等它稳定（超时则进入死等，说明晶振没起振） */
    while((0U == (RCU_CTL & RCU_CTL_HXTALSTB)) && (HXTAL_STARTUP_TIMEOUT != timeout++)){ }
    if(0U == (RCU_CTL & RCU_CTL_HXTALSTB)){
        while(0U == (RCU_CTL & RCU_CTL_HXTALSTB)) { }     // ← 卡死在这里 = 晶振有问题
    }

    /* ③ 电源相关：打开 PMU 时钟 + 选 LDO 电压档位 */
    RCU_APB1EN |= RCU_APB1EN_PMUEN;
    PMU_CTL |= PMU_CTL_LDOVS;

    /* ④ 配三条分频（先配好，等 PLL 稳定后生效） */
    RCU_CFG0 |= RCU_AHB_CKSYS_DIV1;      /* AHB  = SYSCLK     = 168 MHz */
    RCU_CFG0 |= RCU_APB2_CKAHB_DIV2;     /* APB2 = AHB / 2    =  84 MHz */
    RCU_CFG0 |= RCU_APB1_CKAHB_DIV4;     /* APB1 = AHB / 4    =  42 MHz */

    /* ⑤ 配置主 PLL：PSC = 8, PLL_N = 336, PLL_P = 2, PLL_Q = 7 */
    RCU_PLL = (8U | (336 << 6U) | (((2 >> 1U) -1U) << 16U) |
                   (RCU_PLLSRC_HXTAL) | (7 << 24U));

    /* ⑥ 开 PLL 并等它锁定 */
    RCU_CTL |= RCU_CTL_PLLEN;
    while(0U == (RCU_CTL & RCU_CTL_PLLSTB)){ }

    /* ⑦ 开 high-drive：把主频扩展到 168 MHz 的额外要求 */
    PMU_CTL |= PMU_CTL_HDEN;
    while(0U == (PMU_CS & PMU_CS_HDRF)){ }
    PMU_CTL |= PMU_CTL_HDS;
    while(0U == (PMU_CS & PMU_CS_HDSRF)){ }

    /* ⑧ 把 CK_SYS 切到 PLL，等切换生效 */
    RCU_CFG0 &= ~RCU_CFG0_SCS;
    RCU_CFG0 |= RCU_CKSYSSRC_PLLP;
    while(0U == (RCU_CFG0 & RCU_SCSS_PLLP)){ }
    ...
}
```

### 4.3 第三步：把每一级频率算出来

**PLL 的三级结构**（这是第四章的重点）：

```
HXTAL 8 MHz
   │
   ├─ ÷ PLLPSC(=8)  ─────────▶ VCO 输入 = 1 MHz      ← 先降到一个低频基准
   │
   ├─ × PLL_N(=336) ─────────▶ VCO 输出 = 336 MHz    ← 再大幅倍频
   │
   ├─ ÷ PLL_P(=2)   ─────────▶ CK_SYS   = 168 MHz    ← 分频出系统主频
   └─ ÷ PLL_Q(=7)   ─────────▶ 48 MHz                 ← 给 USB/SDIO/RNG 用
```

| 级 | 公式 | 代入 | 结果 |
| --- | --- | --- | --- |
| VCO 输入 | `HXTAL / PLLPSC` | 8 MHz ÷ 8 | **1 MHz** |
| VCO 输出 | `VCO_in × PLL_N` | 1 MHz × 336 | **336 MHz** |
| **CK_SYS** | `VCO_out / PLL_P` | 336 MHz ÷ 2 | **168 MHz** ★ |
| PLLQ 输出 | `VCO_out / PLL_Q` | 336 MHz ÷ 7 | **48 MHz** |
| CK_AHB | `CK_SYS / 1`（AHBPSC = ÷1） | 168 ÷ 1 | **168 MHz** |
| **PCLK2** | `CK_AHB / 2`（APB2PSC = ÷2） | 168 ÷ 2 | **84 MHz** |
| **PCLK1** | `CK_AHB / 4`（APB1PSC = ÷4） | 168 ÷ 4 | **42 MHz** |

### 4.4 「教材说 ×21」和「寄存器写 336/2」是什么关系

教材里的说法是：**「分频比 = 168 ÷ 8 = 21」**。而寄存器里写的是 `PLL_N = 336, PLL_P = 2`。两者并不矛盾：

```
等效倍数 = PLL_N / (PLLPSC × PLL_P) = 336 / (8 × 2) = 336 / 16 = 21  ✅

也就是说：
   教材说的「×21」是「从 8 MHz 到 168 MHz 的等效倍数」；
   硬件里拆成了三步：先 ÷8（降到 1 MHz）、再 ×336（升到 336 MHz）、再 ÷2（落到 168 MHz）。
```

**为什么要拆成三步，不直接 ×21？** 因为 PLL 有物理约束：

| 约束 | 原因 |
| --- | --- |
| **VCO 输入必须在 1~2 MHz 左右** | 太低则环路噪声大；所以先把 8 MHz 降到 1 MHz |
| **VCO 输出必须在几百 MHz 量级**（本工程 336 MHz） | PLL 只有在较高频率才工作得稳、抖动小 |
| **再分频得到需要的频率** | 一次 VCO 可以分出多个频率（÷2 给系统、÷7 给 USB），**这是关键收益** |

> **一句话记住**：**「高频 VCO + 后级分频」是 PLL 的标准结构** —— 好处是一次倍频能产出多个互不干扰的时钟。
> 这也回答了「为什么系统 168 MHz 和 USB 48 MHz 不用两颗晶振」。

### 4.5 两个容易被忽略的依赖：LDO 档位与 high-drive

在切到 168 MHz 之前，代码做了两件「和时钟看起来无关」的事：

| 操作 | 含义 | 为什么必须 |
| --- | --- | --- |
| `PMU_CTL \|= PMU_CTL_LDOVS` | 选 **LDO 电压档位** | 主频越高，内核需要的电压/电流越大；档位不匹配会导致跑不稳 |
| `PMU_CTL \|= PMU_CTL_HDEN` → `HDS` | 打开并选择 **high-drive（高驱动）模式** | 库注释写得很直白：**“Enable the high-drive to extend the clock frequency to 168 Mhz”** |

**结论**：**「跑高频」不只是配时钟，还要配电源**。
所以如果你想改主频（比如 200 MHz），**不能只改 PLL 参数** —— 电源档位、Flash 等待周期（latency）、外设分频都要跟着调。**这也是为什么教材说「时钟树改动是牵一发动全身」。**

> **这两行 PMU 操作值得单独展开**：它们打开的是"电源管理单元"这个模块。
> `PMU_CTL_LDOVS`（LDO 电压档）与 `HDEN/HDS`（高驱动模式）到底在控制什么、和三个电源域/省电模式是什么关系，
> 见 **[第 25 篇 · PMU 电源管理](25-PMU电源管理.md)** §2.1（那里把同一段代码逐行拆过，并补上了"PMU 时钟没开会静默失效"这个坑）。
> **一句话记**：本篇讲"时钟从哪来"，第 25 篇讲"电压和电流能不能跟上"。**两者缺一，168 MHz 都跑不稳。**

## 六、TIMERSEL：定时器时钟为什么不等于 APB 时钟

### 6.1 为什么不直接让定时器用 APB 时钟

```
如果定时器直接用 APB 时钟：
   写代码前必须先想「我这个定时器在 APB1 还是 APB2」
   再查出「APB1 = 42 MHz / APB2 = 84 MHz」
   ⇒ 每次算参数都要查两遍，非常烦

倍频的目的不是「让定时器更快」，而是「消除这份认知负担」：
   把定时器时钟统一提到 168 MHz —— 以后算参数只需要记住一个数
```

### 6.2 精确规则（库源码原文）

`gd32f4xx_rcu.h` 第 962~969 行的注释写得比手册还清楚：

> **`RCU_TIMER_PSC_MUL4`**：如果 `APB1PSC/APB2PSC` ∈ {`0b0xx`(÷1), `0b100`(÷2), `0b101`(÷4)}，
> 则 **`CK_TIMERx = CK_AHB`**；
> 否则 `CK_TIMERx = 4 × CK_APBx`。

**套到本工程**（APB1PSC = 0b101 ÷4，APB2PSC = 0b100 ÷2，**两个都在允许集合里**）：

```
CK_TIMERx = CK_AHB = 168 MHz      ← 所有定时器（APB1 上的和 APB2 上的）都是 168 MHz ✅
```

**这就是项目注释「时钟倍频(全局配置 所有定时器都是168Mhz)」的准确依据**，也解释了教材那张资源表里「倍频」列为什么 APB1 写 ×4、APB2 写 ×2 ——**两条总线的分频比不同，但最终都落到 168 MHz**：

```
APB1 侧：42 MHz × 4 = 168 MHz
APB2 侧：84 MHz × 2 = 168 MHz
（对应教材表格中的「倍频 ×4」与「×2」两列）
```

### 6.3 ⚠️ 边界反例（务必记住）

```
如果哪天把 APB1 分成 ÷8（不在允许集合里）：
    CK_TIMERx = 4 × 42/2 = 4 × 21 = 84 MHz     ← 不再是 168 MHz！
    ⇒ 所有 APB1 定时器的参数全部要按 84 MHz 重算
```

**结论**：

| 规则 | 说明 |
| --- | --- |
| 倍频后**统一 168 MHz** 是**有条件的结论** | 条件是 APB 分频 ∈ {÷1, ÷2, ÷4}。本工程满足 |
| **改时钟树 = 所有基于时间的参数重算** | 定时器、PWM、蜂鸣器、RTC、看门狗、串口波特率**一个都跑不掉**（第 13 篇 3.3 节） |
| 代码里怎么确认倍频生效了 | **打印 `RCU_CFG1`**（TIMERSEL 是它的 bit24）。本工程 `main.c` 里就有这两行：<br>`printf("SystemCoreClock = %u\r\n", SystemCoreClock);`<br>`printf("RCU_CFG1 = 0x%08X\r\n", RCU_CFG1);` |

## 七、让代码自己算时钟：`rcu_clock_freq_get()`

库提供了按需查询时钟的函数，参数是一个枚举（`rcu.h` 第 800~807 行）：

```c
typedef enum
{
    CK_SYS  = 0,     /*!< system clock  = 168 MHz */
    CK_AHB,          /*!< AHB clock     = 168 MHz */
    CK_APB1,         /*!< APB1 clock    =  42 MHz */
    CK_APB2,         /*!< APB2 clock    =  84 MHz */
} rcu_clock_freq_enum;

uint32_t rcu_clock_freq_get(rcu_clock_freq_enum);
```

**它最大的用户是串口驱动**（`gd32f4xx_usart.c` 的 `usart_baudrate_set()`）：

```c
switch(usart_periph) {
case USART0:
    uclk = rcu_clock_freq_get(CK_APB2);   // 84 MHz
    break;
case USART2:
    uclk = rcu_clock_freq_get(CK_APB1);   // 42 MHz
    break;
...
}
udiv = (uclk + baudval / 2U) / baudval;   // 由实际频率算出分频
```

**这段代码给我们的启示**：

| 启示 | 说明 |
| --- | --- |
| **别把频率写死** | 库函数是**运行时读寄存器算**出来的，所以**改了时钟树，波特率仍然正确** —— 这是好设计的价值 |
| **但有些东西没法自动** | `PSC`/`ARR` 这类**你自己填的定时器参数**，库帮不了你 —— 必须自己重算 |
| **可以用它写防错代码** | 例如初始化后 `assert(rcu_clock_freq_get(CK_APB1) == 42000000)`，时钟树配错立刻暴露 |

**顺带一个实用技巧**：如果怀疑时钟配置不对，直接打印三个查询值：

```c
printf("SYS=%u AHB=%u APB1=%u APB2=%u\r\n",
       rcu_clock_freq_get(CK_SYS), rcu_clock_freq_get(CK_AHB),
       rcu_clock_freq_get(CK_APB1), rcu_clock_freq_get(CK_APB2));
// 期望输出：SYS=168000000 AHB=168000000 APB1=42000000 APB2=84000000
```

## 八、改时钟树的影响面（联动第 13 篇）

**只要动了这几个宏/参数，下面每一项都要跟着重算**：

| 你改了什么 | 必须跟着改 |
| --- | --- |
| `system_gd32f4xx.c` 里的 `__SYSTEM_CLOCK_*` 宏 | ① 所有 **PSC/ARR**（定时器、PWM、蜂鸣器）② **USARTDIV**（库会自动算，但要确认落到合法值）③ **WWDGT 分频**（若 APB1 变了）④ `SysTick_Config()` 的参数由 `SystemCoreClock` 自动适配 ⑤ Flash 等待周期、LDO/high-drive 档位 |
| `RCU_AHB_CKSYS_DIVx`（AHB 分频） | 所有 APB 频率（因为 APB 是 AHB 再分频）→ 上述全部 |
| `RCU_APB1_CKAHB_DIVx`（APB1 分频） | ① APB1 外设频率 ② **TIMERSEL 是否仍然满足「统一 168 MHz」的条件** ③ WWDGT 计数时间 ④ USART2/UART3/4 波特率 |
| `RCU_APB2_CKAHB_DIVx`（APB2 分频） | APB2 外设频率（USART0、TIMER0/7、ADC、SYSCFG）+ TIMERSEL 条件 |
| `rcu_timer_clock_prescaler_config()`（TIMERSEL） | **所有定时器时钟**（本条最容易漏：只改这一行，定时器频率就变一倍） |
| RTC 的 `rcu_rtc_div_config` / 时钟源选择 | RTC 的 `FACTOR_A` / `FACTOR_S`（第 13 篇 5.6 节） |
| 换 FWDGT 的分频/重装载 | 喂狗周期与超时时间（第 12 篇） |

**自查方法（改完之后按顺序问自己）**：

```
□ 我改的这级时钟，影响哪些总线？        → 对照第五章总表
□ 定时器的 168 MHz 还成立吗？          → 看 TIMERSEL 条件（第六章）
□ 有没有哪个周期是靠「数中断次数」凑的？ → 有就要重算（软 PWM、软方波）
□ 看门狗的窗口还对不对？                → 42 MHz 是否变了
□ 串口波特率误差还是 <2% 吗？          → USARTDIV 落在哪一档
```

**时钟链常数**：

```

IRC16M        16 MHz     （内部，复位默认 CK_SYS）

HXTAL ÷25 =  320 kHz     （本工程 RTC 的 RTCCLK）

CK_SYS   = CK_AHB = 168 MHz
PCLK2 (APB2)      =  84 MHz
```

## 十、排查清单

| 现象 | 优先检查 |
| --- | --- |
| **程序卡死在启动阶段，进不了 `main()`** | 外部晶振没起振 → 卡在 `while(0U == (RCU_CTL & RCU_CTL_HXTALSTB))`。检查晶振焊接、匹配电容（20 pF × 2）、`__SYSTEM_CLOCK_*` 宏选的是 8M_HXTAL 还是 25M |
| 主频不对（跑得慢很多） | `system_gd32f4xx.c` 里选中的宏是 `IRC16M` 或 `120M` —— **那是 16 MHz / 120 MHz**，所有延时都会成比例变长 |
| 打印 `SystemCoreClock` 不是 168 M | 同上；或 `SystemInit()` 没被调用（启动文件/链接脚本问题） |
| 外设完全没反应 | **第一嫌疑犯：忘了 `rcu_periph_clock_enable()`**（时钟门控没开，寄存器写入无效） |
| 定时器周期差 2 倍或 4 倍 | 算参数时用错了总线频率；或 `rcu_timer_clock_prescaler_config()` 没调用/TIMERSEL 条件不成立 |
| WWDGT 时间差 4 倍 | 用了 168 MHz 去算 —— **WWDGT 用 PCLK1 = 42 MHz，不参与定时器倍频** |
| 串口乱码 | 波特率分频与总线频率不匹配（USART0 在 APB2、USART2 在 APB1）；或改了时钟树没重算 |
| 换板子/改配置后一堆外设不对 | **改了时钟树，但只改了部分参数** —— 对照第八章影响面表逐条重算 |
| GPIO 输出速度上不去 | 忘了 GPIO 时钟在 **AHB1（168 MHz）**，不是 APB |
| `printf` 输出一半就死机 | 与时钟无关，看第 12 篇（阻塞发送 + 看门狗超时） |
| 复位后立刻跑飞 | 复位默认时钟是 **IRC16M 16 MHz**，如果 `SystemInit()` 之前就依赖 168 MHz 的时序（比如某个外设在启动阶段被访问），会出问题 |
| 想跑到 200 MHz 但跑不起来 | 不能只改 PLL —— 还要调 **LDO 电压档位、high-drive、Flash 等待周期、APB 分频**（第四章 4.5 节） |

## 十二、练习题

1. **画图练习**：不看本篇，自己画出本工程的完整时钟树（含 PLL 三级、AHB/APB 分频、TIMERSEL、RTC 与 FWDGT 支路），然后对照第一章检查。
2. **算频练习**：假设把 `__SYSTEM_CLOCK_*` 换成 `200M_PLL_8M_HXTAL`，写出你需要重新确定的 PLL 参数（PSC/N/P/Q）和 APB1/APB2 分频比，使 APB 不超过规格、定时器仍能统一到最大频率。
3. **查总线练习**：用两条 grep，分别查出 `RCU_I2C0`、`RCU_CAN0`、`RCU_ADC0`、`RCU_USART5` 挂在哪条总线上，并列出它们的时钟频率。
4. **打印练习**：在 `main()` 里加一段代码，打印 `CK_SYS / CK_AHB / CK_APB1 / CK_APB2` 和 `RCU_CFG1`，验证倍频与 TIMERSEL 是否生效。
5. **防错练习**：写一个 `clock_check()` 函数，在启动时校验四项频率是否为期望值，不对就打印错误并点亮某个 LED。
6. **影响面练习**：把 APB1 改成 ÷2（84 MHz），然后逐条列出你必须重算的参数（定时器、串口、看门狗），并实际验证串口是否还能正常通信。
7. **对比练习**：把 RTC 时钟源从 `HXTAL` 改成 `IRC32K`，观察走时偏差；再算一算一天会偏多少（参考第 13 篇 7.1 节的方法）。
8. **拓展阅读**：找《GD32F4xx 用户手册》RCU 章节里的时钟树图，对照本篇第一章，标出图中你还没用到的时钟支路（如 I2S、以太网、USB 48 MHz、ADC 时钟）。
