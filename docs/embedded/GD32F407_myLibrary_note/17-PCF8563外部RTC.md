## 一、PCF8563 是什么

**一颗挂在 I2C 总线上的独立实时时钟芯片**。MCU 通过 I2C 读写它的寄存器，就能设置/读取年月日时分秒，还能用它的闹钟和定时器。

```
        VDD ──┬── 主电源
              ├── 备电（纽扣电池/超级电容）   ← 主电源掉电后靠它继续走时
   MCU ───────┼── SCL  (PB6)
              ├── SDA  (PB7)
              └── INT ──→ PB5 ──→ EXTI5（闹钟/定时器到点时拉低）
              │
        ┌─────┴─────┐
        │  PCF8563  │  + 外接 32.768 kHz 晶振
        └───────────┘
```

| 特性 | 说明 |
| --- | --- |
| **I2C 地址** | **`0x51`**（7 位）→ 写 `0xA2`、读 `0xA3` |
| 时间格式 | **BCD**（和 MCU 内置 RTC 一样） |
| 时间范围 | 年 00~99（**世纪位**区分 19xx / 20xx）、月、日、星期、时、分、秒 |
| 中断输出 | **INT 引脚**（开漏、低有效），可被闹钟/定时器触发 |
| 特殊功能 | 闹钟（Alarm）、定时器（Timer）、CLKOUT 输出、掉电检测 |
| 备电 | 板上给了一路**备电**（第 20 篇的硬件文档里记作"外置 RTC PCF8563 + 备电"） |

**本工程用到的引脚（来自 `msp_exti.h`）**：

| 信号 | 引脚 | 配置 |
| --- | --- | --- |
| INT（中断输出） | **PB5** | `GPIO_PUPD_PULLUP` + **下降沿触发**（`EXTI_TRIG_FALLING`） |
| SCL / SDA | PB6 / PB7 | 复用 I2C（第 15 篇） |

## 二、和 MCU 内置 RTC 的关系

本工程**已经有一个内部 RTC**（`Hardware/msp_rtc`，第 11 篇），现在又用了一颗外部 RTC 芯片——**这不是重复劳动，两种方案各有取舍**。

| | **MCU 内置 RTC**（第 11 篇） | **PCF8563 外部芯片**（本篇） |
| --- | --- | --- |
| 位置 | 芯片内部（备份域） | **独立芯片** |
| 时钟源 | 可选 HXTAL÷25 / LXTAL / IRC32K | **自带专用 32.768 kHz 晶振输入** |
| 掉电保持 | 需要 **VBAT 供电**（板上有无电池决定成败） | **芯片自带备电引脚**，用纽扣电池/超级电容即可 |
| 中断能力 | 闹钟中断要**绕到 EXTI_17**（第 11 篇 7.3 节） | **有专用 INT 引脚**，直接接任意 EXTI 线 |
| 额外功能 | 亚秒、唤醒定时器 | **闹钟、可编程定时器、CLKOUT 时钟输出、掉电检测** |
| 成本/占板面积 | 0（内置） | 一颗芯片 + 晶振 + 备电 |
| 换 MCU 时 | 要重新配 | **驱动照搬**（只要能接 I2C） |

**选型建议**：

```
只要"系统知道现在几点"、且板上有 VBAT 电池        → 用内置 RTC（省器件）
要求"绝对时间准确、掉电必须走、还要定时中断"        → 用 PCF8563 这类独立 RTC
产品要换 MCU/换平台                              → 独立 RTC 的软件资产可复用
```

**⚠️ 一个容易忽略的点**：本工程**两个 RTC 同时存在**，且各自的时间结构体不同名但含义重复——

```c
// Hardware/msp_rtc.h（第 11 篇，内部 RTC）
typedef struct { uint16_t year; uint8_t month, day, week, hour, min, sec; } Time;

// Driver/bsp_pcf8563.h（本篇，外部 RTC）
typedef struct {
    uint16_t year; uint8_t month, day, week, hour, minutes, second;
} Time_pcf;   // 有重复Time需要提出去     ← 作者自己的注释，说明已经意识到这个问题
```

**注意 `min` vs `minutes`、`sec` vs `second` 的命名差异**——这属于"两个模块各写各的"留下的技术债。**正确做法是抽一个公共 `rtc_time_t` 放到共享头文件里**（作者已经在注释里写下了 TODO）。

## 三、寄存器映射（本篇最需要背的东西）

PCF8563 一共 16 个寄存器（`0x00 ~ 0x0F`）：

| 地址 | 名称 | 位域 | 说明 |
| --- | --- | --- | --- |
| `0x00` | 控制寄存器 1 | `TEST1 / STOP / TESTC / ...` | 一般用默认值 |
| **`0x01`** | **控制/状态寄存器 2** | `TIE / AIE / TF / AF / TI_TP / ...` | **中断使能与标志位（关键）** |
| `0x02` | 秒 | `VL sss ssss` | **VL = 电压低标志**（要掩掉） |
| `0x03` | 分 | `x mmm mmmm` | 掩 `0x7F` |
| `0x04` | 时 | `xx hh hhhh` | 掩 `0x3F` |
| `0x05` | 日 | `xx DD DDDD` | 掩 `0x3F` |
| `0x06` | 星期 | `xxxx xwww` | 掩 `0x07`（**不是 BCD**，就是 0~6） |
| `0x07` | 月 | `C xxM MMMM` | 掩 `0x1F`；**`C` 是世纪位** |
| `0x08` | 年 | `xx YY YYYY` | 掩 `0x3F`（BCD） |
| `0x09` | 闹钟-分 | `AE mmm mmmm` | **`AE` = 屏蔽位** |
| `0x0A` | 闹钟-时 | `AE hh hhhhh`→`AE hh hhhh` | 同上 |
| `0x0B` | 闹钟-日 | `AE DD DDDD` | 同上 |
| `0x0C` | 闹钟-星期 | `x xxxx www`（bit7 也是屏蔽位） | 同上 |
| `0x0D` | CLKOUT 频率 | `FE ffff...` | 本工程未用 |
| **`0x0E`** | **定时器控制** | `TE pppp cccc` | **`TE` 开关 + 时钟源选择** |
| **`0x0F`** | **定时器计数值** | `NNNN NNNN` | 00~FF |

### 3.1 为什么读时间必须"掩码"

**因为一个字节里既有时间又有标志位**：

```
秒寄存器 0x02： VL sss ssss
               │  └──┬────┘
               │     └── 秒的 BCD 值（0~59）
               └── 电压低标志（VL=1 表示备电电压过低，时间可能不准）

如果直接 BCD2DEC(整个字节) → 高位的 VL 会被当成十位数字 → 秒数错得离谱
```

**所以代码里逐个字段都做了掩码**：

```c
void bsp_pcf8563_read_time(Time_pcf *t)
{
    uint8_t timeBuffer[7] = {0};

    msp_iic_read_nbyte(PCF8563_ADDR, 0x02, timeBuffer, 7);   // 一次读 7 个寄存器

    t->second  = BCD2DEC(timeBuffer[0] & 0x7F);  // VLsss ssss   → 掩掉 VL
    t->minutes = BCD2DEC(timeBuffer[1] & 0x7F);  // xmmm mmmm
    t->hour    = BCD2DEC(timeBuffer[2] & 0x3F);  // xxhh hhhh
    t->day     = BCD2DEC(timeBuffer[3] & 0x3F);  // xxDD DDDD
    t->week    = timeBuffer[4] & 0x07;           // xxxx xwww    → 星期不是 BCD！
    t->month   = BCD2DEC(timeBuffer[5] & 0x1F);  // CxxM MMMM    → 掩掉世纪位

    t->year    = BCD2DEC(timeBuffer[6]);         // xxYY YYYY

    if ((timeBuffer[5] >> 7) & 0x01)             // 单独取世纪位
        t->year += 2000;
    else
        t->year += 1900;
}
```

**三个要点**：

| 要点 | 说明 |
| --- | --- |
| **`msp_iic_read_nbyte(..., 0x02, buf, 7)` 一次读 7 个** | 因为 I2C 支持"地址自动递增"，**读完秒会自动指向分**——这比读 7 次（每次都要起始+地址+寄存器）高效得多 |
| **每个字段的掩码不同** | 不能统一用一个 `&0x7F`，要按数据手册的位域逐个掩 |
| **星期不做 BCD 转换** | `0x06` 低 3 位是"0~6"的**普通数字**，不是 BCD。**这是最容易搞混的一点** |

### 3.2 世纪位：百年后怎么办

```
月寄存器 0x07 的 bit7 = C（Century）
    C = 1 → 20xx 年
    C = 0 → 19xx 年

所以 PCF8563 只能表达 1900~2099 这 200 年。
代码里读的时候补世纪，写的时候设置世纪位：
```

```c
// 写时间时
if (t->year > 1999) // 2000 年之后世纪位置 1
    timeBuffer[5] |= (1 << 7);
```

> **和第 11 篇内部 RTC 的对照**：内部 RTC 是"`year` 两位 + 软件 `+2000`"，**硬编码只支持 20xx**；PCF8563 多了一个世纪位，**能区分 19xx/20xx**。两种方案都是"两位年 + 世纪信息"，只是世纪信息的存放位置不同。

### 3.3 写时间：一次写 7 个字节

```c
void bsp_pcf8563_set_time(Time_pcf *t)
{
    if (t->year < 1900 || t->year > 2099)
        return;                          // ← 范围校验（超出就静默返回）

    uint8_t timeBuffer[7] = {0};

    timeBuffer[0] = DEC2BCD(t->second);  // 秒
    timeBuffer[1] = DEC2BCD(t->minutes); // 分
    timeBuffer[2] = DEC2BCD(t->hour);    // 时
    timeBuffer[3] = DEC2BCD(t->day);     // 日
    timeBuffer[4] = t->week & 0x07;      // 周(0~6，非BCD)
    timeBuffer[5] = DEC2BCD(t->month);   // 月

    if (t->year > 1999)
        timeBuffer[5] |= (1 << 7);       // 世纪位

    timeBuffer[6] = DEC2BCD(t->year % 100);  // 年后两位

    msp_iic_write_nbyte(PCF8563_ADDR, 0x02, timeBuffer, 7);
}
```

**读写是对称的**（都按 `0x02` 起始、连续 7 个字节），**只是方向不同**：

| | 读（`read_time`） | 写（`set_time`） |
| --- | --- | --- |
| 数据处理顺序 | 先 `& 掩码`，再 `BCD2DEC` | 先 `DEC2BCD`，再 `| 置标志位` |
| 星期字段 | `& 0x07` | `& 0x07` |
| 世纪位 | 从月寄存器 bit7 **取出** | 往月寄存器 bit7 **写入** |

> **⚠️ 一个真实的边界问题**：`set_time()` 里的范围校验失败时是 **`return` 静默返回**——调用方无法知道"设置没生效"。**更好的做法是返回 `uint8_t` 错误码**（像 I2C 那样有 `IIC_STA` 枚举）。这在调试时很关键：**"时间没设进去"和"设置成功了但读出来不对"是两条完全不同的排查路径。**

## 四、闹钟与定时器

### 4.1 闹钟：屏蔽位是关键

PCF8563 的闹钟有 4 个寄存器（分、时、日、星期），**每个寄存器的 bit7 是"屏蔽位（AE）"**：

```
AE = 1 → 这个字段不参与比较（忽略）
AE = 0 → 这个字段参与比较
```

**这和第 11 篇内部 RTC 的 `alarm_mask` 是同一个设计思想**（那里是"mask 位 = 忽略该字段"）：

```c
void bsp_pcf8563_set_alarm(Alarm *alarm)
{
    uint8_t timeBuffer[4] = {0};

    timeBuffer[0] = DEC2BCD(alarm->min & 0x7F);
    timeBuffer[1] = DEC2BCD(alarm->hour & 0x7F);

    // day：如果 bit7=1（屏蔽），原样保留；否则 BCD 转换
    if (alarm->day & 0x80)
        timeBuffer[2] = alarm->day;      // 屏蔽位原样透传
    else
        timeBuffer[2] = DEC2BCD(alarm->day);

    // week：保留 bit7，低 3 位有效
    if (alarm->week & 0x80)
        timeBuffer[3] = 0x80;
    else
        timeBuffer[3] = alarm->week & 0x07;

    msp_iic_write_nbyte(PCF8563_ADDR, 0x09, timeBuffer, 4);
}
```

**注意这个函数的"双关"写法**：调用方通过**在字段里塞 bit7** 来选择"屏蔽还是比较"：

```c
alarm.hour = 15;         // 0x0F —— bit7=0 → 参与比较（15 点）
alarm.hour = 15 | 0x80;  // 0x8F —— bit7=1 → 忽略小时（每小时都响）
```

**这个设计有好处也有坑**：

| | 说明 |
| --- | --- |
| 好处 | 一个结构体同时表达"值"和"是否屏蔽"，不用额外字段 |
| 坑 | **调用方必须知道这个约定**，否则会写出 `alarm.hour = 0x8F` 这种"看起来是 143 点"的代码 |

> **本工程 main.c 里的实际用法**（注意它没有用屏蔽位，四个字段全部参与比较）：
> ```c
> alarm.hour = 15;  alarm.min = 0;  alarm.day = 28;  alarm.week = 1;
> bsp_pcf8563_set_alarm(&alarm);
> ```
> **但 PCF8563 的"日"和"星期"不能同时有效**（硬件上按"日比较"或"星期比较"二选一，由控制寄存器 1 的 bit7 决定）。**同时写 day 和 week 时，只有一个真正生效**——这是"读手册才能发现"的细节。**想做成"每周一 15:00 响"，必须去配那一位。**

### 4.2 中断使能与标志：状态寄存器 `0x01`

```c
// 开启闹钟
void bsp_pcf8563_alarm_enable(void)
{
    msp_iic_read_nbyte(PCF8563_ADDR, 0x01, &sta_c2, 1);   // 先读回原值
    sta_c2 |= (1 << 1);   // AIE = 1，允许闹钟中断
    sta_c2 &= ~(1 << 3);  // AF  = 0，清标志
    msp_iic_write_nbyte(PCF8563_ADDR, 0x01, &sta_c2, 1);  // 再写回去
}
```

**`0x01` 的四个关键位**：

| 位 | 名称 | 含义 |
| --- | --- | --- |
| bit0 | **TIE** | 定时器中断使能 |
| bit1 | **AIE** | 闹钟中断使能 |
| bit2 | **TF** | 定时器标志（**到点了硬件置 1，软件要清**） |
| bit3 | **AF** | 闹钟标志（同上） |

**"读-改-写"这个模式很常见**（和第 03 篇按键的位图、第 09 篇数码管缓冲区是一个思路）：**只改我要改的那一位，其余位保持原样**。

**如果直接 `write(0x01, 0x02)` 会怎样？** 会把 TIE 和别的位一起清掉——**这正是"读改写入必须用 `|=` / `&=~` 而不是直接赋值"的经典案例**。

### 4.3 定时器：一个可编程的周期中断

```c
// 配置定时器
// clock: 0x80=1Hz  0x81=64Hz  0x82=1/60Hz  0x83=1/3600Hz
void bsp_pcf8563_set_timer(uint8_t clock, uint8_t cnt)
{
    uint8_t timeBuffer[2] = {0};

    timeBuffer[0] = 0x80 | (clock & 0x7F); // 打开定时器 + 时钟频率
    timeBuffer[1] = cnt;                   // 计数值

    msp_iic_write_nbyte(PCF8563_ADDR, 0x0E, timeBuffer, 2);
}
```

**定时器的四个时钟源**：

| 值 | 时钟源 | 计数值范围 | 定时范围 |
| --- | --- | --- | --- |
| `0x80`（`0x83`） | **1 Hz** | 1 ~ 255 | **1 ~ 255 秒** |
| `0x81`（`0x82`） | **64 Hz** | 1 ~ 255 | 15.6 ms ~ 3.98 s |
| `0x82`（`0x81`） | **1/60 Hz** | 1 ~ 255 | 1 ~ 255 分钟 |
| `0x83`（`0x80`） | **1/3600 Hz** | 1 ~ 255 | 1 ~ 255 小时 |

> **上表括号里的值是按 PCF8563 数据手册的 `0x0E` bit[1:0] 编码（00=1/3600Hz、01=1/60Hz、10=64Hz、11=1Hz）推的**。
> **⚠️ 本工程代码注释里给的是 `0x80=1Hz / 0x81=64Hz / 0x82=1/60Hz / 0x83=1/3600Hz`——两种说法正好相反。** 代码里 `timeBuffer[0] = 0x80 | (clock & 0x7F)` 把 `clock` 的低 2 位直接当编码用，**所以实际频率取决于你传进去的低 2 位**。
> **这正是"写驱动必须先核对数据手册"的活例子**：注释是二手的、可能抄错，**手册才是一手的**。（对照方法见第 23 篇「怎么查手册」。）

### 4.4 中断链路（和 EXTI 的关系）

```
PCF8563 到点（闹钟或定时器）
     ↓ INT 引脚拉低（开漏，需上拉）；同时把 AF 或 TF 置 1
   PB5（EXTI5，下降沿触发）
     ↓
   EXTI5_9_IRQHandler()        ← 注意中断函数名是"5~9 共用一个"
     ↓
   on_rtc_interrupt()                ← bsp_pcf8563.c 里
     ↓
   读 0x01 判断 AF / TF
     ├─ AF=1 → bsp_pcf8563_alarm_clear() + on_rtc_alarm()
     └─ TF=1 → bsp_pcf8563_timer_clear() + on_rtc_timer()
```

**EXTI5 的配置（`msp_exti.h` 新增，`57b3f4a` 提交带来的）**：

```c
#define USE_EXTI5 1

#define EXTI5_PORT_RCU  RCU_GPIOB
#define EXTI5_PORT      GPIOB
#define EXTI5_PIN       GPIO_PIN_5
#define EXTI5_PUPD      GPIO_PUPD_PULLUP     // ← INT 是开漏输出，必须上拉
#define EXTI5_EXTI_PORT EXTI_SOURCE_GPIOB
#define EXTI5_EXTI_PIN  EXTI_SOURCE_PIN5
#define EXTI5_NUM       EXTI_5
#define EXTI5_TRIG_TYPE EXTI_TRIG_FALLING    // ← 低有效，只在下降沿触发
#define EXTI5_IRQ       EXTI5_9_IRQn
```

**三处和第 06 篇（按键 EXTI）不同的地方**：

| 点 | 按键 EXTI（第 06 篇） | PCF8563 INT（本篇） |
| --- | --- | --- |
| 触发极性 | `EXTI_TRIG_BOTH`（上下沿都要） | **`EXTI_TRIG_FALLING`**（只关心"拉低"这一个动作） |
| 消抖 | 需要 30 ms 时间窗 + 电平去重 | **不需要**（芯片输出的是干净的电平跳变） |
| 中断函数名 | `EXTI0_IRQHandler` / `EXTI3_IRQHandler` | **`EXTI5_9_IRQHandler`**（EXTI5~9 **共用一个中断向量**） |

**处理函数**：

```c
void EXTI5_9_IRQHandler()
{
    if (exti_interrupt_flag_get(EXTI_5) == SET)
    {
        exti_interrupt_flag_clear(EXTI_5);

        // RTC回调
        on_rtc_interrupt();
    }
}
```

**`on_rtc_interrupt()` 里为什么要"读寄存器判断是哪个标志"？**

```c
void on_rtc_interrupt(void)
{
    msp_iic_read_nbyte(PCF8563_ADDR, 0x01, &sta_c2, 1);   // ← 在中断里做 I2C 读！

    // 判断 AF 标志位
    if ((sta_c2 >> 3) & 0x01)
    {
        bsp_pcf8563_alarm_clear();
        on_rtc_alarm();
    }

    // 判断 TF 标志位
    if ((sta_c2 >> 2) & 0x01)
    {
        bsp_pcf8563_timer_clear();
        on_rtc_timer();
    }
}
```

**因为闹钟和定时器共用一根 INT 线**——中断来了只知道"PCF8563 有事"，**具体是闹钟还是定时器，必须读标志位才知道**。这和"多个中断源共用一个 EXTI 线要读标志判断"是同一个套路（第 06 篇的 EXTI0/EXTI3 也是各自读标志）。

**⚠️ 这段代码放在中断里做 I2C 读，是有隐患的**（第 06 篇的"中断里不做耗时操作"）：

| 隐患 | 说明 |
| --- | --- |
| I2C 读要经过完整时序 | 软件 I2C 一次读 1 字节约 9 个时钟周期 × 几 μs ≈ **几十 μs 的阻塞** |
| 失败分支里还有 `printf` | 软件 I2C 出错时**在中断里 `printf`**——串口发送是阻塞的（第 12 篇算过：60 字节 ≈ 5.2 ms） |
| 如果同时开了看门狗 | 这几毫秒的阻塞**可能直接把 WWDGT（窗口只有 1.66 ms）喂不上** |

**更稳的做法**：中断里只置一个"待处理标志"，回到主循环再读寄存器、再回调（第 09 篇数码管/第 12 篇看门狗都是这个思路）。

**回调**（本工程固定的解耦手法）：

```c
#ifndef __weak
#define __weak __attribute__((weak))
#endif

__weak void on_rtc_alarm(void) { printf("alarm\n"); }
__weak void on_rtc_timer(void) { printf("timer\n"); }
```

**注意这两个回调是"非空"的默认实现**（打印一行）——这是本工程一贯的做法（第 11 篇 `on_rtc_alarm` 也是这样）：**打印比空函数好，能立刻区分"中断没进"和"进了但没干活"。**

### 5.3 `886ba18`：把时间显示到 OLED

**提交信息**：`[更新] IIC OLED 显示 pcf8563 时间`（跨模块：`bsp_iic_oled` 71 行、`msp_iic` 113 行、`main.c` 57 行）

```c
void oled_show_rtc(Time_pcf *t)
{
    char buf[32] = {0};

    // 1. 先显示 BMP1 整幅背景（128x64）
    //    这一步会覆盖上次 GRAM，保证背景干净
    bsp_iic_oled_show_picture(0, 0, 128, 64, BMP1, 1);

    // 2. 在 BMP1 原本 "2014/05/01" 的位置覆盖显示日期
    sprintf(buf, "20%02d/%02d/%02d", t->year % 100, t->month, t->day);
    bsp_iic_oled_show_string(36, 38, buf, 8, 1);

    // 4. 在 BMP1 原本 "ASCII: CODE:" 的位置覆盖显示时间
    sprintf(buf, "%02d:%02d:%02d", t->hour, t->minutes, t->second);
    bsp_iic_oled_show_string(36, 2, buf, 8, 1);

    // 5. 统一刷新到 OLED
    bsp_iic_oled_refresh();
}
```

**这个函数有一个很实用的技巧**——**"整幅背景图 + 局部覆盖文字"**：

```
先把一张 128×64 的全屏图刷进去（相当于"擦干净画布"）
再把变化的数字写在固定坐标上
⇒ 不用做"擦除旧数字"的逻辑，也不用担心残影
   （每次都是全新背景 + 新数字）
```

**代价是刷屏数据量大**：每次刷新要发 128×64/8 = **1024 字节**（走 I2C 至少 1 kB 数据）。这也解释了为什么第 15 篇要专门加 `msp_iic_write_col_nbyte()`：

```
OLED 显存是按"页"组织的：共 8 页，每页 128 列
要把一幅 128×64 的图发出去，必须按页发
而 BMP 数据是"整幅连续存放"的 → 需要按 offset 跨步取
⇒ 所以就出现了 write_col_nbyte(..., offset, len)
```

**"数据组织方式决定接口形态"**——这是驱动设计里很常见的一类问题（第 02 篇的 LED 参数表、第 09 篇的段码表也是）。

### 5.5 `87da7e0`（10-10 21:29）：⚠️ 闹钟中断打断 IIC —— 一次真实的重入 bug

> **这是本工程第一个"多模块并发"类型的 bug**，比前四笔提交都更值得读：
> 每一段代码单看都对，**放在一起跑就必错**。完整的现场分析见工程内文档 `Doc/闹钟IIC重入问题与修复.md`（12.5 KB）。

**现象**：闹钟没到点时一切正常；**闹钟每次触发后**，串口必出现

```
IIC device not acknowledged!
IIC device not found!
```

两条连在一起，**每个闹钟周期必现**（不是偶发）。

**触发链路**：

```
主循环 while(1)                                    EXTI5 中断（任意时刻插入）
 ├─ bsp_pcf8563_read_time(&time)   ← 软 IIC 读 7 B        │
 └─ oled_show_rtc(&time)           ← 软 IIC 刷整屏 ~38 ms │
                              ▲                          │
                              └──────── 打断 ────────────┤
                                                         │
    PCF8563 闹钟 → INT(PB5) 拉低 → EXTI5 下降沿 ──────────┘
                                     └─ on_rtc_interrupt()
                                          ├─ msp_iic_read_nbyte(0x51, 0x01, ...)  ← 又一次 IIC！
                                          ├─ bsp_pcf8563_alarm_clear()            ← 又一次 IIC！
                                          └─ on_rtc_alarm() → printf("alarm")     ← 还占着串口！
```

**根因（三条叠加）**：

| # | 根因 | 说明 |
| --- | --- | --- |
| 1 | **用的是软件 IIC** | `IIC_HARD_SOFT_SWITCH = 0`；每一位靠 `gpio_bit_set/reset` + `delay_1us(2)` 翻转，**时序完全由 CPU 逐位掌握**——一旦被打断，位间隔立刻错乱，从机解析不了帧 → 不应答（ACK 保持高） |
| 2 | **OLED 与 PCF8563 共用一条软 IIC，且没有互斥** | 两者都在 `PB6/PB7`、都走 `msp_iic`，代码里**没有任何"总线忙"保护** |
| 3 | **中断里发起了完整 IIC 事务** | `on_rtc_interrupt()` 在中断上下文里做 IIC 读 + IIC 写 + `printf`（阻塞式串口发送） |

**为什么"必现"而不是"偶发"**：主循环每一轮都要 `oled_show_rtc()` → 整屏 128×64 刷新，全是软件 IIC，**耗时约 38 ms**（第 18 篇算过）。
也就是说主循环**几乎 100 % 的时间都泡在 IIC 传输里**，闹钟中断撞上"传输进行中"的概率接近 100 %。

**为什么"连报两条"**：旧代码把状态读进**静态变量** `sta_c2`，且**不检查读取是否成功**：

```c
msp_iic_read_nbyte(PCF8563_ADDR, 0x01, &sta_c2, 1);   // 失败时 sta_c2 还是旧值
if ((sta_c2 >> 3) & 0x01) { bsp_pcf8563_alarm_clear(); on_rtc_alarm(); }  // 继续执行 → 又发一次 IIC → 再报一条
```

**方案选型（重要，尤其是被否掉的方案 C）**：

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| **A. 中断只置标志（采用）** | EXTI5 里只清标志 + 置 `volatile` 全局标志；**主循环**检测到标志后再调 `on_rtc_interrupt()` | ✅ 彻底消除重入；改动最小；符合 `README.md` 的"中断里只做标志位" |
| B. 给软 IIC 加"忙"互斥 | `volatile uint8_t iic_busy`，中断里发现忙就只置标志 | 🟡 可选加固，需要 OLED / PCF8563 都过同一把锁 |
| C. 传输期间关中断 | `__disable_irq()` | ❌ **根本行不通**：`delay_1us()` 依赖 **SysTick 中断**做递减，关了中断 → `while (delay)` **死锁** |

> **方案 C 被否掉的理由是本篇最值钱的一句话**：
> **本工程的"延时"不是靠硬件定时器等待，而是"CPU 空转 + SysTick 中断来递减"**（第 01 篇）。
> 所以任何"长时间关中断"的做法都会**连带把时基一起关掉**——这类"看起来最粗暴有效"的方案，
> 在"软件延时依赖中断"的架构里是**自杀式**的。**架构约束比报错信息本身更重要。**

**改动（5 个文件，3 处逻辑 + 2 处注释）**：

```c
// ① msp_exti.c —— 中断里只置标志
volatile uint8_t g_rtc_int_flag = 0;
void EXTI5_9_IRQHandler()
{
    if (exti_interrupt_flag_get(EXTI_5) == SET)
    {
        exti_interrupt_flag_clear(EXTI_5);
        g_rtc_int_flag = 1;          // 只置标志，不在中断里做 IIC / printf
    }
}

// ② msp_exti.h —— 导出标志
extern volatile uint8_t g_rtc_int_flag;

// ③ bsp_pcf8563.c —— on_rtc_interrupt() 改用局部变量 + 检查返回值
void on_rtc_interrupt(void)
{
    uint8_t sta = 0;
    // 读取失败直接返回，避免用旧缓存值误判
    if (msp_iic_read_nbyte(PCF8563_ADDR, 0x01, &sta, 1) != IIC_SUC)
        return;
    if ((sta >> 3) & 0x01) { bsp_pcf8563_alarm_clear(); on_rtc_alarm(); }   // AF
    if ((sta >> 2) & 0x01) { bsp_pcf8563_timer_clear(); on_rtc_timer(); }   // TF
}

// ④ bsp_pcf8563.h —— 注释改为"主循环检测到 g_rtc_int_flag 后调用"

// ⑤ main.c —— 主循环处理标志
while (1)
{
    // PCF8563 中断事件处理：原在 EXTI5 中断中执行，移到主循环以避免软件 IIC 重入
    if (g_rtc_int_flag) { g_rtc_int_flag = 0; on_rtc_interrupt(); }
    ...
}
```

> 注意 `sta_c2` 这个静态缓存**没有删除**——它仍在 `alarm_enable` / `alarm_clear` / `timer_*` 里被使用，
> 本次只是**不再用它做中断里的判断**（"最小改动"原则的体现）。

**顺带修的小东西**：`msp_iic.c` 里那句报错 `printf("IIC device not acknowledged")` 补上了 `\n`（第 15 篇提过的"两条日志粘在一起"的观感问题）。

**这次修复留下的三条通用规则**（值得抄进自己的规范）：

1. **中断服务函数里绝不发起软件 IIC**（同理**也不要 `printf`**——阻塞式串口发送同样是"重活"）。
2. **凡是"由 CPU 逐位控制的时序"（软件 IIC、软件 SPI、单总线），都天然不允许被抢占**；
   要么在中断里避免，要么改用硬件外设（硬件 IIC/SPI 可以把整个事务交给外设，被插入也无所谓）。
3. **读外设状态失败时，绝不能用缓存值继续判断**——那会把"通信错误"放大成"逻辑错误"（多打印一条、多执行一次清标志）。

> **更根本的提醒**：本次修复的是"**并发访问**"这个触发条件，**并没有改变"OLED 与 PCF8563 共用一条无锁软总线"这个事实**。
> 只要将来再有第二个中断源想访问 IIC，同样的坑会再出现一次（这也是方案 B 被留作后续加固的原因）。

### 5.6 `dcdda0d`（10-15）：名字改对了——`on_rtc_int()` → `on_rtc_interrupt()`

这次提交的主人是触摸按键（第 31 篇），但它**顺手改了本篇的一个函数名**：

| 改前 | 改后 | 为什么 |
| --- | --- | --- |
| `on_rtc_int()` | **`on_rtc_interrupt()`** | ① 表达"这是一个**中断事件处理**函数"（而它现在**已经不在中断里跑了**，名字必须能说清"它由谁调用"）；② 与新的 `on_touch_key_interrupt()` **命名对齐** |

**这个改名值得单独记一笔，因为它体现了名字与职责的关系**：

```
改之前：on_rtc_int      →  "RTC 中断"（像是中断服务函数，其实是主循环调用的处理函数）
                        →  而 87da7e0 之后它已经"不在中断里"了，名字开始撒谎

改之后：on_rtc_interrupt →  "RTC 中断【事件】处理"（一个"处理某类事件"的普通函数）
                        →  身份诚实，和 on_touch_key_interrupt 同族
```

**应用侧也跟着改**：

```c
// main.c 主循环
if (g_rtc_int_flag) { g_rtc_int_flag = 0; on_rtc_interrupt(); }   // 旧名 on_rtc_int();
```

> **本工程里"中断相关"的名字现在分得很清楚，值得照这个模式命名**：
>
> | 名字形态 | 身份 | 例子 |
> | --- | --- | --- |
> | **`XXX_IRQHandler()`** | ★ **真·中断服务函数**（名字由启动文件写死） | `EXTI5_9_IRQHandler` |
> | **`on_xxx_interrupt()`** | **中断事件的"处理函数"**（**主循环/任务里调用**） | `on_rtc_interrupt`、`on_touch_key_interrupt` |
> | **`on_xxx_press()` / `on_xxx_alarm()`** | **业务事件回调**（`__weak`，应用层可覆盖） | `on_rtc_alarm`、`on_touch_key_press` |
> | **`g_xxx_int_flag`** | 中断与主循环之间的**唯一接口** | `g_rtc_int_flag`、`g_touch_key_int_flag` |

## 六、最终代码速查

```c
// --- Driver/bsp_pcf8563.h ---
#define PCF8563_ADDR 0x51

typedef struct { uint16_t year; uint8_t month, day, week, hour, minutes, second; } Time_pcf;
typedef struct { uint8_t min, hour, day, week; } Alarm;

void    bsp_pcf8563_init(void);               // 空实现（I2C 由 msp_iic_init 负责）
uint8_t bsp_pcf8563_read_byte(void);          // 读秒寄存器
void    bsp_pcf8563_set_time(Time_pcf *t);    // 写时间（十进制进 → BCD 出）
void    bsp_pcf8563_read_time(Time_pcf *t);   // 读时间（BCD 进 → 十进制出）
void    bsp_pcf8563_set_alarm(Alarm *alarm);  // 配闹钟（bit7 为屏蔽位）
void    bsp_pcf8563_alarm_enable(void);       // 开闹钟中断 + 清标志
void    bsp_pcf8563_alarm_clear(void);        // 清 AF 标志
void    bsp_pcf8563_set_timer(uint8_t clock, uint8_t cnt);
void    bsp_pcf8563_timer_enable(void);
void    bsp_pcf8563_timer_clear(void);
// 回调（__weak，应用层可重定义）
void on_rtc_alarm(void);
void on_rtc_timer(void);
void on_rtc_interrupt(void);                        // 由 EXTI5_9_IRQHandler 调用
```

**参数速查表**：

| 项目 | 值 |
| --- | --- |
| I2C 地址 | **`0x51`**（写 `0xA2` / 读 `0xA3`） |
| 时间寄存器基址 | **`0x02`**（连续 7 个：秒 分 时 日 周 月 年） |
| 闹钟寄存器基址 | **`0x09`**（连续 4 个：分 时 日 周） |
| 状态/控制寄存器 | **`0x01`**（TIE bit0 / AIE bit1 / TF bit2 / AF bit3） |
| 定时器寄存器 | **`0x0E`**（TE bit7 + 时钟选择） / **`0x0F`**（计数值） |
| 时间格式 | BCD（星期除外） |
| 世纪位 | 月寄存器 bit7：1 = 20xx |
| 中断引脚 | **PB5** → **EXTI5** → `EXTI5_9_IRQHandler` |
| 触发沿 | **下降沿**（INT 低有效） |
| 上拉 | `GPIO_PUPD_PULLUP`（INT 开漏输出） |

**常用寄存器掩码速查**：

| 字段 | 掩码 | 备注 |
| --- | --- | --- |
| 秒 | `& 0x7F` | 掩掉 VL |
| 分 | `& 0x7F` | — |
| 时 | `& 0x3F` | — |
| 日 | `& 0x3F` | — |
| 星期 | `& 0x07` | **不是 BCD** |
| 月 | `& 0x1F` | 掩掉世纪位，世纪位另取 `>>7` |
| 年 | 无 | BCD |

## 七、排查清单

| 现象 | 优先检查 |
| --- | --- |
| 读时间全是 0 或 0xFF | I2C 没通（先看第 15 篇）；地址写错（`0x51` 要左移）；器件没供电 |
| **读出来是乱码 / 数值明显偏大** | **忘了按位掩码**（尤其秒的 `VL` 位、月的世纪位） |
| 秒一直在 60 以上 | 把 `VL` 位当成十位了（只掩 `0x7F` 不够？检查是否用 `BCD2DEC(整个字节)`） |
| 星期显示成 8 以上 | 星期位域是低 3 位（`&0x07`），且**不是 BCD** |
| 年份变成 1900 多 | 世纪位没读到/没写对（月寄存器 bit7） |
| 时间设不进去 | `set_time()` 的范围校验失败静默 `return`（传了非法年月日）；或 I2C 写失败 |
| 时间不走字 | 32.768 kHz 晶振没起振；或控制寄存器 1 的 STOP 位被置 1 |
| **闹钟不触发** | ① AIE 没置 1 ② AF 标志没清（会一直"认为已触发"）③ 闹钟寄存器屏蔽位写错 ④ EXTI5 没配 |
| 闹钟触发了但不知道是哪个事件 | `on_rtc_interrupt()` 里要**读 `0x01` 判 AF/TF**（两个共用一个 INT 脚） |
| 定时器不启动 | `0x0E` 的 bit7（TE）没置 1；或计数值为 0 |
| **定时器周期和预期差很多** | **时钟源编码搞反了**（代码注释与手册的说法相反，必须以手册为准，见第 23 篇） |
| 中断进了但反复进 | AF/TF 标志没清；或 EXTI 标志没清 |
| 中断里卡住/系统复位 | 中断里做 I2C + `printf`（阻塞几十 μs ~ 几 ms），可能撑爆看门狗窗口 |
| **每次闹钟触发后都报 `IIC device not acknowledged!`** | ★ **软件 IIC 重入**：中断里发起了 IIC，打断了主循环正在进行的软 IIC 时序（**已由 `87da7e0` 修复，见 §5.5**） |
| 闹钟日志一次打两条 | 读状态失败后仍用**静态缓存旧值**判断（应改成局部变量 + 检查返回值） |
| PCF8563 与 OLED 同时用 IIC 时互相干扰 | 两者共用 `PB6/PB7` 与 `msp_iic`，**没有总线互斥**（改成"只在主循环访问"或加忙标志） |
| 日/星期闹钟只有一个生效 | PCF8563 的"日比较"和"星期比较"是二选一（控制寄存器 1 有一位决定），不能同时用 |
| 编译报 `Time` 重定义 | `msp_rtc.h` 与 `bsp_pcf8563.h` 各有一个时间结构体，注意区分 `Time` / `Time_pcf` |

## 九、练习题

1. **读手册修正编码**：找到 PCF8563 数据手册的 `0x0E` 寄存器说明，确认四个时钟源的正确编码，修正 `bsp_pcf8563_set_timer()` 的注释（或代码）。
2. **消抖无关的可靠性**：给 `on_rtc_interrupt()` 改成"中断里只置标志、主循环处理"，避免在中断里做 I2C 与 `printf`。
   > ✅ **已由 `87da7e0` 完成**（§5.5）。可再对照真实改动，检查你自己写的版本有没有漏掉"**读失败就返回**"这一条。
3. **做一次"每周一 15:00"闹钟**：查手册找到"日/星期比较选择"那一位，配出每周一触发的闹钟并实测。
4. **用上 `bsp_pcf8563_read_byte()`**：它现在读的是秒寄存器（`0x02`），写个小测试每 100 ms 读一次，验证秒在递增（不依赖 OLED）。
5. **加掉电检测**：读秒寄存器时顺便检查 `VL` 位，如果为 1 就在 OLED 上显示"备电电压低"，提示更换纽扣电池。
6. **统一时间结构体**：把 `Time` 和 `Time_pcf` 合并成一个公共 `rtc_time_t`，放在共享头文件里，两个 RTC 驱动都改用它（注意 `min/minutes`、`sec/second` 的命名分歧）。
7. **接上蜂鸣器**（第 07 篇）：重定义 `on_rtc_alarm()`，让闹钟响一声（体会 `__weak` 回调的用法）。
8. **关掉内部 RTC**：把 `msp_rtc_init(HXTAL)` 注释掉，只留 PCF8563，观察系统是否正常（理解"两个 RTC 是否真的都需要"）。
